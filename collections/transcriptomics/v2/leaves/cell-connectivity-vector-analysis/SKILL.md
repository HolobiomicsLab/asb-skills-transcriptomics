# cell-connectivity-vector-analysis

## Summary

Totem's automatic clustering-selection criterion: compute the Calinski-Harabasz (VRC) score on the one-dimensional cell-connectivity vector rather than the low-dimensional embedding, so the clustering chosen to build the Slingshot MST has cells with coherent connectivity along the tree.

## When to use

Use when a Totem analysis has produced many candidate CLARA clusterings and you must automatically pick which one(s) to feed into Slingshot MST construction based on cell connectivity.

## When NOT to use

- You want to score clusterings on the low-dimensional embedding itself (e.g. the 5-dimensional LMDS output) instead of the cell-connectivity vector — Totem's criterion specifically uses the connectivity vector as the data representation.
- There is no set of candidate clusterings yet (CLARA clustering and min.cluster.size filtering have not been run).
- The target trajectory is disconnected or contains cycles — Totem cannot generate such trajectories, so selecting a clustering for its tree-shaped MST is out of scope.

## Inputs

- Totem object containing candidate CLARA clusterings over a range of k values
- One-dimensional cell-connectivity vector computed from the MSTs of all candidate clusterings

## Outputs

- Ranked list of clusterings ordered by Calinski-Harabasz score computed on the connectivity vector
- selected_clusterings.rds with the top-ranked clustering selection

## How to apply

Load the Totem object that holds the candidate clusterings (generated by running CLARA over a range of k, default 10k runs, after filtering out clusterings with clusters smaller than min.cluster.size, default 5 cells) and extract the one-dimensional cell-connectivity vector — deliberately not the raw 5-dimensional LMDS embedding, because the selection should reward clusterings whose cells have similar connectivity along the inferred tree. For each candidate clustering, compute the variance ratio criterion, i.e. the Calinski-Harabasz score via fpc::calinhara, using the connectivity vector as the data representation. Rank all clusterings by the combined Calinski-Harabasz score and cell connectivity and retrieve the top-ranked set with SelectClusterings(selection.method = 1). Save the selected clustering(s) and their ranking as selected_clusterings.rds for downstream MST construction with Slingshot.

## Related tools

- **Totem** (Provides SelectClusterings(selection.method = 1) for the VRC/connectivity-based ranking and selection of candidate clusterings) — https://github.com/elolab/Totem
- **fpc** (Supplies calinhara, the Calinski-Harabasz (variance ratio criterion) implementation applied to the connectivity vector)
- **R** (Language in which the selection workflow is executed)
- **Slingshot** (Consumes the selected clustering to construct the Minimum Spanning Tree backbone of the trajectory)

## Examples

```
R: vrc <- fpc::calinhara(connectivity_vector, clustering_labels); selected <- SelectClusterings(totem, selection.method = 1)
```

## Evaluation signals

- selected_clusterings.rds contains a non-empty top-ranked set of clusterings.
- The ranking is ordered by the Calinski-Harabasz score computed with fpc::calinhara on the connectivity vector, not on the low-dimensional embedding.
- The selected clustering, when passed to Slingshot, yields a tree-shaped MST with biologically meaningful milestone connections.
- Clusterings whose members have similar cell connectivity rank above clusterings with the same k but incoherent connectivity.
- Clusterings with clusters below min.cluster.size (default 5 cells) do not appear among the candidates being ranked.

## Limitations

- k-medoids (CLARA) may behave poorly with high-dimensional PCA input (e.g. 30 principal components), producing 1-2 cell clusters that distort the connectivity signal.
- On datasets with extremely rare and extremely prevalent cell types simultaneously, k-medoids may not cluster properly, requiring manual cluster merging before selection.
- Totem cannot generate disconnected trajectories or trajectories with cycles, and dynplot will not produce correct pseudotime for multi-root (converging) trajectories.
