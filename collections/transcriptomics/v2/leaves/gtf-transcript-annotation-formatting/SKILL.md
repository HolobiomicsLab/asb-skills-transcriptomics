# gtf-transcript-annotation-formatting

## Summary

Formats the transcript paths extracted by Tiglon's label-based dynamic path extension into a GTF file of assembled candidate transcripts, applying Tiglon's output filters (min_trans_cov, min_trans_length) so that every predicted transcript from the labeled splice graph is emitted in a standard annotation format.

## When to use

Use when transcript paths recovered from a labeled splice graph (edges labeled 1, 2+, 2-) must be written out as an annotation file, and output candidates need to be filtered by coverage and length thresholds before downstream use.

## When NOT to use

- Input is long-read RNA-seq data (PacBio or ONT) — the current Tiglon version is not compatible with long-read datasets
- Annotation-guided assembly is required — the current Tiglon version has no option to guide assembly with known transcript annotations
- Input is a single aligner's BAM and the goal is standard de novo assembly rather than integrating multi-aligner mappings

## Inputs

- Labeled splice graph of a gene locus (edges labeled 1, 2+, 2-) with predicted transcript paths from Tiglon's dynamic path extension
- Per-transcript expression levels estimated by Tiglon's abundance analysis
- List of BAM alignment files generated by different aligners (Hisat2 and Star) consumed by Tiglon

## Outputs

- GTF file of assembled candidate transcripts (e.g., recovered_transcripts.gtf) passing min_trans_cov and min_trans_length thresholds

## How to apply

After the Exp/Pre/Suc dynamic programming extension has produced paths covering all edges of the labeled splice graph, filter the predicted transcripts using Tiglon's output thresholds: --min_trans_cov/-c (minimum expression level estimated by abundance analysis, default >0) and --min_trans_length/-L (minimum assembled transcript length, default 500). Optional refinement filters include --min_average_frac/-d and --min_unbalance_frac/-D (both default 0.03) and --min_gap_length/-e (default 200). Write the surviving transcripts in GTF format, the output format Tiglon uses for all assembled candidate transcripts. Iterate extraction-and-writing until the edge-coverage fraction of the labeled splice graph equals 1, i.e., every graph edge is represented by at least one emitted transcript path.

## Related tools

- **Tiglon** (Performs the label-based dynamic path extraction on the labeled splice graph and writes filtered transcripts in GTF format) — https://github.com/yutingsdu/Tiglon

## Examples

```
tiglon -i alignments_list.txt -o recovered_transcripts.gtf -c 0 -L 500
```

## Evaluation signals

- Edge-coverage fraction of the labeled splice graph equals 1: every graph edge is covered by at least one predicted transcript path
- Output file parses as valid GTF with transcript features carrying genomic coordinates consistent with the splice graph exons
- All emitted transcripts meet min_trans_length >= 500 (default) and min_trans_cov above the specified threshold
- Lowly expressed transcripts (small junction support) recovered from 2- labeled edges are present in the output, matching Tiglon's reported strength
- Transcript set is reproducible given the same seed-path priority ordering (2+ paired paths, 2- paired paths, 2+ edges, 2- edges, label-1 elements)

## Limitations

- The current version of Tiglon does not have an option for annotation-guided assemblies
- The current version is not compatible with long-read RNA-seq datasets (e.g., Pacific Biosciences [PacBio] or Oxford Nanopore Technologies [ONT])
- Tiglon accepts BAM files generated only by Hisat(2) and Star, constraining which alignment inputs can feed the GTF output
