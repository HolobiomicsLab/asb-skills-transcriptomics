# runtime-benchmarking-of-computational-methods

## Summary

Times each of decoupleR's 11 statistical methods in both the R (Bioconductor) and Python implementations on a simulated omics matrix and reports median runtime per sample and regulator, quantifying implementation-level scalability differences.

## When to use

Use when comparing execution speed of two implementations of the same method suite (e.g., R vs Python decoupleR) on large simulated omics matrices, or when reproducing a scalability benchmark reported as ms/sample/regulator.

## When NOT to use

- The goal is performance (AUROC/AUPRC) evaluation on perturbation experiments — that is decoupleRBench's benchmark pipeline, not the runtime scalability analysis
- The target method has only one implementation (no R-vs-Python comparison is possible), so relative runtime scaling cannot be measured
- Input is real perturbation data (RNA or phospho-proteomic count tables with metadata) intended for activity inference rather than simulated matrices for timing

## Inputs

- Simulated omics count matrix generated by R/process/get_simmulated_data.R from the decoupleR_manuscript repository
- Analysis data from Zenodo record https://zenodo.org/record/5645208
- decoupleR R (Bioconductor) and Python implementations with all 11 methods available
- Benchmark scripts run_scale_bench.R and R/process/get_simmulated_data.R

## Outputs

- Per-method runtime measurements for the R and Python implementations on the simulated matrices
- runtime_table.csv: comparison table reproducing the structure of Supplementary Fig. S7, with median runtime in ms per sample and regulator per implementation

## How to apply

Download the analysis data from the Zenodo record (https://zenodo.org/record/5645208) referenced by the decoupleR manuscript, then generate the simulated omics dataset for the scalability test by running 'Rscript R/process/get_simmulated_data.R' from the decoupleR_manuscript repository. Execute the scalability benchmark via 'bash run_scale_bench.R', timing each of decoupleR's 11 methods in both the R (Bioconductor) and Python implementations on the simulated matrices; note the README warns this analysis might take a while. Compute the median runtime per sample and regulator across methods for each language implementation, matching the paper's reporting convention of ms/sample/regulator on an Intel(R) Core(TM) i7-8550U CPU @ 1.80 GHz. Assemble the runtime measurements into a comparison table reproducing the structure of Supplementary Fig. S7 and write it to runtime_table.csv; the rationale is that the Python implementation (scverse/decoupler) is 'its faster and memory efficient Python implementation' relative to the deprecated R version.

## Examples

```
Rscript R/process/get_simmulated_data.R; bash run_scale_bench.R
```

## Evaluation signals

- Median runtime across the 11 methods is on the order of 1.44 ms per sample and regulator in R and 0.44 ms in Python, as reported for an Intel(R) Core(TM) i7-8550U CPU @ 1.80 GHz
- The Python implementation's median runtime is lower than the R implementation's for the same methods and matrices
- runtime_table.csv uses the paper's reporting convention (ms/sample/regulator) and matches the structure of Supplementary Fig. S7
- All 11 decoupleR methods are represented for both language implementations in the timing results
- The simulated dataset was regenerated from Zenodo data before timing (get_simmulated_data.R completed without error)

## Limitations

- Absolute runtimes are hardware-dependent: the paper's values (1.44 ms R, 0.44 ms Python) were measured on an Intel(R) Core(TM) i7-8550U CPU @ 1.80 GHz and only order-of-magnitude agreement is expected on other machines
- The README warns 'Run scalablity analysis (This might take a while)' — the benchmark is slow to execute
- The R decoupleR version is deprecated (the scverse README points to saezlab/decoupler as the deprecated R version), so R-side timings reflect legacy code rather than actively maintained implementations
