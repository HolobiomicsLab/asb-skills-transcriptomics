# chimeric-rna-hyb-record-parsing

## Summary

Parse and annotate hybrid (chimeric) RNA records in the 'hyb' file format generated by miRNA/target ligation methods such as CLASH and qCLASH, using Hybkit's HybFile iterator and HybRecord class with eval_types() and eval_mirna() to assign segment types and miRNA identities before any downstream analysis.

## When to use

Use when input is hyb-format chimeric RNA sequence data (optionally with paired Vienna/CT fold files) from CLASH or qCLASH experiments and records must be integrity-checked, filtered, and annotated with segment types and miRNA identities before analysis or plotting.

## When NOT to use

- Input is already an annotated feature/count table or a CSV summary of hybrid types — parsing raw hyb records would be redundant
- Data are raw sequencing reads (FASTQ) rather than post-clustering hybrid records in the hyb format defined by the Hyb software package
- The analysis requires genome alignment or hybrid-read generation; Hybkit starts from already-defined hybrid records and does not perform read alignment

## Inputs

- .hyb-format chimeric RNA hybrid file (15-16 tab-delimited columns per record)
- Paired Vienna-format or CT secondary-structure/fold file (optional, for fold analyses)
- MirBase miRNA reference identifiers (e.g. MIMAT0000078_MirBase_miR-23a_microRNA) for miRNA annotation

## Outputs

- Annotated HybRecord objects with assigned segment types and miRNA identities
- Filtered hyb (and paired fold) files with artifactual ribosomal- and mitochondrial-RNA hybrids removed
- Record counts/quality-control results from hyb_check integrity checking

## How to apply

Read each line of the .hyb file via hybkit's HybFile iterator, which returns one HybRecord object per hybrid carrying the 15-16 tab-delimited hyb columns. First run hyb_check on the hyb file and its paired Vienna fold file to verify data integrity, then use hyb_filter to remove artifactual ribosomal- and mitochondrial-RNA hybrids (e.g. --filter any_seg_contains for custom subsets such as keeping only 'kshv' hybrids). On each retained record call HybRecord.eval_types() to assign segment types (e.g. miRNA, mRNA, lncRNA) and eval_mirna() to identify the miRNA segment (5p/3p/both/none), which is required before type/miRNA, target, grouped target, or fold analyses. When fold information is needed, iterate the hyb file and Vienna file concurrently with HybFoldIter so each HybRecord is merged with a FoldRecord built from the corresponding Vienna record.

## Examples

```
python3 -m pip install hybkit && hyb_filter -i my_hyb_file.hyb -f my_hyb_file.vienna --filter any_seg_contains kshv
```

## Evaluation signals

- hyb_check completes on every .hyb line without error, confirming the expected 15-16 tab-delimited hyb columns per record
- After filtering, record-type and miRNA count-table totals in the type/miRNA analysis match the number of filtered hybrid records in each replicate
- Every processed HybRecord has non-empty segment-type and miRNA annotations following eval_types() and eval_mirna()
- hyb_filter with a paired Vienna file produces hyb and fold outputs whose record counts remain synchronized (HybFoldIter pairing succeeds without off-by-one errors)
- Hybkit's pytest suite ($ pytest) and ./auto_tests/auto_test.sh pass after installation

## Limitations

- Hybkit operates on hyb-format data as defined by the Hyb software package (Travis et al. 2014); other chimeric-read formats require prior conversion
- Artifactual ribosomal- and mitochondrial-RNA hybrids must be explicitly removed with hyb_filter before analysis or counts will be biased
- Duplicate hybrid records (by HybRecord.id) are not removed unless the duplicate-filtration options in hyb_filter are enabled
