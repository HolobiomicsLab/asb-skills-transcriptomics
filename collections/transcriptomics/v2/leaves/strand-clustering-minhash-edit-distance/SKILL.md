# strand-clustering-minhash-edit-distance

## Summary

A decode-stage error-correction step in FrameD that groups the multiple noisy copies of each encoded strand generated by synthesis/sequencing via MinHash/edit-distance clustering, optionally followed by multiple sequence alignment (MSA, e.g. Muscle), before the inner code is reversed to produce a consensus sequence.

## When to use

Use when decoding DNA storage sequencing reads where each encoded strand has multiple noisy copies, and you must aggregate copies toward a consensus before reversing the inner encoding.

## When NOT to use

- When the error model does not warrant it: MSA is 'not always beneficial' and its inclusion depends on the error rate and error types being injected — skip it for low-error or benign error profiles
- When the chosen decode strategy is consolidation after the inner code rather than pre-inner-code clustering (the alternative FrameD decode mode)
- When only a single copy per strand exists, so there is nothing to cluster or aggregate toward consensus

## Inputs

- Noisy sequencing reads (multiple copies per encoded DNA strand) from simulated fault-injection runs (i.i.d. error model or DNArSim nanopore channel output)
- FrameD decode pipeline skeleton: file -> packets -> base-sequences with indexed outer code and inner code mapping base-sequences to strands

## Outputs

- Per-cluster consensus base-sequences fed into inner-code reversal
- Decoded file for byte-for-byte round-trip comparison against the original input
- Fault-injection statistics (e.g. fi.stats files) and JSON results compilable into a Pandas dataframe via db_gen.py

## How to apply

In the FrameD decode path, run strand clustering (MinHash for fast approximate grouping, edit distance for refinement) over the sequencing reads so copies of the same encoded strand land in one cluster; apply this before reversing the inner code. Optionally add a multiple sequence alignment step (e.g. Muscle) on each cluster to aggregate information across copies toward a consensus — the paper found the choice to include MSA is dependent on the error rate and the type of errors injected and is not always beneficial, so decide based on the injected error model (e.g. i.i.d. vs. DNArSim nanopore channel). Alternatively, use FrameD's consolidation decode mode, which merges strands after the inner code instead of before it. FrameD provides transparent parallelism (MPI plus batch-level job submission, e.g. IBM LSF) because clustering and MSA must scale to large numbers of sequencing reads and many fault-injection iterations. Validate by running a file -> encode -> decode round trip and confirming byte-for-byte identity with the original input.

## Related tools

- **FrameD** (Hosts the decode pipeline in which MinHash/edit-distance clustering and optional MSA are inserted before inner-code reversal; provides core encoding, decoding, and file manipulation support and transparent parallelism) — https://github.com/dna-storage/framed
- **DNArSim** (Nanopore channel simulator used to generate realistic read sets (with synthesis-to-basecalling memory errors) that the clustering/MSA decode path is evaluated against) — https://github.com/BHam-1/DNArSim

## Evaluation signals

- A full file -> encode -> decode round trip reproduces the original input byte-for-byte
- Every decoded strand copy is assigned to exactly one cluster before inner-code reversal (no orphan reads)
- Decoding succeeds both with and without the MSA step; enabling/disabling MSA changes results only as predicted by the error-rate/error-type dependency
- Consolidation-mode decode (post-inner-code) and clustering-mode decode (pre-inner-code) both yield valid consensus reconstruction on the same input
- Compiled fault-injection results (db_gen.py dataframe) show the expected recovery statistics for the injected error model (iid vs. DNArSim)

## Limitations

- MSA inclusion depends on the error rate and error types injected and is not always beneficial
- Large-scale runs perform best on HPC systems with many cores and an MPI implementation; the batch infrastructure assumes an IBM LSF scheduler and must be extended (TcshJob class in tools/lsf/submit.py) for Slurm/Cobalt
- Encoding or decoding large files may perform poorly on a standard computer
