# hierarchical-linkage-algorithm-implementation

## Summary

Implements efficient agglomerative hierarchical clustering with an arbitrary linkage (here KMD linkage) via a heap-based routine that maintains, per pair of clusters, the list of k minimal inter-cluster distances, giving O(nk) linkage updates and O(n^2) memory independent of k.

## When to use

Use when the desired linkage function (e.g. k-minimal-distance linkage generalizing single and average linkage) has no existing O(n^2)-time implementation, so a custom heap-based generic-linkage agglomerative routine must be built and validated against SciPy baselines.

## When NOT to use

- The linkage is a standard one (single, average, complete, Ward) already implemented efficiently in SciPy's cluster.hierarchy.linkage — the paper notes the python/scipy KMD implementation runs longer than widely used clustering algorithms, so custom code adds cost without benefit.
- The dataset is at million-object scale and a full dendrogram is required — use the article's sampling-based extension (KMDHierarchicalClustering sub_sample=True) instead, since full-memory KMD linkage is O(n^2).
- The task is selecting the best k or number of clusters rather than implementing/verifying the linkage algorithm itself — use the KMD silhouette score / DBCV workflow instead.

## Inputs

- Feature matrix X (numpy array) of ~1000 objects generated by scikit-learn random sample generators (seed=1) or any dataset matrix for which a dendrogram is needed
- Chosen k value (k=1 to mimic single linkage; large k to approach average linkage)

## Outputs

- Hierarchical clustering dendrogram in SciPy-compatible linkage format
- Cophenetic correlation values vs SciPy single linkage (k=1) and average linkage (large k)
- Per-dataset timing and peak-memory log for each k setting
- kmd_linkage_verification_report.md with results and validation outcome

## How to apply

Generate standard simulated toy datasets with scikit-learn random sample generators (1000 objects, seed=1), then implement a heap-based generic-linkage agglomerative routine that keeps, for each pair of clusters, a list of the k minimal inter-cluster distances; when two clusters merge, update affected pairs by merging their sorted distance lists in O(k) per pair, yielding O(nk) per iteration with O(n^2) memory independent of k. Run the implementation at k=1 and compare the resulting dendrogram to SciPy's cluster.hierarchy.linkage single linkage via cophenetic correlation, then run at a large k and compare to SciPy average linkage the same way. Record per-dataset timing and peak memory for each k setting during the runs. Accept the implementation only when both the k=1-vs-single-linkage and large-k-vs-average-linkage cophenetic correlations are >= 0.99, and write results plus the timing/memory log to kmd_linkage_verification_report.md.

```

```

## Evaluation signals

- Cophenetic correlation between the k=1 implementation's dendrogram and SciPy single linkage is >= 0.99 on all simulated toy datasets
- Cophenetic correlation between the large-k implementation's dendrogram and SciPy average linkage is >= 0.99 on all simulated toy datasets
- Per-iteration linkage update cost scales as O(nk) and memory stays O(n^2) regardless of how large k is set
- Timing and peak-memory measurements are logged for every dataset and k setting during the runs
- Results and validation outcome are written to kmd_linkage_verification_report.md

## Limitations

- A single run of KMD clustering is inherently slower than single and average linkage clustering because it must maintain, for each pair of clusters, a list of the k minimal distances.
- The python/scipy implementation runs longer than widely used clustering algorithms implemented in non-interpreted languages, though it is more accessible to users.
- Automatic selection of the hyperparameter k requires running the clustering over a large range of k values, consuming additional computational resources.
