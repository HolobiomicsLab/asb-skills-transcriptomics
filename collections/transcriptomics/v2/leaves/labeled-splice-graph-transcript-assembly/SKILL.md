# labeled-splice-graph-transcript-assembly

## Summary

Genome-guided transcriptome assembly via Tiglon's labeled splice graph: integrate BAM alignments from multiple aligners (Hisat2 and Star), label splice-junction edges by which aligner captured them, and recover transcripts with a label-based dynamic path extension algorithm.

## When to use

Use when RNA-seq reads are spliced-aligned to a reference genome with more than one aligner (e.g., Hisat2 and Star) and a full-length transcript assembly (GTF) is needed that recovers transcripts missed by single-aligner assemblers like StringTie2 or Scallop.

## When NOT to use

- Only one aligner's alignments are available and a standard assembler suffices — Tiglon's advantage comes from integrating Hisat2 and STAR mappings, and it accepts only Hisat(2)/Star BAM files
- Input is long-read RNA-seq data (PacBio or Oxford Nanopore) — the current Tiglon version is not compatible with long-read datasets
- Annotation-guided assembly is required — the current Tiglon version has no option for using known transcript annotations to guide assembly

## Inputs

- BAM files of spliced RNA-seq alignments generated by Hisat2 (run with --dta)
- BAM files of spliced RNA-seq alignments generated by STAR
- A bamFile_list text file listing the Hisat2 and STAR BAM files (one per line)
- Strand specification (-s <strand>) for the library
- Reference annotation GTF for evaluation (e.g., mm10.ncbiRefSeq.gtf, NCBI RefSeq)

## Outputs

- Assembled candidate transcripts in GTF format from Tiglon
- Baseline assemblies (StringTie2 per-sample and merged GTFs, Scallop GTFs)
- Cuffcompare transcript-level sensitivity, precision, and F-score metrics per assembler

## How to apply

First splice-align the RNA-seq reads to the reference genome (e.g., GRCm38/mm10) independently with Hisat2 (--dta) and STAR, producing coordinate-sorted BAM files per sample. Tiglon accepts BAM files generated by Hisat(2) and Star only; it builds a labeled splice graph per gene locus where nodes are exons and edges are junctions, labeling each edge as 2 if captured by all employed aligners (or by 2+ identical reads) and 1 otherwise. Tiglon then runs its label-based dynamic path extension to output assembled candidate transcripts in GTF format; the input is a file listing the alignment files, one per line. Assemble baselines (StringTie2 per sample plus StringTie2-Merge, and Scallop on STAR alignments) and evaluate all GTF outputs against a reference annotation (e.g., mm10.ncbiRefSeq.gtf) with Cuffcompare to compute transcript-level sensitivity, precision, and F-score.

## Examples

```
Tiglon -B bamFile_list -s <strand> -o Tiglon_outdir
```

## Evaluation signals

- Tiglon's input GTF should contain transcripts assembled from both Hisat2 and STAR BAM files; confirm the bamFile_list has one BAM per line covering both aligners
- On the four M. musculus samples (GRCm38/mm10), Tiglon's average F-score should be about 0.2341 with average precision around 51.71% when evaluated against mm10.ncbiRefSeq.gtf via Cuffcompare
- Expected improvement margins over baselines: ~7.45% over StringTie2-Merge, ~12.19% over StringTie2+MergedAlignments, ~21.85% over Scallop + MergedAlignments
- Low-expression transcript recovery should improve within 108.64%-139.58% over Scallop (Star) and 25.36%-39.91% over StringTie2-Merge
- Output file must be valid GTF with assembled transcript structures; Tiglon's edge labels in the splice graph should distinguish junctions captured by all aligners (label 2) from the rest (label 1)

## Limitations

- Tiglon currently accepts only BAM files generated by Hisat(2) and Star, not other aligners
- The current version has no option for annotation-guided assemblies using known transcript annotations
- The current version is not compatible with long-read RNA-seq datasets (e.g., PacBio or Oxford Nanopore)
- Combining Tiglon's integrating strategy with TransBorrow's borrowing strategy is proposed as future work, not implemented
