# scalability-performance-evaluation-omics-methods

## Summary

Benchmarks the runtime scalability of omics inference methods (decoupleR's R vs Python implementations) by timing each method on simulated large-scale matrices and normalizing to ms per sample and regulator.

## When to use

Use when comparing execution-speed scaling of two implementations of an omics method across large simulated datasets, where runtime must be normalized per sample and per regulator.

## When NOT to use

- The goal is method accuracy (AUROC/AUPRC against perturbation ground truth) rather than runtime — use the decoupleRBench perturbation benchmark pipeline instead.
- Timing on user's own small real datasets rather than the simulated scalability matrices — the paper's ms/sample/regulator figures are only comparable on the simulated data.
- The implementation under test is neither decoupleR (R/Bioconductor) nor decoupler (Python) — the normalization and expected values are specific to these two implementations.

## Inputs

- Analysis data from Zenodo record https://zenodo.org/record/5645208
- Simulated omics count matrices generated by R/process/get_simmulated_data.R
- decoupleR installed in both R (Bioconductor) and Python
- Benchmark harness scripts run_scale_bench.R and decoupleRBench from saezlab/decoupleRBench

## Outputs

- runtime_table.csv — per-method runtimes for R and Python implementations, median runtime per sample and regulator per language
- Comparison table reproducing the structure of Supplementary Fig. S7

## How to apply

Download the analysis data from the Zenodo record (https://zenodo.org/record/5645208) and clone the decoupleR_manuscript repository. Generate the simulated omics matrices for the scalability test with 'Rscript R/process/get_simmulated_data.R'. Execute 'bash run_scale_bench.R' to time each of decoupleR's 11 methods in both the R (Bioconductor) and Python implementations on the simulated matrices. Compute the median runtime per sample and regulator across methods for each implementation, following the paper's reporting convention (ms/sample/regulator on an Intel(R) Core(TM) i7-8550U CPU @ 1.80 GHz). Assemble the per-method runtimes into a comparison table reproducing Supplementary Fig. S7 and write runtime_table.csv; the rationale is that normalized per-sample-per-regulator timings make implementations directly comparable regardless of matrix dimensions.

## Related tools

- **decoupleR** (Method under benchmark; its 11 statistical methods are timed in both R (Bioconductor) and Python implementations on simulated matrices) — https://www.bioconductor.org/packages/release/bioc/html/decoupleR.html
- **decoupleRBench** (Benchmark R package built for evaluating decoupleR, installed via devtools::install_github('saezlab/decoupleRBench')) — https://github.com/saezlab/decoupleRBench
- **R** (Runs data retrieval, simulation of scalability data (get_simmulated_data.R), and the R-implementation timings) — https://www.bioconductor.org/packages/release/bioc/html/decoupleR.html
- **Python** (Hosts the decoupler Python implementation whose timings are compared against the R implementation) — https://github.com/saezlab/decoupler-py

## Examples

```
Rscript R/process/get_simmulated_data.R; bash run_scale_bench.R
```

## Evaluation signals

- The median runtime across the 11 methods is on the order of 1.44 ms per sample and regulator in R and 0.44 ms in Python.
- The Python implementation shows a clear speed advantage over R on the same simulated matrices (orders of magnitude faster per the paper's claim).
- runtime_table.csv reproduces the structure of Supplementary Fig. S7 (per-method runtime comparison of R vs Python).
- Timings were collected on the paper's reference hardware (Intel(R) Core(TM) i7-8550U CPU @ 1.80 GHz) so the normalized values are comparable.
- The simulated scalability data were regenerated from the exact pipeline script get_simmulated_data.R, not substituted with other matrices.

## Limitations

- The scalability analysis 'might take a while' to run, per the manuscript README.
- Reported runtimes are hardware-dependent (Intel Core i7-8550U CPU @ 1.80 GHz); absolute values will differ on other machines.
- The timing results reflect the decoupleR_manuscript codebase; the R decoupleR version is now deprecated in favor of the scverse decoupler Python package, so reproducing the original R numbers requires the pinned manuscript environment.
- Median runtime per sample and regulator is a summary across 11 methods; per-method behavior (e.g. slowest methods) can differ from the median.
