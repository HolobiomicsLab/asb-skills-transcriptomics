# single-cell-rna-count-normalization

## Summary

Normalize raw single-cell RNA UMI count matrices to logarithmic counts per ten thousand (log CPTT) within AnnData so that subsequent scTriangulate stability scoring, clustering, and mix-and-match integration operate on a comparable scale. scTriangulate assumes adata.X is properly normalized before computing TFIDF/reassign scores.

## When to use

Use when raw single-cell RNA-seq UMI counts (e.g. 10x h5/h5ad matrices from GEO like GSE117825 or Synapse syn26320732) must be converted into log CPTT-normalized AnnData before scTriangulate integration.

## When NOT to use

- Input data is already normalized log CPTT or you only have ADT/ATAC modalities, where the article prescribes CLR normalization instead of RNA CPTT
- You are performing data-level multimodal integration (Seurat-WNN, TotalVI) that requires a joint latent space rather than decision-level annotation integration on normalized counts
- AnnData already contains adata.raw — per the README this must be removed first, so normalization alone is insufficient until adata.raw is deleted

## Inputs

- Raw single-cell RNA UMI count matrix in AnnData (adata.X) format, e.g. 10x Genomics h5/h5ad or GEO-deposited pre-processed count matrices (GSE117825, pbmc_10k_v3)
- Optional: ADT or ATAC matrices for multimodal runs (normalized with CLR, not CPTT)

## Outputs

- AnnData object with adata.X normalized to logarithmic counts per ten thousand (log CPTT)
- AnnData with adata.obsm['X_umap'] coordinates generated by scanpy_recipe for downstream scTriangulate visualization

## How to apply

Load raw UMI counts into an AnnData object, then run the scTriangulate.preprocessing.scanpy_recipe wrapper (built on scanpy 1.7.2), which handles QC, filtering, and optional scaling and generates adata.obsm['X_umap'] for downstream visualization. Normalize RNA to logarithmic counts per ten thousand (log CPTT), i.e. normalize_total with target_sum=10,000 followed by log1p, since scTriangulate's TFIDF5/TFIDF10 stability scores and marker-gene detection assume normalized adata.X. For non-RNA modalities the article instead uses Center log-ratio (CLR) normalization via scTriangulate.preprocessing.Normalization.CLR_normalization — apply CPTT specifically to RNA raw UMI counts. Ensure adata.raw is deleted before running scTriangulate because a raw attribute interferes with how scanpy calculates marker genes. Only after this normalization step should alternative clustering annotations be added (add_annotation, add_umap) and ScTriangulate.lazy_run be invoked with parameters such as win_fraction_cutoff=0.3.

## Related tools

- **scTriangulate** (Provides the preprocessing module (scanpy_recipe, Normalization.CLR_normalization) used to QC, filter, and normalize counts before integration; article used version 0.9.0) — https://github.com/frankligy/scTriangulate
- **scanpy 1.7.2** (Underlying engine for scTriangulate's scanpy_recipe wrapper performing normalization (CPTT/log1p) and QC on raw UMI counts)

## Examples

```
from sctriangulate.preprocessing import scanpy_recipe; adata = scanpy_recipe(adata)  # then verify adata.X is log CPTT and adata.raw is deleted
```

## Evaluation signals

- adata.X values are on log CPTT scale (normalize_total target_sum=10,000 followed by log1p), not raw integer UMI counts
- adata.raw is absent (deleted) before scTriangulate runs, so marker-gene calculation is not interfered with
- adata.obsm['X_umap'] exists after scanpy_recipe so add_umap/visualization steps can consume it
- Subsequent scTriangulate run with win_fraction_cutoff=0.3 and add_metrics='tfidf5' completes and resolves transitional states (HSC-cycle, MEP, LMPP) in the bone marrow atlas

## Limitations

- Programmatic default analytical settings may not be optimal for all study designs
- Normalization choice is modality-dependent: log CPTT applies to RNA, whereas ADT requires CLR normalization via scTriangulate.preprocessing.Normalization.CLR_normalization
- adata.raw, if present, will interfere with how scanpy calculates marker genes and must be deleted
