# branched-cell-fate-trajectory-visualization

## Summary

Visualizes linear or branched developmental trajectories from single-cell RNA-seq by combining multiple Hamiltonian path solutions from redPATH into an N-by-N cell transition probability matrix and embedding it via PCA, exposing binary cell fate decisions such as those in human hematopoietic stem cells.

## When to use

Use when a scRNA-seq dataset is suspected to contain a branched developmental trajectory and pseudotime has already been inferred with redPATH's redpath() function, so multiple Hamiltonian path solutions (norm_res_new) are available to combine.

## When NOT to use

- When only a single pseudotime ordering is available and no multiple Hamiltonian path solutions (norm_res_new) have been generated by redpath(), since the transition matrix requires multiple path solutions
- When the underlying pseudotime inference performed poorly — the article notes this approach may fail when pseudotime results are poor
- When the goal is lineage-internal dynamics such as cell cycle/proliferation visualization, which redPATH handles with plot_cycle_diff_3d/plot_diff_3d on reCAT output instead

## Inputs

- Hamiltonian path solutions object 'norm_res_new' automatically saved by the redpath() function (multiple normalized asymmetric Hamiltonian paths)
- redpath_pseudotime vector from redpath() covering all cells
- Pre-filtered gene-by-cell expression matrix (GO-subset via get_GO_exp, dispersion-filtered with filter_exp(dispersion_threshold = 10))
- Optional cell type label vector for coloring cells

## Outputs

- trajectory_visualization_data: transition-matrix-derived PCA embedding of cells exposing linear/branching structure
- trajectory_plots: ggplot2/plotly trajectory visualizations (e.g. 2-panel grid.arrange layout or 3D plot colored by cell type showing binary branching)

## How to apply

First run redpath(filtered_GO_data, threadnum = 4, base_path_range = c(4:8)) on the GO-subset, dispersion-filtered (dispersion_threshold = 10) expression matrix; base_path_range should span the estimated number of cell types k0 to k0 + 4. redpath() automatically saves the multiple normalized Hamiltonian path solutions to the global environment as 'norm_res_new', which is overwritten on each run. Pass these solutions to get_branch_viz_data(hamiltonian_path_solutions, redpath_pseudotime, labels = NULL), which sums the probabilities of transitions between cells into a transition matrix. Embed this matrix with PCA via plot_trajectory to visualize the linear/branching trend, coloring cells by type label (e.g. with ggplot2/plotly for 3D views as in the hHSC Figure 5C analysis). Correct application is confirmed when the plot reproduces the known binary branch structure and the pseudotime vector covers all cells.

## Related tools

- **redPATH** (Provides redpath() to generate multiple asymmetric Hamiltonian path solutions, norm_res_new, get_branch_viz_data() to build the cell transition probability matrix, and plot_trajectory()/plotly utilities for PCA-based branching visualization) — https://github.com/tinglabs/redPATH
- **ggplot2** (Plotting backend for the trajectory visualizations produced by plot_trajectory (grid.arrange layout))
- **plotly** (3D rendering backend for redPATH trajectory and differentiation plots)

## Examples

```
hamiltonian_path_solutions <- norm_res_new; trajectory_visualization_data <- get_branch_viz_data(hamiltonian_path_solutions, redpath_pseudotime, labels = NULL); trajectory_plots <- plot_trajectory(trajectory_visualization_data, redpath_pseudotime)
```

## Evaluation signals

- The output plot reproduces the two-branch structure of the hHSC reference figure (Figure 5C; check script_runs and file_exists on figure5c_branching_trajectory.png)
- The returned redpath_pseudotime vector covers all cells from the redpath() call (length equals number of columns in the filtered expression matrix)
- norm_res_new exists in the global environment after redpath() and is used as hamiltonian_path_solutions input — it is overwritten on each redpath() run, so it must correspond to the current dataset
- get_branch_viz_data accepts labels = NULL or a label vector; trajectory plots color cells by type label and the branched cell fate decision is visually distinguishable
- Transition matrix is N-by-N (cells-by-cells) summing transition probabilities across the multiple Hamiltonian path solutions

## Limitations

- This branching visualization approach does not require cell type labeling, but may fail when the pseudotime results perform poorly
- 'norm_res_new' is automatically overwritten in the global environment every time the redpath() function is run, so solutions from a previous dataset can be silently replaced
- Integrative models are preferred to analyze proliferation and differentiation simultaneously; the current visualization of their coupling is limited
