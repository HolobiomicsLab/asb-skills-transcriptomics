# sirv-benchmark-evaluation

## Summary

Reproduces the SIRV isoform-detection benchmark from the VIsoQLR paper, in which FLAIR (default parameters with a supplied GTF) and StringTie2 (long-read mode with '-L -f 0') are run as comparators on GMAP-aligned PacBio Sequel II UHR Iso-Seq data and scored against the 68 known SIRV reference isoforms and their reference abundances.

## When to use

Use when benchmarking isoform detection/quantification tools on spike-in or synthetic standards (e.g. SIRVs) with PacBio long reads, needing exact-match counts against a known isoform set and cosine similarity of abundance profiles.

## When NOT to use

- The goal is de novo isoform discovery on poorly annotated genomes rather than scoring detection accuracy against a fully known spike-in reference set
- Data are short-read RNA-seq or ONT data assembled with a different aligner workflow, since this benchmark is defined on GMAP-aligned PacBio SIRV alignments
- A single-gene, manual-curation analysis (e.g. a minigene experiment) is required, where VIsoQLR's interactive fine-tuning is the appropriate tool rather than this batch benchmark

## Inputs

- GMAP-aligned SIRV read alignments (BAM plus BAI index) from PacBio Sequel II UHR Iso-Seq data
- SIRV GTF annotation with known exon coordinates (68 isoforms)
- SIRV reference isoform set and reference abundance profiles
- PacBio Sequel II UHR Iso-Seq FASTQ reads (from PacificBiosciences/DevNet data release)

## Outputs

- Per-tool detected isoform counts vs the 68 known SIRV isoforms (expected: FLAIR 37/68 = 54%, StringTie2 12/68 = 18%, VIsoQLR 49/68 = 72%)
- Cosine similarity of predicted isoform abundances vs SIRV reference abundances (expected: FLAIR 0.42, VIsoQLR 0.68)
- Isoform comparison table across VIsoQLR, FLAIR and StringTie2

## How to apply

Load the GMAP-aligned SIRV read alignments (BAM plus BAI index) produced by the mapping step of VIsoQLR, generated by building a GMAP reference index and aligning the raw PacBio FASTQ reads. Run FLAIR with default parameters supplying the SIRV GTF so exon coordinates guide isoform correction, and run StringTie2 on the same BAM in long-read mode with '-L' and '-f 0' so low-confidence transcripts are not filtered. Compare each tool's assembled isoform set against the 68 known SIRV reference isoforms, counting only exact matches with 99% exon-coordinate accuracy as the criterion. Then compute the cosine similarity between each tool's predicted isoform abundance profile and the reference SIRV abundances. The scripts used in the original benchmark are provided in the TBLabFJD/VIsoQLR_benchmark repository (isoform_analysis.sh for preprocessing/tool runs and isoform_comparison.R for comparisons).

## Related tools

- **FLAIR** (Comparator isoform detector run with default parameters and the SIRV GTF for exon-coordinate correction)
- **StringTie2** (Comparator assembler run on the same BAM in long-read mode with '-L' and '-f 0' to avoid filtering low-confidence transcripts)
- **GMAP** (Aligner used to build the reference index and produce the GFF3/BAM alignments fed to all three tools)
- **VIsoQLR** (Reference tool being benchmarked; detects 72% of known SIRV isoforms with 99% exon-coordinate accuracy) — https://github.com/TBLabFJD/VIsoQLR
- **TBLabFJD/VIsoQLR_benchmark** (Repository of preprocessing, isoform-calling and comparison scripts (isoform_analysis.sh, isoform_comparison.R) used to run this benchmark) — https://github.com/TBLabFJD/VIsoQLR_benchmark

## Examples

```
bash isoform_analysis.sh; Rscript isoform_comparison.R
```

## Evaluation signals

- FLAIR detection count equals 37 of 68 known SIRV isoforms (54%)
- StringTie2 detection count equals 12 of 68 known SIRV isoforms (18%)
- VIsoQLR detection count equals 49 of 68 (72%) with 99% exon-coordinate accuracy
- Cosine similarities equal 0.68 (VIsoQLR) and 0.42 (FLAIR) against reference SIRV abundances
- All three tools are evaluated on identical GMAP-aligned BAM inputs, not tool-specific alignments

## Limitations

- StringTie2 extends isoform boundaries and fails to call isoforms lacking certain exons; this extension appears in both the SIRV and PAX6 analyses and seems to be an artifact not present in the BAM files
- Most isoforms missed by VIsoQLR's automatic analysis were below the default 2% read threshold, so lowering the threshold trades precision for recall and requires manual parameter tuning
- No software version numbers are reported for VIsoQLR, StringTie2 or FLAIR, complicating exact reproducibility
