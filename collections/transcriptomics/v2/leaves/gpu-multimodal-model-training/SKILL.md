# gpu-multimodal-model-training

## Summary

Train the mvTCR multi-view Variational Autoencoder on a CUDA-enabled GPU machine to fuse transcriptome and paired TCR CDR3 sequences into a shared cell-level embedding, using the paper's tested version stack (mvTCR v0.1.3 + PyTorch v1.8.0 for reproduction, or v2.1.2 for new work).

## When to use

Use when a >60k-cell 10x Genomics-style dataset with paired gene expression and TCR sequences must be fused into a single cell-level multimodal embedding, or when reproducing mvTCR benchmarks on GPU hardware.

## When NOT to use

- The dataset is unpaired or has partially missing α/β-CDR3 data — the authors note mvTCR was 'applied mainly to paired data' and missing-modality handling is insufficiently addressed
- Only a CPU-only machine is available — GPU and CUDA support is heavily encouraged and required for training
- The analysis requires modalities beyond transcriptome and TCR (e.g. chromatin accessibility), which mvTCR does not yet incorporate

## Inputs

- Preprocessed 10x Genomics single-cell dataset (>60k cells) with paired TCR sequences, e.g. from SchubertLab/mvTCR_reproducibility
- Cell-level annotations: cell type, clonotype, and/or pMHC antigen specificity labels
- Trained-model checkpoints from Zenodo (doi.org/10.5281/zenodo.7215447) for evaluation/reproduction runs

## Outputs

- Trained mvTCR model checkpoints per dataset/setting
- Shared multimodal cell-level embeddings (Scanpy-format adata with embedding, MuData-compatible)
- Evaluation tables (e.g. specificity_f1_results.csv, tcr_contribution_results.csv) generated by downstream notebooks

## How to apply

Create an isolated conda environment and install mvtcr via pip, then add a CUDA-matched PyTorch build (v1.8.0 with mvTCR v0.1.3 to reproduce published results; v2.1.2 for new analyses). Run the preprocessing notebook tutorials/01_preprocessing.ipynb to add the required annotations and filtering, then train via tutorials/02_training_analysis.ipynb (cell-type/clonotype annotations available) or tutorials/03_training_prediction.ipynb (specificity annotations available). A GPU machine is required; hyperparameter optimization was run 48 GPU-hours on a single 32GB GPU (or a 4-GPU node with 512GB), and 8GB RAM sufficed for the >60k-cell preprocessed 10x dataset, so scale memory to dataset size. After training, compute the shared embedding and validate against pretrained checkpoints from Zenodo (doi.org/10.5281/zenodo.7215447) when exact reproduction is required, since models can diverge across CUDA versions and hardware.

## Related tools

- **mvTCR** (Multi-view VAE trained on GPU to fuse transcriptome and TCR into a shared cell-level embedding; installed via pip install mvtcr==0.1.3 for reproduction) — https://github.com/SchubertLab/mvTCR
- **PyTorch** (Deep-learning backend; v1.8.0 with CUDA build for reproduction, v2.1.2 for new work)
- **Scanpy** (Consumes the mvTCR embedding in standard single-cell workflows on the Scanpy-format output)

```
conda create --name mvTCR python=3.10 -y && conda activate mvTCR && pip install mvtcr && conda install nb_conda_kernels -y
```

## Evaluation signals

- Environment resolves exactly: conda env python=3.8.8 (reproduction) or 3.10 (new), mvtcr==0.1.3, matching CUDA PyTorch per pytorch.org previous-versions instructions
- Reproduced specificity-prediction F1-Scores approach the published values: mvTCR 0.821 > TCR-only 0.767 > RNA-only 0.759 (averaged over five random splits)
- Trained-model embeddings align with the Zenodo checkpoints' embeddings (authors warn models 'might diver' across CUDA versions/hardware)
- Training completes on the >60k-cell 10x dataset within ~8GB RAM (CPU memory) plus a single GPU with 32GB memory for HPO

## Limitations

- Models may diverge from the publication's due to 'different runtimes on the compute clusters, different hardware components, and CUDA-versions'; pretrained models are provided on Zenodo (doi.org/10.5281/zenodo.7215447)
- Hyperparameter optimization is costly: 48 GPU-hours per dataset, either one 32GB GPU or a 4-GPU node with 512GB
- MAC with M1 chip is unsupported — several dependencies are unavailable
- Only CDR3 sequence is used for TCR representation; VDJ-gene encoding and pre-trained TCR embedding models are not yet incorporated
- mvTCR was mainly applied to fully paired data; partially missing data handling remains insufficiently addressed
