# cross-condition-scorecard-aggregation

## Summary

Merges the pre-computed scorecards from all pairwise experimental comparisons in a main folder into a single per-gene occurrence overview (e.g., SA_RS13430 appearing on 65 scorecards), separating globally altered genes from condition-specific ones. It complements `multiple_view` (radial overview) by providing countable, file-based knowledge extraction across comparisons.

## When to use

Use when a main folder already holds one sub-directory per pairwise comparison with scorecard outputs, and the goal is to rank genes by total occurrences across all comparisons versus genes found only in isolated conditions.

## When NOT to use

- Individual scorecards have not yet been reconstructed for each pairwise comparison (reconstruct_scorecard has not been run on the sub-folders) — the aggregation re-uses prior outputs and will fail or be meaningless
- The analysis goal is a single pairwise comparison; use the single-comparison scorecard workflow instead of cross-condition aggregation
- You want a radial/visual overview of fold-change magnitudes across comparisons — use scorecard_functions.multiple_view(main_folder) instead, which is only for the scorecard and not the four-way plot

## Inputs

- main_folder (string path) hosting one sub-directory per experimental comparison, each containing pre-computed scorecard outputs for that pairwise comparison
- Frequency summaries previously generated by scorecard_functions.count_frequencies on the same main_folder

## Outputs

- Per-gene occurrence-count report in CSV or Excel format listing total occurrences of each gene across all comparisons
- Optional separate report of uncommon entries (genes specific to isolated conditions rather than globally altered)

## How to apply

Organize a main_folder containing one sub-directory per experimental comparison, each holding that comparison's scorecard outputs. First run `scorecard_functions.count_frequencies(main_folder)` to obtain a summary of the number of entries/genes identified by the scorecard in each comparison. Then run `scorecard_functions.common_entries(main_folder)`, which re-uses the frequency information previously created, to compute total occurrences per gene across comparisons; it can also emit a separate report of uncommon entries (genes specific to isolated conditions rather than globally altered). Save the occurrence-count report as a CSV or Excel file listing per-gene totals (e.g., gene X active in N of M comparisons). Rationale: four-way plots cannot merge information across multiple plots, so this aggregation step supplies the cross-experiment synthesis the scorecard library was designed for.

## Examples

```

```

## Evaluation signals

- Output report exists in CSV or Excel format and contains per-gene occurrence counts for every scorecard region of interest
- Occurrence counts are consistent with the number of sub-folder comparisons present in main_folder (a gene can appear in at most N of M comparisons)
- count_frequencies was run before common_entries, since common_entries re-uses the frequency information previously created
- Genes with the highest totals (e.g., SA_RS13430 on 65 scorecards) correspond to consistently active genes, while the uncommon-entries report lists condition-specific genes

## Limitations

- Aggregation requires the prior folder structure (main_folder with one sub-directory per pairwise comparison) and prior count_frequencies output; it cannot be run standalone
- Results depend on the per-comparison scorecard thresholds (e.g., fold-change thresholds 2 and 3 with multiplication factor 1.5 and p<=0.05 in dataset 1; fold-change 2 and 4 with multiplication factor 2 and p<=0.001 in dataset 3), so cross-comparison counts are threshold-sensitive
