# equivalent-rule-set-computation

## Summary

scBONITA's rule-determination stage: a genetic algorithm finds a minimum-error set of sign-compatible canalyzing Boolean rules per KEGG network node from scRNA-seq data, refined by node-wise local search, yielding an equivalent rule set (ERS) with a per-node uncertainty factor.

## When to use

Use when scRNA-seq data and a prior knowledge network (e.g., KEGG pathways like hsa00010/hsa00020) are available and executable Boolean regulatory rules are needed, especially when multiple rule sets can explain the data.

## When NOT to use

- Only a single best-fit rule set is acceptable and rule-set degeneracy cannot be tolerated (the method explicitly returns an ERS because multiple rule sets explain the data equally well)
- The data are bulk RNA-seq rather than single-cell — use the original BONITA method, on which scBONITA builds
- No prior knowledge network topology is available; rule inference is topology-constrained (KEGG or GRAPHML networks are required inputs)

## Inputs

- Training scRNA-seq expression matrix (rows = genes/features, columns = cells, first column gene names, first row cell IDs matching metadata, log2(TPM+1)-like units)
- Metadata/conditions file (rows = cells, columns = cell properties, entries 0/1)
- Contrast file (tab-separated pairs of conditions to compare)
- KEGG pathway topologies (e.g., hsa00010, hsa00020, organism 'hsa') or GRAPHML networks from non-KEGG sources

## Outputs

- inferred_rules.txt with a sign-compatible canalyzing Boolean rule for every node of each KEGG network
- Equivalent rule set (ERS) of discrete-state models per pathway
- Per-node uncertainty factor quantifying rule-inference uncertainty and gene impact (e.g., RHOA = 0.13)
- SLURM log files and sbatch scripts generated by pipeline.py

## How to apply

Format the training data matrix-style (rows as genes, columns as cells, log2(TPM+1)-like units) with matching metadata and contrast files, then run scBONITA setup via pipeline.py to generate sbatch scripts for the target KEGG topologies. Adjust the NODE and CELL constants in the C sampling code to the dataset dimensions (e.g., 20000 genes x 10000 cells), compile with make, and submit the generated jobs to the SLURM queue. The genetic algorithm searches for sign-compatible canalyzing rules per network node that reproduce observed single-cell expression states; because multiple rule sets can explain the training data equally well, node-wise local search refines candidates and scBONITA returns the equivalent rule set (ERS) in inferred_rules.txt, with a per-node uncertainty factor (e.g., 0.13 for RHOA in the monocyte leukocyte transendothelial migration network). The rationale is that scRNA-seq is treated as samples from the state space of a dynamic Boolean network, and the ERS plus uncertainty quantifies how much inference is driven by the data versus the prior topology.

## Examples

```
python3.6 pipeline.py --dataFile "example.csv" --fullPipeline 1 --maxNodes 20000 --separator "," --listOfKEGGPathways "00010" "00020" --getKEGGPathways 1 --organism hsa cvThreshold None
```

## Evaluation signals

- Every node of each KEGG network has an inferred rule in inferred_rules.txt
- All inferred rules are sign-compatible with the prior network edges and canalyzing
- SLURM log files show rule-inference jobs completed without errors (check queue and logs periodically)
- The C sampling code compiled with NODE and CELL set to the training-dataset dimensions (e.g., 20000 x 10000)
- Per-node uncertainty factors are reported for inferred rules (e.g., 0.13 for RHOA in the monocyte leukocyte transendothelial migration network)

## Limitations

- Multiple rule sets can explain the training data equally well, so the ERS rather than a unique rule set is returned — per-node rules carry inferential uncertainty
- scRNA-seq has technical limitations causing nonspecific distortions of expression, which can affect rule inference; inference is expected to improve with pure cell populations rather than mixed PBMC subpopulations
- Time-series data are rarely available, so scBONITA assumes scRNA-seq samples the state space of a dynamic Boolean network
- Large scRNA-seq datasets need >10G RAM; rule inference and attractor analysis are not recommended on a desktop computer
