# reference-cci-output-validation

## Summary

A reproducibility skill for verifying that condition-specific cell-cell interaction (CCI) datasets regenerated with CellPhoneDB v2 from the Chua et al. COVID-19 scRNA-seq data match the reference CCI deposits in the martaint/InterCellar-reproducibility repository, before they are consumed by InterCellar.

## When to use

Use when reproducing InterCellar paper CCI inputs (COVID-19 control/moderate/critical) and generated CellPhoneDB outputs must be checked against the reference CCI data deposited in martaint/InterCellar-reproducibility.

## When NOT to use

- CCI data were generated by a tool other than CellPhoneDB v2 (e.g., CellChat, ICELLNET, SingleCellSignalR) — validate against the matching reference deposit for that tool instead
- The goal is downstream interpretation of already-validated CCI data (cluster-verse, gene-verse, function-verse analysis) rather than reproduction of the inputs

## Inputs

- Preprocessed Chua et al. COVID-19 scRNA-seq expression matrix with cell-type annotations (from martaint/InterCellar-reproducibility, input_data/)
- Condition group definitions (5 controls / 2,966 cells; 8 moderate patients; 11 critical patients, each subsampled to 10,000 cells)
- Reference per-condition CCI output files from CellPhoneDB v2 deposited in martaint/InterCellar-reproducibility (mean expression, p-values, significant means)

## Outputs

- Three condition-specific CCI input datasets (control, moderate, critical) validated as matching the reference CCI deposit
- Validation verdict per condition (output_matches_reference)

## How to apply

Load the preprocessed Chua et al. scRNA-seq expression matrix and cell-type annotations from the martaint/InterCellar-reproducibility repository, then split the data into the three condition groups: 5 controls with 2,966 cells, and 8 moderate plus 11 critical patients each subsampled to 10,000 cells. Run CellPhoneDB v2 statistical analysis with default parameters separately per condition group so that condition-specific batch effects are not introduced by pooling. Collect the per-condition CellPhoneDB output files (mean expression, p-values, significant means) as the three CCI datasets. The decision point is validation: each generated condition-specific CCI dataset must exist and match the corresponding reference CCI deposit in the repository (output_matches_reference) before it is uploaded to InterCellar as a CCI dataset in step 1 of its workflow.

## Related tools

- **CellPhoneDB** (Run per condition group with default statistical parameters to produce the mean expression, p-values, and significant-means CCI output files that are validated)
- **InterCellar** (Downstream consumer of the validated CCI datasets, which are uploaded in the first workflow step as a CCI data file) — https://github.com/martaint/InterCellar-reproducibility

## Evaluation signals

- All three condition-specific CCI datasets (control, moderate, critical) exist as files after generation
- Each generated CCI dataset matches the corresponding reference CCI deposit in martaint/InterCellar-reproducibility (output_matches_reference)
- Per-condition sample sizes follow the protocol: 2,966 cells for 5 controls; 10,000-cell subsample for each of the moderate (8 patients) and critical (11 patients) groups
- Each CCI dataset contains the expected CellPhoneDB v2 output triple: mean expression, p-values, and significant means

## Limitations

- Predicted cell-cell interactions are computational predictions and await experimental validation (e.g., smFISH or flow cytometry co-occurrence)
- CellPhoneDB is only one of the limited set of tools supported as InterCellar input; other tools require their own reference validation path
- Subsampling of moderate and critical groups to 10,000 cells means validated CCI results depend on the specific subsample drawn
