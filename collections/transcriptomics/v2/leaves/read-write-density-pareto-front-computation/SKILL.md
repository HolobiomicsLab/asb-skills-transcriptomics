# read-write-density-pareto-front-computation

## Summary

Computes read/write density Pareto fronts for DNA storage pipelines (e.g., RS, HEDGES, HEDGES-MSA) from FrameD fault-injection simulation results, to determine which pipeline configuration is optimal at a given error rate and error model.

## When to use

Decision support for choosing a DNA storage encoding pipeline (RS vs HEDGES vs HEDGES-MSA) when fault-injection simulation outputs are available and trade-offs between read density (reads required for recovery) and write density must be compared across error rates.

## When NOT to use

- When no fault-injection simulation results exist yet — this skill consumes FrameD 'fi.stats' outputs, it does not run the encoding/decoding fault injection itself
- When comparing pipelines under an error model not supported by the configured FrameD/DNArSim setup (e.g., custom error channels without a valid configuration JSON)

## Inputs

- FrameD fault-injection simulation output directories containing per-leaf 'fi.stats' files and JSON statistics
- FrameD pipeline configuration JSONs (examples/iid/*.json for the i.i.d. error model; examples/DNArSim/*.json for the nanopore channel model)
- Simulated input file encoded by each pipeline (RS, HEDGES, HEDGES-MSA)

## Outputs

- Per-condition read density (reads required for recovery) and write density values
- Read/write density Pareto fronts per pipeline and error rate
- A combined table such as pareto_fronts.csv mirroring the structure of Fig. 4
- A Pandas dataframe (fault_injection_dataframe) generated by db_gen.py from the raw results

## How to apply

Run FrameD fault-injection simulations for each candidate pipeline (RS, HEDGES, HEDGES-MSA) under the chosen error model (i.i.d. at 1%, 5%, 10%, or DNArSim nanopore channel) using the paper's deposited configuration JSONs from Zenodo deposit 10.5281/zenodo.7757762, with multiple fault-injection iterations per condition and FrameD's transparent parallelism (MPI plus batch-level parallelism) to handle the large read counts. After runs complete, compile per-leaf 'fi.stats' statistics into a Pandas dataframe with tools/data_analysis/db_gen.py, then compute read density and write density per pipeline/error-rate condition and derive the Pareto fronts. Assemble all fronts into a single table (e.g., pareto_fronts.csv) mirroring Fig. 4 of the paper. The key decision the front supports: HEDGES-MSA outperforms HEDGES at higher i.i.d. error rates (5% and 10%), while at 1% the HEDGES pipeline envelops HEDGES-MSA, so adding multiple sequence alignment is not always beneficial.

## Related tools

- **FrameD** (Fault-injection simulation framework used to generate encoding/decoding results for RS, HEDGES, and HEDGES-MSA pipelines; includes db_gen.py for compiling results and framed.ipynb for figure/analysis generation) — https://github.com/dna-storage/framed
- **DNArSim** (Nanopore channel simulator used as the alternative (non-i.i.d.) error model for the DNArSim configuration set)

## Examples

```
cd $DNASTORAGE_HOME/tools/data_analysis; python db_gen.py --path <top result path> --name fault_injection_dataframe
```

## Evaluation signals

- Reproduced fronts match reported behavior: RS attains the best write density at 1% i.i.d. error
- HEDGES-MSA outperforms HEDGES on the Pareto front at 5% and 10% i.i.d. error rates
- HEDGES envelopes HEDGES-MSA at 1% error, confirming MSA inclusion is not always beneficial
- db_gen.py produces a loadable Pandas dataframe at the top-level results path containing rows for all run configurations (240 simulations across 6 JSON configs in the full paper setup)
- Notebook-based figures (framed.ipynb) run end-to-end from the pickled raw data (framed_iid.pickle, framed_DNArSim.pickle) and reproduce Fig. 4 structure

## Limitations

- Full-scale configuration (all 240 simulations) is only tractable on HPC systems; the shipped job-generation commands assume an IBM LSF scheduler and must be extended (e.g., TcshJob/LSFJob classes in submit.py) for Slurm or Cobalt
- The optimality of including MSA depends on both the error rate and the type of errors injected, so conclusions from the i.i.d. model do not automatically transfer to the DNArSim nanopore channel model
- Encoding or decoding large files may perform poorly on standard hardware; HPC or many-core systems with MPI are recommended
