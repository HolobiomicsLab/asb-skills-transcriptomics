# dual-reference-viral-read-counting

## Summary

Quantifies pathogen (e.g. SARS-CoV-2) reads per cell in 10x scRNA-seq data by running cellranger count against the host genome, then using scPathoQuant to map host-unmapped reads to a pathogen reference with bbmap or bowtie2 and integrate pathogen UMI counts back into the 10x matrix files. Validates the result against a combined GRCh38 + pathogen cellranger run.

## When to use

Use when you have 10x cellranger output from infected-cell scRNA-seq and need per-cell pathogen read/UMI counts integrated into filtered_feature_bc_matrix, or when validating an alignment strategy against a combined host+pathogen cellranger reference.

## When NOT to use

- Input reads have not first been processed by cellranger count against the host genome — scPathoQuant consumes the 10x output folder, not raw FASTQ
- Non-10x single-cell platforms whose output scPathoQuant does not consume via the -10x parameter
- The pathogen genome is already integrated into the host reference used for the primary cellranger run (e.g. hg38 with HIV integrated), leaving no host-unmapped pathogen reads to extract

## Inputs

- 10x output folder generated by cellranger count against the host genome (e.g. GRCh38), containing filtered_feature_bc_matrix and raw_feature_bc_matrix plus possorted_genome_bam.bam
- Pathogen reference genome fasta and optional gtf file (e.g. SARS-CoV-2 NCBI GCF_009858895.2), placed in a folder with at most 2 files
- Host+pathogen combined-reference cellranger output for cross-method validation (optional)

## Outputs

- pathogen_al_counts.csv — total reads mapping to the pathogen in each cell
- pathogen_al_gene_counts.csv — reads mapping to individual pathogen genes (requires gtf)
- pathogen-integrated filtered_feature_bc_matrix / raw_feature_bc_matrix loadable by Seurat Read10X
- pathogen_al.bam, pathogen_al_mapped_sort.bam(.bai) for IGV visualization, pathogen_al_mapped.fq.gz for phylogenetic analyses
- pathogen_copy.png, pathogen_genes.png, coveragemap.png violin plots

## How to apply

First run cellranger count on each sample against the host genome (GRCh38) to produce the 10x folders scPathoQuant consumes via its -10x parameter. Optionally run a second cellranger count with a combined GRCh38 + pathogen reference (e.g. NCBI GCF_009858895.2 for SARS-CoV-2), simplifying the fasta header (e.g. > SARS-CoV-2) since the header is used for total pathogen read quantification. Then run scPathoQuant with -p2genome pointing to the pathogen fasta/gtf folder, once with the default bbmap aligner (-align bbmap, -p 8) and once with bowtie2 (--bowtie2_params="--very-sensitive --non-deterministic") to obtain comparable quantifications. Extract per-cell pathogen counts from pathogen_al_counts.csv and the pathogen-integrated filtered_feature_bc_matrix, define pathogen-positive cells per method, and compare positive-cell counts across methods plus Kendall rank correlations between scPathoQuant and CellRanger UMI counts. In the Ravindra et al. 2021 HBEC SARS-CoV-2 time course, all three methods identified the same SARS-CoV-2+ cells (4,279 at 1 dpi, 13,998 at 2 dpi, 26,935 at 3 dpi), with SPQ bbmap correlating slightly more highly with CellRanger than SPQ bowtie2.

## Related tools

- **scPathoQuant** (Python package that extracts host-unmapped reads, maps them to the pathogen genome with bbmap/bowtie2, quantifies per-cell pathogen UMIs, and integrates counts back into the 10x files) — https://github.com/galelab/scPathoQuant
- **cellranger** (Generates the host-aligned 10x output folder consumed via -10x, and provides the combined host+pathogen reference quantification used as the comparison method)
- **bbmap** (Default alignment tool inside scPathoQuant for mapping host-unmapped reads to the pathogen genome)
- **bowtie2** (Alternative aligner run with --very-sensitive --non-deterministic to obtain the third per-cell quantification for cross-method comparison)
- **samtools** (External dependency used by scPathoQuant to handle BAM/SAM operations when pulling unmapped reads and quantifying pathogen reads)
- **htseq** (htseq-count (--intersection-nonempty) quantifies reads mapping to pathogen genes when a gtf is provided)
- **seurat** (Reads the pathogen-integrated filtered_feature_bc_matrix via Read10X for downstream analysis)

## Examples

```
scpathoquant -10x path/to/10x/sample -op path/for/results -p 8 -p2genome path/to/viral/fastafilefolder -align bowtie2 --bowtie2_params="--very-sensitive --non-deterministic"
```

## Evaluation signals

- Per-time-point pathogen-positive cell counts must match across all three methods (CellRanger combined reference, SPQ bbmap, SPQ bowtie2); for the HBEC SARS-CoV-2 set the expected values are 4,279 / 13,998 / 26,935 at 1 / 2 / 3 dpi
- Kendall rank correlations between scPathoQuant UMI counts and CellRanger UMI counts are reported in sars2_cell_counts.csv, with SPQ bbmap expected to correlate slightly more highly than SPQ bowtie2
- pathogen_al_counts.csv exists and per-cell counts agree with the pathogen rows in the overwritten filtered_feature_bc_matrix
- Overwritten filtered_feature_bc_matrix loads cleanly in Seurat via Read10X and contains the pathogen feature rows
- pathogen_al_mapped_sort.bam plus .bai index are produced and viewable in IGV

## Limitations

- The pathogen fasta header is used to quantify total pathogen reads, so complicated headers should be simplified (e.g. > SARS-CoV-2) or counts will be misattributed
- The _tmp/ working directory can be very large; --tmp_removal should be used if disk space is an issue
- Default aligner parameters are used for pathogen mapping (htseq-count uses non-default --intersection-nonempty), so sensitivity depends on the chosen aligner/parameters (e.g. bbmap --semiperfectmode or bowtie2 --very-sensitive)
- A gene-level pathogen gtf is optional — without it, pathogen gene counts and pathogen_genes_al_sort_counts.sam are not produced
