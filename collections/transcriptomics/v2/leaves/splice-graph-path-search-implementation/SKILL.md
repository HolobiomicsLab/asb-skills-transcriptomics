# splice-graph-path-search-implementation

## Summary

Reconstructs transcript-representing paths from Tiglon's labeled splice graph using a label-based dynamic path extension program, where junction edges labeled 1, 2+, or 2- guide seed selection and extension order. It converts multi-aligner splice-junction evidence (e.g., Hisat2 and Star BAM mappings) into assembled candidate transcripts in GTF format.

## When to use

Use when you have a labeled splice graph built from integrated mappings of multiple aligners (labels 1, 2+, 2-) and need to extract transcript-representing paths, particularly to recover lowly expressed transcripts.

## When NOT to use

- Input is long-read RNA-seq data (PacBio or Oxford Nanopore) — the current Tiglon version is not compatible with long-read datasets
- An annotation-guided assembly is required — Tiglon has no option to use known transcript annotations to guide assembly
- Only a single aligner's BAM is available from a non-supported mapper — Tiglon v.1.1 only accepts BAM files generated by Hisat(2) and Star

## Inputs

- Labeled splice graph of a gene locus (nodes = exons, edges = junctions labeled 1, 2+, or 2-) from the upstream graph-construction step
- BAM alignment files generated by Hisat(2) and Star, listed in an input file
- Filter thresholds: min_trans_cov (float, default >0) and min_trans_length (int, default 500)

## Outputs

- recovered_transcripts.gtf containing assembled candidate transcript paths covering all graph edges
- Edge-coverage status confirming every graph edge is traversed by at least one predicted transcript path

## How to apply

Load the labeled splice graph for a gene locus and initialize seed paths by descending label priority: paired paths labeled 2+ first, then 2- paired paths, 2+ edges, 2- edges, and finally label-1 elements. Extend each seed using the Exp/Pre/Suc dynamic programming path-extension procedure, choosing the best predecessor/successor continuation at each node. After each extracted path, apply the fmin weight update to traversed edges and reset their labels to 1 so lower-priority elements become eligible in subsequent iterations. Iterate until all graph edges are covered by at least one predicted path, then filter transcripts using --min_trans_cov (default >0) and --min_trans_length (default 500). The rationale is that label 2 marks junctions captured by all employed aligners, so paths anchored on such edges are the most reliable, while the iterative label-reset ensures label-1 junctions (captured by only one aligner) still get incorporated.

## Related tools

- **Tiglon** (Runs the label-based dynamic path extension (Exp/Pre/Suc procedure with fmin weight update) on the labeled splice graph to recover transcript paths) — github.com/yutingsdu/Tiglon
- **BamTools** (Library dependency for parsing the Hisat2/Star BAM alignment inputs) — https://github.com/pezmaster31/bamtools

## Evaluation signals

- Edge-coverage fraction equals 1: every graph edge of the labeled splice graph is covered by at least one predicted transcript path
- Output GTF (recovered_transcripts.gtf) contains transcript structures with lengths above the default min_trans_length of 500
- Seed path order respects label priority: 2+ paired paths extracted before 2- paired paths, before 2+ edges, 2- edges, and label-1 elements
- Traversed edges have updated fmin weights and reset labels to 1 after each extracted path, as expected from the iterative update
- Program terminates only after the input labeled graph (e.g., the XR_929,880.3 locus graph) is fully consumed without uncovered junctions

## Limitations

- The current version of Tiglon does not have an option for annotation-guided assemblies, i.e., where the known transcript annotations are used to guide the assembly procedure
- The current version is not compatible with long-read RNA-seq datasets (e.g., Pacific Biosciences [PacBio] or Oxford Nanopore Technologies [ONT])
- Tiglon v.1.1 only accepts BAM files generated by Hisat(2) and Star
