# dna-storage-pipeline-simulation

## Summary

Fault-injection simulation of DNA data storage pipelines (RS, HEDGES, HEDGES-MSA) using FrameD, under i.i.d. or DNArSim nanopore error models at defined error rates (1%, 5%, 10%), to compute read/write density Pareto fronts.

## When to use

Use when you need to simulate DNA storage pipelines under fault injection (i.i.d. or nanopore/DNArSim error models) and compare read/write density Pareto fronts across pipeline configurations.

## When NOT to use

- You have real sequencing reads from a wet-lab storage experiment and need empirical evaluation rather than fault-injection simulation
- You only need to encode or decode a small file without evaluating storage-system resilience under injected errors
- Your error model is not one of the supported ones (i.i.d. or the DNArSim MinION R9.4/Guppy v5.0.7 'super-accurate' nanopore profile)

## Inputs

- FrameD JSON configuration files for the RS, HEDGES, and HEDGES-MSA pipelines (examples/iid/*.json for i.i.d. errors, examples/DNArSim/*.json for nanopore)
- Zenodo deposit 10.5281/zenodo.7757762 (deposited FrameD demonstration configurations and input data)
- DNArSim nanopore channel model (github.com/BHam-1/DNArSim) with FASTA input sequence (e.g., example/ref.txt, length 1086) and channel memory k=6
- Error-rate settings (1%, 5%, 10%) and multiple fault-injection iterations per condition

## Outputs

- Per-run statistics files (fi.stats) in each simulation leaf directory
- Compiled Pandas dataframe of fault-injection results generated by db_gen.py
- Read/write density Pareto fronts (e.g., pareto_fronts.csv) and figures reproducing Fig. 4 (i.i.d.) and Fig. 5 (nanopore)

## How to apply

Obtain the FrameD demonstration configurations from Zenodo deposit 10.5281/zenodo.7757762, or use the six .json files shipped in examples/iid (i.i.d. error model) and examples/DNArSim (nanopore channel via DNArSim). Configure fault-injection simulations for the three pipelines (RS, HEDGES, HEDGES-MSA) at 1%, 5%, and 10% error rates, with multiple fault-injection iterations per condition; run the full 240 simulations on an HPC system with MPI and an IBM LSF scheduler, or use examples/small/run_small.csh (12 cores, subshell background jobs) on commodity hardware. After runs complete, find the human-readable fi.stats files in each leaf directory and compile them with tools/data_analysis/db_gen.py into a Pandas dataframe. Compute read density (reads required for recovery) and write density for every configuration, take the Pareto-optimal configurations across all three pipelines, and save/plot the fronts (e.g., pareto_fronts.csv mirroring Fig. 4; Fig. 5 for the nanopore model). Validate that RS attains the best write density at 1% i.i.d. error, HEDGES-MSA outperforms HEDGES at 5% and 10% while HEDGES envelops HEDGES-MSA at 1%, and that under the nanopore model every frontier point is a HEDGES-MSA configuration with no MSA-only configuration present.

## Related tools

- **FrameD** (Fault-injection test bed that runs the RS, HEDGES, and HEDGES-MSA pipelines, provides transparent MPI/batch parallelism, and compiles statistics into a dataframe) — https://github.com/dna-storage/framed
- **DNArSim** (Nanopore channel model with memory (Julia) used to inject synthesis-to-basecalling errors into oligo sequences for the DNArSim error model simulations) — https://github.com/BHam-1/DNArSim

## Examples

```
python db_gen.py --path <top result path> --name fault_injection_dataframe
```

## Evaluation signals

- Under the i.i.d. model, RS attains the best write density at 1% error
- Under the i.i.d. model, HEDGES-MSA outperforms HEDGES at 5% and 10% error rates
- Under the i.i.d. model, the HEDGES pipeline envelops HEDGES-MSA at 1% error (adding MSA is not always beneficial)
- Under the DNArSim nanopore model, every cross-pipeline frontier point belongs to HEDGES-MSA and no MSA-only configuration appears on the frontier
- Each simulation leaf directory contains a human-readable fi.stats file, and db_gen.py produces the expected Pandas dataframe at the top result path

## Limitations

- The full 240-simulation paper configurations only run tractably on HPC systems and currently assume an IBM LSF scheduler; other schedulers (e.g., SLURM) require extending the TcshJob class in tools/lsf/submit.py
- Requires MPI (tested with Intel MPI 2017 u1 and Open MPI 4.1.5), Julia 1.6.2, and Python 3.6-3.10; encoding/decoding large files may perform poorly without substantial compute
- Conclusions about including MSA are error-rate- and error-type-dependent (MSA helps at 5-10% i.i.d. and under nanopore burst errors, but not at 1%), so results do not transfer across error models
