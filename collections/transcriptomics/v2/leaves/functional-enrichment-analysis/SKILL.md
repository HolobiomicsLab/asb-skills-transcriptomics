# functional-enrichment-analysis

## Summary

Functional enrichment analysis of differentially expressed genes (DEGs) using the functional Hunter enrichment module of ExpHunter Suite, which converts a DEG gene list into biological knowledge by combining multiple annotation databases and custom term sets.

## When to use

Use when a gene list from differential expression analysis (e.g. DEGs from a vote-threshold consensus across DEG methods) needs to be converted into overrepresented biological processes, such as ECM or basement membrane terms.

## When NOT to use

- The input is a raw count table rather than an already-derived DEG list — differential expression detection (e.g. via DEgenes Hunter's combined DEG methods) must be run first
- The analysis requires downstream use of logFC (e.g. GSEA) from an unreliable fold-change estimate — the article warns incorrect fold change estimation has important implications for downstream analyses that use logFC such as GSEA
- A single-organism, single-database standard GO analysis is sufficient — the rationale of this skill is combining multiple annotation databases and custom term sets

## Inputs

- Table of differentially expressed genes from a multi-method DEG vote-threshold analysis (e.g. PMM2-CDG DEGs from task_006)
- Gene list (preferably with log2 fold change values) for enrichment testing
- Annotation databases and custom term sets available through ExpHunterSuite (e.g. reactome.db)

## Outputs

- functional_enrichment_results.tsv (table of enriched biological terms/processes)
- Filtered set of enrichment terms matching the biological question (basement membrane / extracellular matrix)
- Companion record of gene-level logFC values (e.g. CACNA1H log2FC)
- HTML results report generated by the ExpHunterSuite pipeline

## How to apply

Load the DEG results table produced by the upstream differential expression task (e.g. prevalent PMM2-CDG DEGs identified with a minimum vote threshold of three) into R. Run the functional Hunter enrichment module of ExpHunterSuite in R/Bioconductor on the DEG gene list, combining multiple annotation databases and custom term sets; ExpHunterSuite supports non-model organisms through orthologous translation for annotation. Filter the enrichment output for the biological processes of interest (here, basement membrane and extracellular matrix related terms) and write results to functional_enrichment_results.tsv. Validation consists of confirming the enrichment table contains the expected terms and checking companion gene-level records, e.g. that CACNA1H's log2 fold change is negative.

## Evaluation signals

- Validation via contains_substring: the enrichment table contains basement membrane / extracellular matrix related terms (the expected PMM2-CDG finding)
- Validation via value_in_range: the CACNA1H log2 fold change record extracted from the DEG table is negative, consistent with calcium channel underexpression in PMM2-CDG
- A functional_enrichment_results.tsv file is produced with parsed enrichment term rows rather than an empty table
- The pipeline completes with a generated HTML results report, as described in the ExpHunterSuiteExamples README
- Enrichment results reflect combination of multiple annotation databases and custom term sets, not a single-database GO run

## Limitations

- Optimal vote thresholds and DEG-derived gene lists may not generalize: 'this may differ for other organisms, tissues and experimental designs'
- Incorrect fold change estimation could lead to poor qPCR target selection and affects downstream logFC analyses such as GSEA
- The biological findings (e.g. calcium channel involvement in PMM2-CDG) are still under investigation and not fully resolved
