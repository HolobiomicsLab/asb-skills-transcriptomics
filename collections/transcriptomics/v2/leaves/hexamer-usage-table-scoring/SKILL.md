# Hexamer usage table scoring

## Summary

Scores transcript sequences by hexamer usage frequencies from a training-data hexamer table, a sequence intrinsic feature (SIF) that LncDC uses to distinguish coding-potential (mRNA) from non-coding (lncRNA) transcripts in an XGBoost classifier.

## When to use

Use when building coding-potential features for lncRNA/mRNA classification and you need a training-set-calibrated hexamer usage score (SIF) for each transcript, as in LncDC's H-Train feature matrix.

## When NOT to use

- The input is already a numeric feature table with hexamer scores precomputed — re-running lncDC-train.py would regenerate the table unnecessarily.
- You only need to score against your own organism's codon/hexamer bias without any training model — use a standalone hexamer/Fickett calculator instead of LncDC's train/predict pair.
- Training lncRNAs are unavailable or insufficient for a non-model organism — in that case LncDC recommends training with data from an evolutionarily close model organism rather than a hexamer table from weak training data.

## Inputs

- mRNA sequences in FASTA format (plain or gzip-compressed) for training table generation
- CDS sequences in FASTA format, in the same order and number as the mRNA records
- lncRNA sequences in FASTA format
- Prebuilt hexamer table in CSV format (e.g. train_hexamer_table.csv) at scoring time

## Outputs

- Hexamer table CSV (e.g. self_mouse_hexamer_table.csv) generated by lncDC-train.py
- Per-transcript hexamer score values embedded in the SIF columns of the 57-feature matrix (h_train_feature_matrix.csv / lncdc output CSV)

## How to apply

First run lncDC-train.py with mRNA (-m), CDS (-c), and lncRNA (-l) FASTA files to generate the training hexamer table (e.g. self_mouse_hexamer_table.csv or the default train_hexamer_table.csv). At prediction time, pass the table with the -x option to lncDC.py, which computes each input transcript's hexamer score against this prebuilt table. The hexamer score is combined with other SIFs (Fickett score, GC content, four FEELnc-style ORF features), SSFs, and PFs into a 57-column feature matrix per H-Train transcript before imputation (imputer.pkl) and scaling (scaler.pkl). FASTA inputs may be plain text or gzip-compressed (*.gz); the CDS FASTA must have the same order and number of records as the mRNA FASTA.

## Examples

```
python bin/lncDC.py -i test/mouse_test_toy.fasta -o lncdc_mouse.csv -x data/train_hexamer_table.csv -m data/XGB_model_SIF_PF.pkl -p data/imputer_SIF_PF.pkl -s data/scaler_SIF_PF.pkl -t 8
```

## Evaluation signals

- The hexamer table CSV is produced alongside the model, imputer, and scaler files with the expected -o prefix (e.g. self_mouse_hexamer_table.csv).
- At prediction, -x is supplied with a hexamer table whose CDS record count and order match the mRNA FASTA used for training.
- Each scored transcript contributes a populated hexamer-score column to the one-row-per-transcript feature matrix (57 populated columns per H-Train transcript).
- Predictions with the default human table should label coding transcripts as 'mrna' and non-coding as 'lncrna' in the output CSV, matching the human_test_toy example.

## Limitations

- Secondary-structure feature computation is optional and much slower; hexamer scoring must remain consistent with whichever -r/-k model variant (SIF_PF vs SIF_PF_SSF) is used, since model/imputer/scaler files differ.
- For non-model organisms with few well-annotated lncRNAs, a self-trained hexamer table may be unreliable; LncDC recommends training with data from evolutionarily close model organisms (Zebrafish, Yeast, Drosophila melanogaster, C. elegans, Arabidopsis thaliana, Oryza sativa, etc.).
