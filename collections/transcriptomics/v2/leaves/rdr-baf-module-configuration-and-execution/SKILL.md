# rdr-baf-module-configuration-and-execution

## Summary

Configure and execute XClone's two-module CNA inference—run_RDR on the read-depth AnnData and run_BAF on the allelic AnnData, then run_combine—to obtain haplotype-aware copy number states per cell from scRNA-seq count matrices.

## When to use

Use when allele- and haplotype-specific CNA states must be inferred from scRNA-seq RDR and BAF matrices already produced by the xcltk preprocessing pipeline, and per-cell clonal copy-number profiles are needed.

## When NOT to use

- The xcltk preprocessing step has not been run and RDR/AD/DP matrices do not yet exist — run xcltk RDR and BAF modules first
- The goal is copy-neutral LOH detection from bulk or single-cell DNA-seq; methods like CHISEL/ACT on scDNA-seq, or InferCNV/CopyKAT which do not use allelic information, may be more appropriate contexts
- Only expression-based CNA calling without haplotype information is required (e.g., InferCNV-style RDR-only analysis)

## Inputs

- RDR AnnData (read-depth matrix) generated by the xcltk RDR preprocessing module
- BAF AnnData (allelic AD/DP count matrices) generated by the xcltk BAF preprocessing module
- Cell annotations (cell_anno_key) and normal reference cell type labels (ref_celltype)

## Outputs

- RDR_Xdata: RDR-module CNA-state AnnData from xclone.model.run_RDR
- BAF_merge_Xdata: BAF-module CNA-state AnnData from xclone.model.run_BAF
- Combined haplotype-aware per-cell CNA states from xclone.model.run_combine

## How to apply

After xcltk generates the RDR read-depth matrix and BAF allelic AD/DP matrices, build AnnData objects with xclone.pp.xclonedata (data_mode 'RDR' and 'BAF', genome_mode 'hg38_genes') and attach cell annotations via cell_anno_key and ref_celltype for normal cells. Run the RDR module with xclone.model.run_RDR and XCloneConfig(module='RDR'), typically setting trans_t = 1e-6 and a start probability vector such as np.array([0.3, 0.4, 0.3]). Run the BAF module with xclone.model.run_BAF and XCloneConfig(module='BAF'), enabling BAF_denoise = True and the 5-state allele-bias transition matrix with trans_t = 1e-6. Both modules smooth CNA states horizontally with hidden Markov models along genome coordinates and vertically with a k-nearest-neighbors cell-cell graph; the BAF module further applies three-step haplotyping (SNP→gene→gene bin→chromosome arm). Finally, merge the modules with xclone.model.run_combine to produce the combined haplotype-aware CNA states per cell, and optionally cluster subclones with XClustering.

## Related tools

- **XClone** (Main package providing run_RDR, run_BAF, run_combine, XCloneConfig and XClustering for module execution and merging) — https://github.com/single-cell-genetics/XClone
- **xcltk** (Preprocessing toolkit that generates the RDR read-depth and BAF allelic AD/DP matrices consumed by the XClone modules) — https://github.com/hxj5/xcltk

## Examples

```
RDR_Xdata = xclone.model.run_RDR(RDR_adata, config_file=xconfig); BAF_merge_Xdata = xclone.model.run_BAF(BAF_adata, config_file=xconfig)
```

## Evaluation signals

- Both module AnnData objects (RDR_Xdata, BAF_merge_Xdata) contain per-cell CNA states over hg38 gene coordinates and pass xclone's internal consistency checks
- Combined CNA calls agree with known chromosomal events (e.g., in ATC2: gains on chr5 in subclone 2, chr7, chr19 and loss on chr6p)
- Subclone clustering of combined states resolves expected tumor subclones even at extreme tumor purity (e.g., two subclones in ATC2 at 2% tumor purity)
- ARI against independently produced inferCNV/CopyKAT labels is high (reported ~0.998 vs inferCNV, ~0.961 vs CopyKAT in ATC2)
- Configuration values match the documented settings: trans_t = 1e-6, BAF_denoise = True, 5-state allele-bias transition matrix

## Limitations

- Python environment sensitivity: XClone requires Python 3.7 or >=3.9, with 3.9 recommended for stable performance in the latest version
- The ATC2 dataset has extremely low tumor purity (2% tumor cells), stressing signal-to-noise; the workflow is demonstrated but performance on other very low-purity samples is not guaranteed
- InferCNV and CopyKAT comparison baselines do not use allelic information and cannot detect copy-neutral LOH, so agreement metrics do not validate haplotype-specific calls
- XClone is updated frequently; users should read the tutorials/release history and keep the software up to date
