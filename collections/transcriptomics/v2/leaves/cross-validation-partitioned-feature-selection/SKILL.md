# cross-validation-partitioned-feature-selection

## Summary

A stability-selection skill that trains mode-wise random-forest feature selectors on each training partition of a 5-times 5-fold cross-validation scheme, retains the top 400 position-specific features per selector, and intersects the 25 resulting feature sets to recover only the position-specific gapped k-mer features that are discriminative across every partition.

## When to use

Use when you need to identify which sequence-position features (e.g., position-specific gapped k-mer descriptors on 41-nt RNA sequences) are consistently, not just incidentally, predictive across repeated cross-validation resampling.

## When NOT to use

- You already have a validated small feature subset and only need to train/evaluate the final classifier (use the Model.ipynb workflow instead).
- The question is predictive performance (accuracy/MCC) rather than feature stability — cross-validation evaluation experiments are the wrong vehicle for ranking consistency analysis.
- Sequences are not position-aligned (the descriptors are position-specific to the 41-nt window, so shifted or variable-length inputs break the pattern-position annotation).

## Inputs

- Dataset.csv (benchmark RNA 5hmC dataset of 41-nt sequences)
- All_Features_Dataset.csv (position-specific gapped k-mer features generated by Feature Generation.ipynb)
- 25 cross-validation training partitions from 5-times 5-fold resampling

## Outputs

- selected_features.csv (table of the 34 surviving features with k-mer pattern, sequence position, and descriptor mode)
- 25 sets of top-400 mode-wise RF-selected features (one per training partition)

## How to apply

First run the Feature Generation pipeline (Feature Generation.ipynb in Jupyter/Anaconda) on Dataset.csv to produce All_Features_Dataset.csv containing the proposed position-specific gapped k-mer features. Then, for each of the 25 training partitions from 5-times 5-fold cross-validation, train mode-wise random-forest selectors (scikit-learn RandomForestClassifier) and retain the top 400 features per selector per mode, yielding 25 sets of 400 features. Intersect the 25 sets using numpy/pandas set operations; for the iRNA5hmC-PS dataset exactly 34 features must survive in every set. Annotate the surviving features with their k-mer pattern and position relative to the 41-nt sequence (e.g., A-A-A at positions 22-26, G-G-G at positions 36-40) and tally descriptor-mode membership: 27 of the 34 must originate from the proposed gapped modes B/C/D, supporting the paper's claim that PSG k-mer features carry vital 5hmC discriminative information. Save the annotated intersection table as selected_features.csv.

## Evaluation signals

- The intersection of the 25 partition-wise selected feature sets contains exactly 34 features.
- Mode-membership tally shows 27 of the 34 surviving features drawn from the proposed gapped descriptor modes B, C, and D.
- Each partition-wise set contains exactly 400 features (top-400 cutoff applied per mode-wise RF selector).
- selected_features.csv entries map each feature to a k-mer pattern plus position range within the 41-nt window (e.g., A-A-A at positions 22-26).
- All_Features_Dataset.csv regenerates deterministically by running Feature Generation.ipynb ('Run All') on Dataset.csv.

## Limitations

- The 34-feature stable set is defined only for this 41-nt RNA 5hmC benchmark and this descriptor family; the paper notes the proposed position-specific features do not work well combined with existing frequency-based counterparts in single models, deferring a feature-subspace ensemble to future work.
- Stability is assessed only under 5-times 5-fold cross-validation with mode-wise RF selectors; other selectors, fold counts, or cutoffs may yield a different intersection.
- Efficacy of the framework on other RNA modification site identification problems has not been evaluated.
