# rna-seq-transcript-assembly

## Summary

Genome-guided transcriptome reconstruction via Tiglon's label-based dynamic path-extension program: build a labeled splice graph from multiple aligners' BAM mappings (Hisat2, Star), then traverse it with dynamic programming to recover transcript-representing paths.

## When to use

Use when you have splice-aware BAM alignments of RNA-seq reads from one or more aligners (e.g., Hisat2 and Star) mapped to a reference genome and need to assemble transcripts, especially lowly expressed ones missed by single-aligner assemblers.

## When NOT to use

- Input is long-read RNA-seq data (PacBio or Oxford Nanopore) — the current Tiglon version is not compatible with long-read datasets
- You need annotation-guided assembly using known transcript annotations — the current Tiglon version has no option for annotation-guided assemblies
- Input alignments come from aligners other than Hisat(2) or Star — the current Tiglon version only accepts BAM files generated by Hisat(2) and Star

## Inputs

- Coordinate-sorted BAM/SAM alignment files of RNA-seq reads produced by Hisat2 and/or Star (via a list file of alignment files from different aligners)
- Reference genome (e.g., GRCh38) used for the alignments

## Outputs

- Assembled candidate transcript structures with expression estimates in GTF format (e.g., recovered_transcripts.gtf)
- Labeled splice graphs per gene locus (intermediate, edges labeled 1, 2+, or 2-)

## How to apply

First map RNA-seq reads to the reference genome with splice-aware aligners such as Hisat2 and Star, then feed the resulting BAM files (Tiglon accepts BAMs from Hisat(2) and Star, listed in an input file) into Tiglon, which builds a labeled splice graph per gene locus where nodes are exons, edges are junctions, and edges are labeled 1 or 2 (label 2 = captured by all employed aligners; 2+ means identical paired reads, 2- otherwise). Seed paths are initialized in descending label priority (2+ paired paths, then 2- paired paths, 2+ edges, 2- edges, label-1 elements), and each seed is extended with the Exp/Pre/Suc dynamic programming procedure that chooses the best predecessor/successor continuation at each node. After each extracted path, the fmin weight update is applied to traversed edges and their labels reset to 1 so lower-priority elements become eligible in later iterations; iterate until all graph edges are covered. Filter resulting transcripts with Tiglon's output thresholds (min_trans_cov, min_trans_length default 500) and write them as GTF. Rationale: neither Hisat2 nor Star alone covers all splice junctions of some true transcripts, so integrating both mappings on the labeled graph recovers transcripts single-aligner assemblers miss.

## Examples

```
tiglon <aligner_bam_list.txt> -o recovered_transcripts.gtf -c 0 -L 500
```

## Evaluation signals

- Edge-coverage fraction of the labeled splice graph equals 1: every graph edge is covered by at least one predicted transcript path after iteration terminates
- Output GTF parses as valid transcript structures and every assembled transcript passes min_trans_cov (>0 default) and min_trans_length (default 500) thresholds
- Reconstruction success on loci known to be missed by single-aligner assemblers (where Hisat2 and Star each cover all exons but neither covers all junctions)
- Tiglon recovers more correct transcripts than StringTie2-Merge, StringTie2, and Scallop baselines (reported average gain: 9.51% over StringTie2-Merge on H. sapiens datasets)
- Pipeline compiles/runs with the documented prerequisites (g++ with C++11, Boost >= 1.47.0, Bamtools) and accepts the BAM files from Hisat(2) and Star

## Limitations

- The current version of Tiglon does not have an option for annotation-guided assemblies, i.e., where known transcript annotations guide the assembly procedure
- The current version is not compatible with long-read RNA-seq datasets (e.g., Pacific Biosciences or Oxford Nanopore Technologies)
- Tiglon currently accepts BAM files generated only by Hisat(2) and Star, limiting the set of aligners whose mappings can be integrated
- A combination with borrowing strategies (e.g., TransBorrow's) or use of known annotations/other assemblers' results is deferred to future work
