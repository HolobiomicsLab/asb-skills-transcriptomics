# seurat-dataset-alignment-for-label-transfer

## Summary

Align single-cell RNA-seq datasets from different labs/protocols into a common feature space (e.g., Seurat-aligned AnnData with the integrated matrix in .X and labels/batch as metadata) before hierarchical progressive-learning label transfer with scHPL, since scHPL matches cell populations across datasets and is not itself a batch correction tool.

## When to use

Use when combining annotated scRNA-seq datasets generated by different labs or sequencing protocols (e.g., Saunders, Zeisel, Tabula Muris) into one classification tree, and per-cell label prediction must transfer across batch-corrected data.

## When NOT to use

- scHPL is not a batch correction tool — do not use it in place of Seurat/scVI/scArches integration; datasets must already be aligned before matching cell populations
- When a new dataset is added, the alignment must be rerun and scHPL rerun with it — avoid this skill if frequent dataset addition without re-alignment is required
- When cell populations genuinely violate hierarchical relationships (e.g., dedifferentiation such as beta-to-alpha cell conversions in type 2 diabetes), a tree-based classifier is inadequate

## Inputs

- Annotated scRNA-seq datasets from multiple labs/protocols (e.g., Saunders, Zeisel low-resolution, Tabula Muris brain datasets as AnnData objects)
- Cell labels and batch indicators as metadata columns per dataset
- An independent unlabeled query dataset (e.g., Seurat-aligned Rosenberg)
- Zenodo-hosted aligned datasets (doi:10.5281/zenodo.4557712)

## Outputs

- Learned hierarchical classification tree linking cell populations across datasets (checkable against Fig. 7G)
- Per-node trained classifiers (linear SVM / kNN / one-class SVM)
- Per-cell predicted labels with rejection for the query dataset (Rosenberg)
- Saved hierarchy and predictions, plus evaluation metrics from scHPL.evaluate

## How to apply

First integrate the datasets with a batch correction tool (the paper's inter-dataset experiments used Seurat-aligned data; the scHPL README also recommends scVI or scArches) so that populations are comparable. Place the aligned expression matrix in the AnnData .X slot and keep cell labels plus batch indicators as metadata columns. Then run scHPL's progressive learning (scHPL.learn) starting from one annotated dataset (e.g., Saunders) and progressively adding the others (Zeisel low-resolution, Tabula Muris) so it automatically finds cross-dataset relationships, such as Saunders mural cells matching Tabula Muris brain pericytes. Train a classifier at each tree node with scHPL.train, choosing the linear SVM for aligned high-dimensional integrated data (vs. kNN or one-class SVM options), and use scHPL.predict on a new aligned query dataset (e.g., Rosenberg) with rejection allowed for unmatched populations. Rationale: scHPL matches populations in the shared space, so any tree error could stem from either bad alignment or scHPL mismatches, making upfront alignment quality critical.

## Related tools

- **scHPL** (Hierarchical progressive learning: constructs the classification tree from aligned datasets, trains per-node classifiers, and predicts/rejects labels on a query dataset) — https://github.com/lcmmichielsen/scHPL
- **Seurat** (Batch correction/alignment of the Saunders, Zeisel, Tabula Muris, and Rosenberg datasets into a shared space prior to scHPL)
- **scArches** (Recommended alternative (with scVI) for aligning datasets before scHPL population matching, via the treeArches framework) — https://github.com/theislab/scarches

## Examples

```
pip install scHPL; tree = schpl.learn(saunders_adata); tree.add_data(zeisel_adata); tree.add_data(tabula_muris_adata); tree.train(classifier='lin'); labels = schpl.predict(tree, rosenberg_adata)
```

## Evaluation signals

- The reproduced tree contains the reported cross-dataset matches, e.g., Saunders mural cell populations matched to Tabula Muris brain pericytes (compare against Fig. 7G)
- Rosenberg predictions match the assignments shown in Fig. 7G, with rejection applied where populations do not match tree nodes
- Per-node linear SVM accuracy is equal to or higher than the one-class SVM baseline; note that one-class SVM performance decreases more on small populations
- Each AnnData object has the aligned matrix in .X with labels and batch indicators present as metadata columns
- Low-dimensional (small population) nodes should be checked carefully, since both classifiers lose accuracy there

## Limitations

- Batch effects make it hard to determine whether tree mistakes stem from erroneous alignment or from mismatches created by scHPL
- Adding a new dataset requires rerunning the alignment and consequently scHPL with current batch correction tools
- One-class SVM performance decreases more on small cell populations; both classifiers degrade on small populations
- No constant terminology exists for cell populations across studies, and many brain cell populations are missing from the Cell Ontology, limiting name-based verification
