# calinski-harabasz-cluster-ranking

## Summary

Ranks Totem's candidate CLARA clusterings by the variance ratio criterion (Calinski-Harabasz score) computed on the one-dimensional cell-connectivity vector rather than the dimensionally reduced data, so that clusterings whose cells show similar connectivity are favored for MST construction.

## When to use

Use when Totem has generated a large set of candidate clusterings (k-medoids/CLARA over many k values) and one must automatically select clustering(s) to feed Slingshot MST construction, using Calinski-Harabasz scores combined with cell connectivity.

## When NOT to use

- The goal is a trajectory with cycles or disconnected components — Totem cannot generate these, so ranking clusterings for MST selection is not applicable.
- The trajectory is multi-root (converging) and correct pseudotime is required — dynplot cannot generate correct pseudotime for multi-root trajectories without manual work-around.
- The dataset simultaneously contains extremely rare and extremely prevalent cell types, where k-medoids itself fails before any ranking could be meaningful.

## Inputs

- Totem object containing candidate clusterings generated by CLARA (k-medoids) over a range of k values
- One-dimensional cell-connectivity vector computed from the MST topologies of the candidate clusterings
- Optional: user-provided prior clustering to bias selection toward similar clusterings

## Outputs

- selected_clusterings.rds containing the top-ranked clustering(s) and their Calinski-Harabasz/connectivity ranking
- Selected clustering used to construct the Minimum Spanning Tree (MST) with Slingshot

## How to apply

Load the Totem object holding the candidate clusterings (produced by running k-medoids/CLARA ~10k times, filtered by min.cluster.size) and extract the one-dimensional cell-connectivity vector, NOT the raw low-dimensional embedding — the rationale is that Totem measures connectivity of cells to identify likely leaves and branch points, so ranking on connectivity picks clusterings whose cells have similar connectivity. For each candidate clustering, compute the variance ratio criterion (Calinski-Harabasz score, e.g. fpc::calinhara) with the connectivity vector as the data representation. Rank the clusterings by the Calinski-Harabasz score combined with cell connectivity (optionally with ARI to a user-supplied prior clustering) and retrieve the top-ranked set via SelectClusterings(selection.method=1). Save the selected clustering(s) and their ranking as selected_clusterings.rds; the selected clustering is then used with Slingshot to construct the MST backbone of the tree-shaped trajectory.

## Related tools

- **Totem** (Generates the candidate CLARA clusterings, measures cell connectivity, and provides SelectClusterings to rank/select clusterings by Calinski-Harabasz score plus connectivity for MST construction) — https://github.com/elolab/Totem
- **Slingshot** (Consumes the selected clustering to construct the Minimum Spanning Tree that forms the trajectory backbone)
- **R** (Implementation environment for the ranking and selection workflow (Totem is an R/Bioconductor package)) — https://github.com/elolab/Totem

## Examples

```
selected <- SelectClusterings(totem, selection.method=1)  # rank CLARA clusterings by Calinski-Harabasz score on the cell-connectivity vector
```

## Evaluation signals

- The output selected_clusterings.rds contains a non-empty, ordered set of clusterings ranked by Calinski-Harabasz score combined with cell connectivity.
- The Calinski-Harabasz score is computed on the one-dimensional cell-connectivity vector, not the 5-dimensional LMDS embedding or the raw expression matrix.
- Selected clusterings yield an MST whose topology matches plausible leaves (high-connectivity end points) and branch points when visualized against the 2-D MDS embedding.
- Clusterings filtered out by min.cluster.size (default 5 cells per cluster) do not appear in the candidate set being ranked.
- When a prior clustering is supplied, the ranking additionally reflects ARI similarity to the prior.

## Limitations

- k-medoids (CLARA) may be unstable with high-dimensional PCA input (e.g. 30 principal components), producing 1–2 cell clusters that degrade the candidate pool.
- If the dataset includes extremely rare and extremely prevalent cell types simultaneously, k-medoids might not work properly, requiring manual cluster merging.
- Ranking selects for tree-shaped MSTs; Totem cannot generate disconnected trajectories or trajectories with cycles, and dynplot cannot produce correct pseudotime for multi-root trajectories.
