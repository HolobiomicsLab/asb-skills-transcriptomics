# blastocyst-scrnaseq-data-handling

## Summary

Generates a low-coverage scRNA-Seq benchmark by randomly down-sampling 1% of allele-specific reads independently within each of the 122 CAST×B6 F1 blastocyst cells from Deng et al., yielding ~147,538 reads per cell, to evaluate whether partial pooling improves allelic proportion estimation.

## When to use

Use when evaluating estimation precision of allelic proportions under reduced sequencing depth, or when a low-coverage replicate of full-depth allele-specific counts is needed for an MSE benchmark.

## When NOT to use

- When the goal is burst-kinetics inference on UMI counts — the sandberg-lab/txburst pipeline expects allelic UMI count CSVs and does not apply weighted allocation
- When a genuinely low-coverage dataset exists; down-sampling is a simulation of low depth and should not substitute for real low-coverage data
- When per-cell depth is already low enough that further down-sampling would produce near-empty count vectors dominated by sampling zeros

## Inputs

- Full-depth allele-specific read count table (maternal/paternal counts per gene per cell) for the 122 blastocyst cells from Deng et al. CAST×B6 F1 scRNA-Seq data, generated by EMASE weighted-allocation counting
- Down-sampling fraction (0.01) and per-cell random sampling seed/procedure

## Outputs

- Down-sampled allele-specific count matrix for all 122 cells (~147,538 reads/cell average) written to a table file
- Per-cell read totals for validating the ~1% down-sampling

## How to apply

Load the full-depth allele-specific read count matrix (maternal/paternal reads per gene per cell) for the 122 early, mid, and late blastocyst cells from the Deng et al. CAST×B6 F1 dataset, where counts were produced upstream by EMASE weighted-allocation counting of multi-reads. Apply random down-sampling at a 1% sampling fraction independently within each cell to mimic low sequencing coverage (~147,538 reads per cell on average), retaining the allele-specific count structure. Write the down-sampled count matrix for all 122 cells to a table file for use as input to the partial-pooling mean-squared-error evaluation, comparing estimates from down-sampled data against full-depth estimates. Rationale: partial pooling has the biggest impact when read coverage is low and the number of cells is large, so controlled down-sampling isolates the coverage effect. Validation: confirm all 122 cells are present and per-cell read totals equal approximately 1% of the corresponding full-depth counts.

## Related tools

- **EMASE** (Produces the full-depth allele-specific counts (weighted allocation of multi-reads via EM) that serve as the input to down-sampling)
- **scBASE** (Consumes the down-sampled counts in the partial-pooling MSE evaluation to test estimation precision under low coverage) — https://github.com/kbchoi-jax/scbase

## Evaluation signals

- Output table contains all 122 cells (early, mid, and late blastocyst stages)
- Per-cell down-sampled read totals equal approximately 1% of the corresponding full-depth counts (average ~147,538 reads/cell)
- Allele-specific (maternal/paternal per gene) count structure is preserved after down-sampling
- MSE evaluation shows partial pooling reduces allelic proportion estimation error most when coverage is low and cell number is large

## Limitations

- The down-sampling seed/randomization procedure is not specified in the article, limiting exact reproducibility of the low-coverage dataset
- Down-sampling is a simulation of low depth; it does not capture library-level artifacts of genuinely low-coverage sequencing
- Down-sampled data inherits the multi-read weighted-allocation assumptions of the EMASE counting step upstream
