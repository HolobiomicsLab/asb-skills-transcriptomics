# Common vs condition-specific gene reporting

## Summary

Aggregates the scorecards of all pairwise experimental comparisons in a main folder into a single per-gene occurrence report, distinguishing genes consistently altered across multiple experiments (e.g., SA_RS13430 appearing on 65 scorecards) from isolated, condition-specific modifications.

## When to use

Use when a directory tree contains one pre-computed scorecard sub-folder per pairwise comparison and you need a global overview of which genes change in many versus few comparisons.

## When NOT to use

- When only a single pairwise comparison exists — the merge is meaningful only across multiple comparison sub-folders in main_folder
- When pre-computed scorecard outputs are absent and raw log2 fold-change/p-adjusted CSVs have not yet been processed by scorecard_functions.scorecard and reconstruct_scorecard
- When the goal is a single-pair four-way plot rather than a global overview; multiple_view applies only to the scorecard, not the four-way plot

## Inputs

- main_folder path (string) hosting one sub-directory per pairwise experimental comparison, each containing pre-computed scorecard outputs (quadrant entries, plots, JSON outcomes)
- Frequency summary previously generated by scorecard_functions.count_frequencies

## Outputs

- CSV or Excel occurrence-count report listing per-gene totals across all comparisons (e.g., gene X active in N of M comparisons)
- Optional separate report of uncommon entries (condition-specific genes)
- Summary of the number of entries/genes identified by the scorecard per comparison

## How to apply

Point the pipeline at main_folder, which hosts one sub-directory per experimental comparison with its scorecard outputs. First run scorecard_functions.count_frequencies(main_folder) to summarize the number of entries/genes identified by the scorecard in each comparison. Then run scorecard_functions.common_entries(main_folder), which re-uses the frequency information previously created, to compute total occurrences per gene across comparisons; it can also emit a separate report of uncommon entries (genes specific to isolated conditions rather than globally altered). Save the occurrence-count report as CSV or Excel listing per-gene totals (gene X active in N of M comparisons); counts should be consistent with the number of sub-folder comparisons in main_folder.

## Related tools

- **scorecard_functions** (Python library providing count_frequencies (per-comparison entry counts) and common_entries (per-gene occurrence totals across comparisons, CSV/Excel output with uncommon-entry report)) — https://github.com/m89p067/Scorecard
- **Pandas** (Holds the CSV fold-change and adjusted p-value data loaded as DataFrame prior to scorecard computation)

## Examples

```
scorecard_functions.count_frequencies(main_folder); scorecard_functions.common_entries(main_folder)
```

## Evaluation signals

- The output report exists in CSV or Excel format
- The report contains per-gene occurrence counts for every scorecard region of interest
- Occurrence counts are consistent with the number of sub-folder comparisons present in main_folder (a gene cannot appear in more scorecards than comparisons exist)
- common_entries was called after count_frequencies, since it re-uses frequency information previously created
- Globally changed genes (high occurrence counts) are distinguishable from condition-specific ones (low counts) in the report

## Limitations

- Requires the folder structure of main_folder with several subfolders, each comparing two experimental conditions
- common_entries must be called after count_frequencies; running it standalone fails because it re-uses previously created frequency information
- The library states no version number for the Python library or Python itself, which may hinder reproducibility
