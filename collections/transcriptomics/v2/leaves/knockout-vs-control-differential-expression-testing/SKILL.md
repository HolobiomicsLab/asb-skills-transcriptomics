# knockout-vs-control-differential-expression-testing

## Summary

Identifies significantly upregulated miRNA/isomiR features in a knockout versus control small RNA-seq contrast by aggregating tiny-count's hierarchically classified per-sample counts and running the tinyRNA workflow's R-based differential expression step, e.g. to find isomiRs upregulated in ZSWIM8-knockout human cell lines.

## When to use

Use when contrasting two small RNA-seq conditions (e.g., wild-type control vs ZSWIM8-knockout human cell lines) and the goal is a filtered differential expression table of miRNA/isomiR features, starting from FASTQ reads plus GFF3 miRNA reference annotations.

## When NOT to use

- Input is already a feature count table produced by another quantifier — the tiny-count hierarchical classification step (5′ nucleotide, length, position, mismatch filters) is the basis of the contrast and would be bypassed.
- The goal is to resolve distinct small RNA classes (e.g., piRNAs vs siRNAs) produced from a single locus rather than to test abundance differences between knockout and control conditions.
- The comparison involves only one condition (no control-vs-knockout contrast), so the R-based differential expression step has no two-condition design to test.

## Inputs

- Demultiplexed small RNA-seq FASTQ(.gz) reads for control and knockout libraries (e.g., Shi et al. 2020 human cell line control vs ZSWIM8-knockout)
- GFF3/GFF2/GTF reference feature annotations with ID/gene_id/Parent tags for miRNA loci
- Reference genome in FASTA with chromosome identifiers matching the annotation file (case sensitive)
- Samples Sheet listing control and knockout samples
- Features Sheet with hierarchical selection-rule preferences for feature counting
- Run Config and Paths File specifying pipeline preferences and input file locations

## Outputs

- Counts matrix of miRNA and isomiR features aggregated across all control and knockout libraries
- Differential expression table filtered for isomiRs significantly upregulated in the knockout (e.g., isomir_differential_expression.csv)
- Pipeline statistics files for counts and preprocessing steps
- Plots generated by the tinyRNA workflow

## How to apply

Obtain demultiplexed FASTQ reads for both conditions plus GFF3/GTF miRNA feature annotations, then run tiny-count with hierarchical selection rules that filter reads by 5′ nucleotide, length, alignment position relative to reference features, and mismatch number so reads are classified as miRNAs or isomiRs with single-nucleotide precision. Aggregate per-sample counts into a counts matrix of miRNA/isomiR features across all control and knockout libraries. Configure the pipeline with the Run Config, Paths File, Features Sheet, and Samples Sheet (obtain templates via `tiny get-templates`), then execute the end-to-end workflow with `tiny run`, which coordinates the R-based differential expression step. Filter the resulting differential expression table for isomiR features significantly upregulated in the knockout and write the results (e.g., isomir_differential_expression.csv). Correctness rests on the feature-counting step: tiny-count can distinguish miRNA from isomiR variants with single-nucleotide precision, so classification errors upstream directly corrupt the contrast.

## Examples

```
conda activate tinyrna && tiny run
```

## Evaluation signals

- The counts matrix contains one column per library and covers all control and ZSWIM8-knockout samples from the Samples Sheet.
- Pipeline statistics files are generated for the counting/preprocessing steps, confirming tiny-count ran with the Features Sheet selection rules.
- The differential expression output reports per-feature statistics for both miRNA and isomiR features between the two conditions.
- The final filtered table contains only isomiR features significantly upregulated in the knockout, written to the expected CSV (isomir_differential_expression.csv).
- Results reproduce known ZSWIM8-knockout isomiR behavior from Shi et al. 2020 and may surface additional upregulated isomiRs not reported in the original analysis.

## Limitations

- Stable-release installation may fail on Apple Silicon–based systems; the development release addresses this, and updating replaces the existing conda environment and any packages installed inside it.
- FASTQ files must be demultiplexed, and reference annotations must satisfy column-9 attribute rules (ID or gene_id or Parent tags; Parent tags with multiple values are not yet supported).
- Reference genome chromosome identifiers are case sensitive and must match the annotation file, or feature counting will fail.
- tiny-count can be run alone or as part of tinyRNA; the differential expression contrast requires the full workflow (or an equivalent R-based step), not just the standalone counter.
