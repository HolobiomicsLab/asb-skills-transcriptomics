# deg-method-consensus-combination

## Summary

Combines per-method DEG calls from DESeq2, limma, and NOISeq (run via the DEgenes Hunter pipeline in ExpHunter Suite) using vote-threshold and combined-FDR consensus strategies plus a Naïve Bayes classifier, because no single method is optimal across datasets. Performance is quantified against known ground truth (spike-in transcripts) using F-measure and logFC correlation.

## When to use

Use when a count table must be analyzed for differential expression and robustness matters, or when evaluating which DEG detection method/combination strategy to trust on RNA-seq data.

## When NOT to use

- When the goal is accurate logFC/fold-change estimation for downstream analyses such as GSEA rather than robust DEG calling — the article notes incorrect fold change estimation could lead to poor qPCR target selection, and combination strategies target DEG calls, not logFC quality
- When blindly extrapolating the spike-in-optimized vote threshold of 2 — the authors state this may differ for other organisms, tissues and experimental designs and they are hesitant to extrapolate a general rule
- When only a single method's final DEG list exists with no per-method results available to combine

## Inputs

- Raw RNA-seq count table (e.g., derived from SRA FASTQ files via clean&map)
- Known ground-truth DEG list (e.g., spike-in transcript identities) for F-measure evaluation
- Per-method DEG results from DESeq2, limma, NOISeq (as produced by DEgenes Hunter)
- R environment configured per seoanezonjic/ExpHunterSuite installation instructions

## Outputs

- Per-method and combination-strategy DEG lists
- F-measure table comparing single methods (DESeq2, limma, NOISeq) and combinations (vote-threshold, combined-FDR, Naïve Bayes) against ground truth
- Per-method logFC correlation table (e.g., limma mean 0.92)
- HTML results report generated by the ExpHunterSuite example scripts

## How to apply

Run the DEgenes Hunter pipeline (ExpHunter Suite, R/Bioconductor) on the raw count table to obtain per-method results from DESeq2, limma, and NOISeq. Then apply combination strategies to the per-method output: a minimum vote threshold cut-off (the optimum was 2 for the spike-in data by F-measure), the combined-FDR strategy, and a Naïve Bayes classifier trained on simulated data. Score each single method and combination against known ground truth (e.g., spike-in transcripts) using F-measure, and assess logFC accuracy via per-method logFC correlation. Benchmark references: DESeq2 0.88, combined-FDR 0.88, vote-threshold-2 0.88, limma 0.76, NOISeq 0.74 F-measure on the spike-in dataset; limma achieved the best logFC correlation (mean 0.92). Write per-method F-measure and logFC correlation tables (e.g., CSV) and compare to these reference values within tolerance.

## Evaluation signals

- F-measure for DESeq2, combined-FDR, and vote-threshold-2 should reach ~0.88 on the spike-in dataset (Table 1 reference values)
- limma should show the best logFC accuracy with mean correlation ~0.92 (Table 2 reference value)
- limma and NOISeq single-method F-measures should be ~0.76 and ~0.74 respectively on the spike-in benchmark
- Vote threshold of 2 should emerge as the optimum cut-off on spike-in data by F-measure
- Running the example scripts end-to-end should produce an HTML results report file

## Limitations

- The optimal vote threshold of 2 may not generalize: 'this may differ for other organisms, tissues and experimental designs', and the authors are hesitant to extrapolate these findings to a more general rule
- A competing recommendation of much higher thresholds exists, but that comparison was based on the analysis of a single human dataset
- Only a Naïve Bayes classifier is provided; more elaborate classifiers are left for future work
- The spike-in replication workflow requires external dependencies outside the R package, including a NCBI SRA download script with JSON credentials, a clean&map program to convert FASTQ to count tables, and Autoflow for the synthetic-experiment scripts
