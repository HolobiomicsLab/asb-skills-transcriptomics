# cross-pipeline-cell-annotation-comparison

## Summary

Reproduces and compares single-cell lineage barcode cell annotations generated by two pipelines (BARtab and Rewind/FateMap) on the same FM0-2 amplicon FASTQ data, quantifying annotation overlap and clone-size concordance as a validation of pipeline equivalence.

## When to use

Use when the goal is to validate a barcode annotation pipeline by re-running an alternative published pipeline on the same single-cell amplicon FASTQs and comparing per-cell barcode calls and clone sizes.

## When NOT to use

- Input is already a cell barcode annotation/counts table rather than raw amplicon FASTQ — barcode extraction and alignment are not needed
- Data are population-level (bulk) barcoding libraries rather than single-cell data with cell barcodes and UMIs
- The barcode design lacks a constant flanking region and known reference library, breaking the cutadapt constant-trimming and bowtie-based reference alignment strategy

## Inputs

- Paired-end single-cell amplicon FASTQ files (FM0-2 dataset, FateMap FM0-237)
- GEO-derived cell barcode whitelists per sample (<sample_id>_whitelist.tsv, '-1' suffixes removed)
- SPLINTR_mCHERRY_V2_barcode_reference_library.fasta barcode reference
- FateMap pipeline code (Rewind/FateMap, UMI threshold 15)

## Outputs

- Cell barcode annotation tables per pipeline (cell barcode -> lineage barcode assignment)
- Overlap contingency of cell annotations (BARtab-only, FateMap-only, both)
- Per-clone size comparisons and Pearson clone-size correlation coefficients between pipelines

## How to apply

Run 'nextflow run DaneVass/bartab --mode single-cell --input_type fastq' on the FM0-2 paired-end amplicon FASTQs, supplying GEO-derived cell barcode whitelists via --whitelist_indir as <sample_id>_whitelist.tsv files with '-1' suffixes removed. QC with FastQC and quality-filter with fastp (minqual 20, pctqual 80); extract cell barcodes and UMIs from R1 with umi-tools using the pattern CCCCCCCCCCCCCCCCNNNNNNNNNNNN, then trim constant regions with cutadapt (--constants all for reference-based randomly fragmented reads). Build a bowtie1 index of the SPLINTR barcode reference library and align with bowtie -a --best --strata -m1 --norc (alnmismatches 2), retaining only alignments that start at the first or end at the last reference position (FILTER_ALIGNMENTS). Remove PCR chimerism by keeping only the most-supported cell barcode-UMI-lineage barcode combination, error-correct and count UMIs with umi-tools count_tab (umi_dist 1, umi_count_filter 5), then aggregate per cell with PARSE_BARCODES_SC (umi_fraction_filter 0.3). Re-run the FateMap pipeline on the same data with its UMI threshold of 15 and compare per-cell barcode annotations and clone sizes in R.

## Evaluation signals

- Cell annotation overlap should reproduce 99.6% (12 BARtab-only, 145 FateMap-only, 39,884 annotated by both tools) across the four conditions
- Pearson clone-size correlation between pipelines should fall between 0.965 and 0.998
- ALIGNMENTS must pass FILTER_ALIGNMENTS: only alignments starting at the first or ending at the last reference position are retained
- Per-cell aggregation applies umi_fraction_filter 0.3 and the BARtab arm uses umi_count_filter 5, while FateMap uses its UMI threshold of 15
- Whitelist files must be formatted as <sample_id>_whitelist.tsv with '-1' suffixes removed from cell barcodes

## Limitations

- No accepted gold-standard dataset with known barcode abundance exists, so benchmarking relies on reproducing published results rather than ground truth
- Benchmarking against similar tools was hampered by differing parameter flexibility between tools
- BARtab and bartools currently do not officially support evolving barcode methods
