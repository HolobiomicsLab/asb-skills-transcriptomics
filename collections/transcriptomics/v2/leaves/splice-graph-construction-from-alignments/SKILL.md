# splice-graph-construction-from-alignments

## Summary

Construct a labeled splice graph from RNA-seq alignments, in which each node is an exon and each edge is a splice junction, with junction edges labeled according to which aligners captured them (label 2 = captured by all aligners, label 1 = otherwise, with 2 refined into 2+ / 2- based on identical read support). This is the graph model Tiglon uses before its label-based dynamic path extension recovers transcripts.

## When to use

Use when integrating BAM alignments from multiple splice-aware aligners (e.g., Hisat2 --dta and STAR) over a gene locus and you need an exon/junction graph whose edges carry aligner-capture labels and averaged read-support weights.

## When NOT to use

- Input is a single aligner's BAM and the goal is plain transcript assembly without multi-aligner integration — a single-aligner assembler workflow (e.g., StringTie2 or Scallop) is the wrong model here
- Input is long-read RNA-seq data (PacBio or ONT) — the current Tiglon version is not compatible with long-read datasets
- You need annotation-guided assembly from known transcript annotations — the current Tiglon version has no option for annotation-guided assemblies

## Inputs

- Per-aligner coordinate-sorted BAM files of spliced RNA-seq alignments (e.g., Hisat2 --dta and STAR BAMs over the same sample, such as SRR307911 aligned to GRCh38)
- A file listing the alignment files generated by different aligners (Tiglon input format)
- Optional reference gene-locus coordinates for restricting graph construction (e.g., the XR_929,880.3 RefSeq locus)

## Outputs

- A labeled splice graph per gene locus with exon nodes, junction edges weighted by averaged read support, and a 'label' field on each edge (1, 2, or refined 2+ / 2-)
- Serialized graph file, e.g., GraphML format (xr_locus_labeled_graph.graphml)

## How to apply

First map the RNA-seq reads (e.g., SRR307911 against GRCh38) with each aligner — Hisat2 in --dta mode and STAR — producing one coordinate-sorted BAM per aligner. For each gene locus, build a per-aligner splice graph whose nodes are exons and edges are splice junctions weighted by read support, then filter spurious junction edges using Tiglon's thresholds: min_average_frac 0.03, min_unbalance_frac 0.03, min_gap_length 200, min_trans_length 500, with min_trans_cov at its default (>0). Merge the per-aligner graphs into one labeled splice graph: label each junction edge 2 when captured by all employed aligners and 1 otherwise, refining label 2 into 2+ when the captured reads are identical across aligners and 2- otherwise, and average the edge weights across aligners. The rationale is that no single aligner covers all junctions of a transcript (e.g., at the XR_929,880.3 locus, its first junction is missed by STAR and its fifth junction is missed by Hisat2), so the labels record exactly which aligner evidence supports each edge for the downstream label-based dynamic path extension. Finally serialize the merged graph (e.g., as GraphML) with a 'label' field on every edge.

## Examples

```
stringtie --mix hisat2_alns.bam star_alns.bam -o assembled.gtf ; tiglon --min_average_frac 0.03 --min_unbalance_frac 0.03 --min_gap_length 200 --min_trans_length 500 aligner_list.txt -o tiglon_transcripts.gtf
```

## Evaluation signals

- The serialized graph (e.g., xr_locus_labeled_graph.graphml) exists and every edge carries a 'label' field
- Junction edge labels match the expected pattern: junctions captured by all aligners are labeled 2 and all others labeled 1 (e.g., at the XR_929,880.3 locus, first and fifth junctions labeled 1, remaining junctions labeled 2)
- Spurious junction edges are removed: filtered edges satisfy Tiglon thresholds min_average_frac 0.03, min_unbalance_frac 0.03, min_gap_length 200, min_trans_length 500
- Edge weights on merged edges equal the average of the per-aligner read-support weights
- Label 2 edges are correctly subdivided into 2+ (identical captured reads across aligners) and 2- (otherwise)

## Limitations

- The current Tiglon version can only accept BAM files generated by Hisat(2) and STAR, so other aligners' outputs cannot feed the graph directly
- The current version has no option for annotation-guided assemblies using known transcript annotations
- The current version is not compatible with long-read RNA-seq datasets (e.g., Pacific Biosciences or Oxford Nanopore Technologies)
