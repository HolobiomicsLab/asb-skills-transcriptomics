# simulation-based-method-comparison

## Summary

Benchmark differential compositional analysis methods (scCODA vs. ANCOM-BC, ANCOM, ALDEx2, ALR t-test, Beta-Binomial, t-test, scDC, Dirichlet-multinomial) on synthetic case-control single-cell count data with known ground-truth effects, scoring each method by Matthews correlation coefficient, ROC AUC, and average precision. It exists because without simulated truth, false-discovery control and detection power of compositional tests cannot be fairly quantified.

## When to use

Use when you need to rank or validate differential abundance testing methods against ground truth on synthetic compositional count data, e.g. at low replicate numbers where FDR control is critical.

## When NOT to use

- Ground-truth differential effects are unknown (real patient data), so MCC and average precision against simulated truth cannot be computed
- The goal is interpreting credible cell-type shifts in a single biological dataset (use credible_effects and summary() directly rather than benchmarking)
- The benchmark goal is not differential compositional testing, e.g. gene-level or clustering benchmarks

## Inputs

- Synthetic case-control cell-type count matrices generated by sccoda.util.data_generation (generate_case_control with b_w_from_abs_change, counts_from_first, sparse_effect_matrix)
- Parameter grid specification: K in {5,10,15} cell types, n0=n1 in {1..5} samples per condition, r=20 replicates
- Fitted scCODA CAResult objects and predictions from sccoda.model.other_models wrappers (ANCOMBCModel, AncomModel, ALDEx2Model, ALRModel_ttest, BetaBinomialModel, TTest, scdney_model, CLRModel/DirichRegModel)

## Outputs

- Aggregated performance table of MCC, ROC AUC, and average precision per method and condition across r=20 replicates (scCODA: AUC 0.99, average precision 0.94)
- ROC/precision-recall curves and FDR-controlling behavior comparisons per replicate count

## How to apply

Generate synthetic case-control compositional count datasets with sccoda.util.data_generation (generate_case_control, b_w_from_abs_change, counts_from_first, sparse_effect_matrix) over the parameter grid K in {5,10,15} cell types, n0=n1 in {1..5} samples per condition, and r=20 replicates. Fit scCODA on each dataset via ana.CompositionalAnalysis with a patsy formula and a fixed reference cell type, running HMC inference via sample_hmc() on TensorFlow/tensorflow-probability, then fit competing wrappers from sccoda.model.other_models (ANCOMBCModel, AncomModel, ALDEx2Model, ALRModel_ttest, BetaBinomialModel, TTest, scdney_model, CLRModel/DirichRegModel) on the identical datasets. Threshold each method's cell-type calls at nominal FDR 0.05 (for scCODA use credible_effects / set_fdr on the CAResult object). Compute MCC, ROC AUC, and average precision per method and condition, aggregating across the 20 replicates; the validation expectation is that scCODA controls false discoveries while maintaining detection power, especially at low replicate numbers.

## Evaluation signals

- The aggregated metrics table must reproduce scCODA's ROC AUC of 0.99 and average precision of 0.94 on the synthetic benchmark
- All competitor model entries (ANCOMBCModel, AncomModel, ALDEx2Model, ALRModel_ttest, BetaBinomialModel, TTest, scdney_model, CLRModel/DirichRegModel) must be present in the output table
- Each method's calls are thresholded at nominal FDR 0.05; scCODA must control false discoveries while ANCOM/ANCOM-BC-style methods show inadequate FDR control at low replicate numbers (n0=n1 in {1..5})
- Metrics are aggregated across all r=20 replicates for every cell of the K/{5,10,15} parameter grid
- Reproducible runs use scCODA>=0.1.2 with tensorflow (>=2.4) and tensorflow-probability (>=0.12), matching the reproducibility repository

## Limitations

- Running the benchmarks is very resource intensive; precomputed generated data and results are provided via Zenodo (doi:10.5281/zenodo.6473255) as .csv/.h5 files for version compatibility
- scCODA requires pre-specified cell-type definitions and assumes a log-linear covariate-abundance relationship, so benchmark conclusions may not hold where these assumptions are mis-specified
- The TensorFlow-based scCODA implementation is no longer maintained; a new Jax version is available in pertpy
