# r-bioconductor-workflow-execution

## Summary

Executes multi-step R/Bioconductor genomics workflows end-to-end by following a paper's demo R scripts (e.g., CaSpER's tcga_BRCA.R), chaining object-construction functions, HMM-based CNV calls, harmonization, and metric computation into reproducible outputs such as TPR/FPR CSV files.

## When to use

Use when a task requires reproducing or adapting an R-based genomics pipeline published as a demo script (e.g., CaSpER TCGA-BRCA CNV calling), producing quantitative metrics like TPR/FPR against a gold standard.

## When NOT to use

- The data are single-cell BAMs needing preprocessing (merging, BAF extraction) rather than executing an already-scripted R workflow on normalized matrices.
- The analysis target is DNA-seq or array-based CNV calling, which CaSpER's RNA-seq framework does not cover.
- Only exploratory visualization of CNV events (heatmaps, BAF plots) is needed without running the full calling pipeline.

## Inputs

- Normalized bulk RNA-seq expression matrix (e.g., 150 randomly selected TCGA-BRCA tumor samples)
- BAF shift files generated by BAFExtract from RNA-seq BAMs
- hg19 gene annotation and cytoband/centromere files
- Gold-standard CNV matrix (e.g., genotyping-array-derived CNV calls) for ROC validation

## Outputs

- Casper object with HMM segment calls across expression and LOH scales
- Large-scale (chromosome-arm) CNV matrix from extractLargeScaleEvents (thr=0.75)
- Gene-level CNV matrix from extractSegmentSummary + gene.matrix
- TPR/FPR metric pairs (e.g., written to tcga_brca_cnv_tpr_fpr.csv)

## How to apply

Locate the paper's companion R demo script in the tool's repository (CaSpER provides meningioma.R, tcga_GBM.R, tcga_BRCA.R, sCellGBM.R, MM135_10X.R under demo/). Prepare the inputs the script expects — for TCGA-BRCA, normalized bulk RNA-seq expression matrices plus BAF shift files from BAFExtract, with hg19 gene annotation built via generateAnnotation and centromere coordinates. Construct the analysis object with CreateCasperObject (sequencing.type='bulk', cnv.scale=3, loh.scale=3, matrix.type='normalized', method='iterative'), then run the pipeline with runCaSpER(object, removeCentromere=T, cytoband=cytoband, method='iterative'). Harmonize multi-scale results using extractLargeScaleEvents(final.objects, thr=0.75) for chromosome-arm events and extractSegmentSummary followed by gene.matrix for gene-level events, then compute validation metrics with calcROC(chrMat, chrMat2) and persist results (e.g., tcga_brca_cnv_tpr_fpr.csv). Runs generally take 5-30 minutes per the README, so budget runtime accordingly and check intermediate objects before writing final outputs.

## Examples

```
final.objects <- runCaSpER(object, removeCentromere=T, cytoband=cytoband, method="iterative"); finalChrMat <- extractLargeScaleEvents(final.objects, thr=0.75)
```

## Evaluation signals

- Reproduced metrics match reported values within tolerance: 60.3% TPR / 3.8% FPR (large-scale amplification), 79% TPR / 7.7% FPR (large-scale deletion), 62.8% TPR / 6% FPR (gene-level deletion), 56.6% TPR / 7% FPR (gene-level amplification).
- extractLargeScaleEvents uses thr=0.75, meaning large-scale calls must agree in at least 7 of 9 pairwise scale comparisons.
- Output CSV contains four TPR/FPR pairs (large-scale amp/del, gene-level del/amp) with FPR well under 10%.
- runCaSpER returns final.objects spanning all expression scales (cnv.scale=3, loh.scale=3) and completes without centromere regions (removeCentromere=T).
- Pipeline completes in the README-stated 5-30 minute range, confirming correct object setup and parameterization.

## Limitations

- Metrics depend on the random 150-sample draw, so reproduced TPR/FPR values carry sampling tolerance rather than exact reproduction.
- 3'-only sequencing (e.g., DropSeq) degrades the BAF shift signal because BAF shift is measured only for variants near 3' gene ends.
- RNA editing, PCR duplication artefacts, and sequencing errors may bias CNV detection through complex effects on the BAF shift signal.
- Cells/samples with substantially large read counts may dominate pooled BAF shift signal and create biases.
