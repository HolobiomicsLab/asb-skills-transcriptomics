# single-cell-proportion-null-simulation

## Summary

A null-simulation benchmarking procedure that quantifies how well Scanpro controls false positives in differential proportion analysis, on both genuinely replicated single-cell data and pseudo-replicated data generated by its iteration-based bootstrapping.

## When to use

Use when benchmarking false-positive control of cell-type proportion analysis: null datasets with unchanged cluster proportions are simulated and accuracy (fraction of unchanged clusters correctly called non-significant) is scored per replicate or pseudo-replicate count.

## When NOT to use

- Clusters supported by less than 2% of all cells are present — the benchmarking found such rare clusters produce unstable results, so null-accuracy estimates for them are unreliable
- The goal is detecting real proportion changes rather than measuring false-positive control — use the proportion-change simulation workflow instead of the null simulation
- Input data is already summarized as a cell-type-by-sample count table outside AnnData — this skill assumes AnnData objects with sample/cluster/condition metadata columns

## Inputs

- Null-simulation AnnData objects generated by scanpro's sim_scanpro (two conditions, five clusters, unchanged proportions, negative-binomial cell counts mu=20000, dispersion=20)
- Column annotations for sample, cluster, and condition in the AnnData metadata

## Outputs

- null_simulation_accuracy.csv with accuracy values per replicate count and pseudo-replicate count
- Per-setting accuracy scores (fraction of truly unchanged clusters correctly called non-significant) aggregated over 100 simulated datasets

## How to apply

Generate 100 null-simulation datasets per replicate count from 2 to 14 with the sim_scanpro function exported by the scanpro package: two conditions and five clusters with unchanged proportions, per-cluster cell counts drawn from a negative-binomial distribution (mu=20000, dispersion=20) yielding ~20,000 cells per condition. Run the scanpro function on each replicated dataset passing sample, cluster, and condition column annotations (e.g. samples_col='sample', clusters_col='cluster', conds_col='conds'). For the unreplicated setting, omit samples_col so Scanpro applies its iteration-based bootstrapping to create pseudo-replicates, and rerun scanpro for increasing pseudo-replicate counts. Score accuracy as the fraction of truly unchanged clusters correctly called non-significant, aggregated over the 100 datasets per setting, and write per-count values to null_simulation_accuracy.csv.

## Examples

```
from scanpro.scanpro import scanpro; out = scanpro(adata, samples_col='sample', clusters_col='cluster', conds_col='conds')
```

## Evaluation signals

- Replicated-setting accuracy falls in the reported 0.98–0.99 range, indicating good false-positive control for datasets with replicates
- Accuracy is computed as the fraction of truly unchanged clusters correctly called non-significant, aggregated over 100 simulated datasets per replicate count
- Simulated datasets contain ~20,000 cells per condition with per-cluster counts from a negative-binomial distribution (mu=20000, dispersion=20)
- Unreplicated (bootstrapped pseudo-replicate) accuracy matches the replicated result from 8 pseudo-replicates upward
- Output CSV contains accuracy values for every replicate count from 2 to 14 and the corresponding pseudo-replicate counts

## Limitations

- Clusters supported by less than 2% of all cells in an experiment produce unstable results
- Bootstrapping has limited benefits when handling rare cell types
- Bootstrapped results should be interpreted with caution and require additional experimental validation
