# genome-guided-transcriptome-assembly

## Summary

Genome-guided transcriptome assembly by integrating BAM alignments from multiple splice-aware aligners (Hisat2 --dta and STAR) using Tiglon's labeled splice graph and label-based dynamic path extension, benchmarked against StringTie2 and Scallop on H. sapiens (GRCh38) and M. musculus (GRCm38) RNA-seq data.

## When to use

Use when assembling transcripts from RNA-seq reads aligned to a reference genome and single-aligner assemblers (StringTie2, Scallop) miss transcripts because no single alignment covers all splice junctions, or when benchmarking assembler accuracy.

## When NOT to use

- Input is long-read RNA-seq data (PacBio or ONT) — Tiglon's current version is not compatible with long-read datasets
- Annotation-guided assembly is required — Tiglon v1.1 has no option to use known transcript annotations to guide assembly
- Alignments come from aligners other than Hisat(2) or STAR — the current Tiglon version only accepts BAM files generated by Hisat(2) and Star

## Inputs

- RNA-seq FASTQ files from SRA/ENA (paired-end, e.g. 100-bp human/mouse reads)
- Reference genome FASTA (GRCh38 for H. sapiens, GRCm38/mm10 for M. musculus)
- Reference transcript annotation GTF (NCBI RefSeq, e.g. hg38.ncbiRefSeq.gtf, mm10.ncbiRefSeq.gtf)
- Coordinate-sorted BAM alignments from Hisat2 (--dta) and STAR
- bamFile_list text file listing BAM paths one per line

## Outputs

- Assembled transcript GTF (e.g. Tiglon.gtf, StringTie2 GTF, Scallop GTF) with transcript structures and expression estimates
- Merged baseline assembly from stringtie --merge
- Cuffcompare evaluation metrics: correct-transcript counts, precision, sensitivity, F-score per assembler per dataset
- Aggregated benchmark tables (e.g. human_benchmark.csv, mouse_benchmark.csv, ablation_improvements.csv)

## How to apply

Align each RNA-seq FASTQ (e.g. SRA accessions SRR307911, SRR387662, SRR10517380, ERR2403203, SRR307903, SRR315323, SRR315334, SRR7536920 for human; DRR205674, DRR205677, ERR3320855, ERR3320871 for mouse) to the reference genome twice: Hisat2 with --dta and STAR, producing sorted BAMs. Merge aligner-specific BAMs with samtools and write a bamFile_list (one BAM per line). Run Tiglon ('Tiglon -B bamFiles_list -s <strand> -o outdir -p 2'), selecting strand mode (-s first/second/unstranded for paired-end) to match library orientation and keeping default filters (min_trans_length 500, min_average_frac 0.03, min_unbalance_frac 0.03, min_gap_length 200). Tiglon builds a labeled splice graph where each edge (junction) is labeled by which aligners captured it (label 2 = captured by all aligners, label 1 otherwise) and applies label-based dynamic path extension to recover transcripts as GTF. Run StringTie2 (plus stringtie --merge) and Scallop on matching single/merged alignments as baselines, and evaluate all GTFs with Cuffcompare against NCBI RefSeq annotations (hg38.ncbiRefSeq.gtf or mm10.ncbiRefSeq.gtf), counting correct transcripts, precision, sensitivity, and F-score per assembler.

## Examples

```
Tiglon -B bamFiles_list -s first -o Tiglon_outdir -p 2
```

## Evaluation signals

- Cuffcompare against RefSeq annotation shows Tiglon recovering ~9.51% more correct transcripts than StringTie2-Merge and 11.25%–13.68% more than StringTie2/Scallop on the eight human datasets
- On mouse M1–M4, Tiglon's average F-score is ~0.2341 with average precision ~51.71%
- Merged Hisat2&Star Tiglon runs improve precision by ~6.47%/6.91% and correct transcripts by ~16.11%/13.98% over Hisat2-only/Star-only runs on human samples
- The motivating transcript XR_929880.3 (sample SRR307911) appears in Tiglon's Cuffcompare output but is absent from StringTie2 and Scallop single-aligner outputs
- Default Tiglon filter parameters are unchanged: min_trans_length 500, min_average_frac 0.03, min_unbalance_frac 0.03, min_gap_length 200

## Limitations

- Tiglon v1.1 only accepts BAM files generated by Hisat(2) and Star
- No annotation-guided assembly option in the current Tiglon version
- Not compatible with long-read RNA-seq datasets (PacBio, Oxford Nanopore)
- Combining the integrating strategy with TransBorrow's borrowing strategy is proposed future work, not implemented
