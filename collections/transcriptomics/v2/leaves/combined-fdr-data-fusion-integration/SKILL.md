# combined-fdr-data-fusion-integration

## Summary

Integrates differential expression (DEG) calls from multiple RNA-seq methods (DESeq2, NOISeq, limma) inside the DEgenes Hunter pipeline using a data-fusion combined-FDR criterion, benchmarked on simulated data with known DE labels against minimum-vote thresholds of 1–4.

## When to use

Use when multiple per-method DEG result sets (per-method statistics/FDR) from ExpHunter Suite must be fused into one robust DEG call set, and performance must be judged against simulated truth labels via precision/recall/F-measure.

## When NOT to use

- When only a single DEG method is used — the fusion and vote-threshold strategies require at least two methods' results to combine
- When the goal is co-expression module detection or functional enrichment rather than combining DEG detection results
- When per-method statistics/FDR are unavailable and only binary DE votes exist — the paper instead recommends a minimum vote threshold cut-off in that setting

## Inputs

- Simulated RNA-seq count tables with known differentially-expressed and non-DE gene labels (from the upstream simulation step)
- Per-method DEG results (DESeq2, NOISeq, limma) including per-method statistics/FDR from the DEgenes Hunter pipeline
- Per-method DEG vote counts for threshold-based comparison

## Outputs

- Combined-FDR DEG call set (single list of genes called DE by data fusion)
- deg_metrics_comparison.csv with precision/recall/F-measure values in [0,1] for each vote threshold and the combined-FDR criterion
- Results report (HTML) generated by the ExpHunterSuiteExamples get_results.sh workflow

## How to apply

Load the simulated RNA-seq count datasets with known DE/non-DE labels from the upstream simulation step, then run the DEgenes Hunter pipeline within ExpHunter Suite in R to obtain individual DEG calls from each integrated method (DESeq2, NOISeq, limma). For the fusion arm, apply the combined-FDR data-fusion criterion that integrates the per-method statistics into a single call set. For comparison, apply minimum-vote threshold cut-offs of 1, 2, 3 and 4 (a gene is DE if at least that many methods voted DE). Compute precision, recall and F-measure for each threshold and the combined-FDR criterion against the simulated truth labels. The article reports that raising the vote threshold increases precision at the cost of recall, and that the combined-FDR criterion behaves similarly to a minimum-vote threshold of 2, the optimum by F-measure on the spike-in data; hence the paper suggests a minimum vote threshold cut-off where per-method statistics for full data-fusion are unavailable.

## Evaluation signals

- All precision/recall/F-measure values in deg_metrics_comparison.csv lie in [0,1]
- Combined-FDR F-measure is comparable to the minimum-vote threshold of 2, the reported optimum by F-measure on spike-in data
- Raising the minimum-vote threshold from 1 toward 4 monotonically increases precision while recall decreases
- Same simulation setup (task_001 truth labels) yields the combined-FDR criterion performing well across all three metrics, matching Fig. 3 style reference summaries
- The ExpHunterSuiteExamples workflow (launch.sh then get_results.sh) completes and produces the expected HTML results report

## Limitations

- The optimal vote threshold (2 on spike-in data) may not generalize: the authors are 'hesitant to extrapolate these findings to a more general rule' since it may differ for other organisms, tissues and experimental designs
- A competing recommendation of much higher thresholds was based on the analysis of a single human dataset, so cross-study consensus on thresholds is not settled
- No previous work had applied machine learning based classification to combining DEG results; the Naïve Bayes classifier here is a first step, with more elaborate classifiers left for future work
