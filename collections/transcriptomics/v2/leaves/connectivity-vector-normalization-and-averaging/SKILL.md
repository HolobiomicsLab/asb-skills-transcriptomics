# connectivity-vector-normalization-and-averaging

## Summary

Computes Totem's per-cell connectivity from the set of Minimum Spanning Trees built by Slingshot over CLARA clusterings: for each MST, per-vertex connectivity is derived from inverse edge weights scaled by vertex degree, each clustering's vector is scaled to a maximum of 1, and the L' vectors are averaged arithmetically.

## When to use

Use when you have a set of Minimum Spanning Trees (one per clustering from Totem/Slingshot) and need per-cell connectivity values in [0,1] to rank clusterings or pinpoint trajectory leaves and branching points.

## When NOT to use

- Input is a single clustering/trajectory with only one MST — no averaging over L' clusterings is possible and Totem's connectivity ranking is not defined.
- The dataset contains disconnected components or cycles, since Totem cannot generate disconnected trajectories or trajectories with cycles.

## Inputs

- Set of L' Minimum Spanning Trees (one per Totem clustering, constructed with Slingshot)
- Edge weight matrix dij for each MST
- Per-vertex degrees kj of each MST

## Outputs

- Per-cell connectivity values bounded in [0,1] (one value per cell)
- Per-clustering scaled connectivity vectors (max = 1) as intermediates

## How to apply

For each MST generated by Slingshot over the CLARA k-medoids clusterings, compute for every ordered vertex pair the connectivity contribution as the inverse edge weight dij divided by the degree kj of the starting vertex, then sum per-vertex contributions to obtain each cell's connectivity within that MST (one vector per clustering). Scale each per-clustering connectivity vector so its maximum value is 1. Average the L' scaled vectors with the arithmetic mean (equation 1) to obtain the final per-cell connectivity. This connectivity is then combined with the Calinski-Harabasz score to rank clustering results, and high-connectivity cells highlight likely trajectory end points (leaves) and branch points.

## Related tools

- **Totem** (Implements the connectivity computation over the per-clustering MSTs and combines it with the Calinski-Harabasz score to rank clustering results.) — https://github.com/elolab/Totem
- **Slingshot** (Constructs the Minimum Spanning Tree for each clustering, which is the direct input to the connectivity computation.)
- **R** (Implementation language of the Totem package used to run the connectivity estimation.)

## Examples

```
library(Totem); sce <- PrepareTotem(SingleCellExperiment(assays=counts), dimRed="LMDS", ndim=5); clusterings <- ClusterTotem(sce); connectivity <- GetConnectivity(sce, clusterings)
```

## Evaluation signals

- Function returns per-cell connectivity values all within [0,1].
- Each intermediate per-clustering connectivity vector has maximum value exactly 1 after scaling.
- Pipeline executes without error on the Totem example data (simulated binary_tree_1 dataset).
- High-connectivity cells fall at expected trajectory leaves on the binary_tree_1 dataset.
- Number of averaged connectivity vectors equals L' (the number of retained clusterings/MSTs).

## Limitations

- Cell connectivity is only meaningful for tree-shaped (connected, acyclic) trajectories; Totem cannot generate disconnected trajectories or trajectories with cycles.
- If upstream clustering fails (e.g. k-medoids instability with high-dimensional PCA input such as 30 principal components producing 1-2 cell clusters), the MSTs fed to the connectivity step are unreliable.
- Extremely imbalanced datasets (rare plus prevalent cell types) can make k-medoids fail, requiring manual cluster merging before connectivity estimation is trustworthy.
