# cohort-size-scaling-analysis

## Summary

A simulation-based benchmarking skill that quantifies how recovery of known gene expression programs (GEPs) improves as more scRNA-seq cohorts are pooled, and compares ICA- vs NMF-based decomposition pipelines. It grounds MetaTiME's design choices (ICA, multi-cohort integration) in quantitative recovery scores.

## When to use

Use when choosing a cohort-pooling size or a matrix-factorization method (ICA vs NMF) for a multi-cohort single-cell decomposition pipeline, and you need evidence on how program recovery scales from 5 to 10 to 20 pooled datasets.

## When NOT to use

- You need to decompose a single dataset rather than assess how multi-cohort pooling improves recovery — the skill's outcome depends on varying cohort size
- Your goal is cell-type annotation on real TME data using pretrained MetaTiME MeCs; this skill validates the decomposition strategy via simulation, not annotation

## Inputs

- 20 synthetic single-cell count matrices generated by scsim, each with 14 embedded GEPs (13 cell-type-specific + 1 signaling)
- Cohort-size settings: pools of 5, 10, and 20 datasets
- List of the 14 known ground-truth GEPs for component matching

## Outputs

- Per-program and per-setting recovery scores for ICA and NMF pipelines
- Comparison table (ICA vs NMF × cohort size 5/10/20) written to simulation_benchmark_results.csv

## How to apply

Run the scsim simulator to generate 20 synthetic single-cell count matrices, each with 14 pre-embedded gene expression programs (13 cell-type-specific programs plus 1 signaling program). For each cohort-size setting (5, 10, and 20 datasets), pool the corresponding synthetic datasets and run the ICA-based meta-component recovery pipeline to decompose expression into independent components, then repeat with the NMF-based pipeline (e.g. scikit-learn implementations) for direct comparison. Match each recovered component back to the 14 known GEPs and compute a recovery score per program and per setting. Aggregate the scores into a comparison table (ICA vs NMF × cohort size 5/10/20) written to simulation_benchmark_results.csv. Rationale: MetaTiME performs large-scale pan-cancer integration with ICA to optimize information independence among components, so the benchmark tests whether ICA preserves independence better than NMF while pooling reduces noise.

## Related tools

- **scsim** (Simulator used to generate 20 synthetic single-cell count matrices with 14 embedded GEPs for the recovery benchmark)
- **MetaTiME** (ICA-based meta-component recovery pipeline applied to pooled synthetic cohorts; the design choice being validated) — github.com/yi-zhang/MetaTiME
- **scikit-learn** (Provides the decomposition implementations used to run the ICA and NMF recovery pipelines on pooled datasets)

## Examples

```
from sklearn.decomposition import FastICA, NMF; X_ica = FastICA(n_components=14).fit_transform(X_pool); X_nmf = NMF(n_components=14).fit_transform(X_pool)
```

## Evaluation signals

- Recovery scores for the true GEPs improve monotonically as pooled cohort size increases from 5 to 10 to 20
- ICA pipeline recovers the true GEPs slightly better than the NMF pipeline at matched cohort sizes
- All 14 embedded GEPs (13 cell-type-specific + 1 signaling) are matched to recovered components in each simulation
- simulation_benchmark_results.csv contains scores for all 6 ICA/NMF × 5/10/20 setting combinations

## Limitations

- Recovery advantage of ICA over NMF is only slight, so the difference may not be robust to simulator settings
- Benchmark uses simulated matrices with pre-embedded transcriptional signatures; real tumor cohorts may not embed equally separable programs
- Recovery is measured against known GEPs, requiring ground truth that is unavailable for real multi-cohort data
