# benjamini-hochberg-fdr-multiple-testing-correction

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Applies Benjamini-Hochberg (BH) false-discovery-rate adjustment to the raw per-event p-values produced by the PAIRADISE paired statistical model, converting them into qval so that ASAS event-SNP pairs can be called significant at the paper's default FDR <= 10% threshold.

## When to use

Use when PAIRADISE's Step 5 statistical model (LRT on delta_i) has produced thousands of raw event-level p-values and you must control the false discovery fraction across tests to call ASAS event-SNP pairs at FDR <= 10%.

## When NOT to use

- The event table already carries a qval column from a prior BH pass — re-adjusting adjusted values would double-correct and shrink the significant set below 116 (GM12878) / 91-143 (Geuvadis populations)
- You need family-wise error rate control (e.g., a single genomewide claim) rather than expected-false-discovery control across thousands of ASAS event-SNP pairs
- P-values come from a method whose assumptions are broken (e.g., the rMATS paired model, where unreliable correlation-parameter estimation can inflate p-values and thus distort the BH ranking)

## Inputs

- Merged PAIRADISE count table from Step 4 (per-event IJC_REF, SJC_REF, IJC_ALT, SJC_ALT counts plus incLen/skpLen effective isoform lengths and sample names)
- Vector of raw (unadjusted) PAIRADISE p-values from the Step 5 likelihood-ratio test (chi-squared, 1 df) run with nloptr/doParallel
- FDR significance threshold (default 0.10)

## Outputs

- pairadise_significant_asas_events.tsv — table of significant ASAS event-SNP pairs (19 documented columns including pval and Benjamini-Hochberg qval), restricted to qval <= 0.10
- Per-event qval for all tested events (BH-adjusted, monotone with rank-ordered p-values)
- Plots of significant ASAS events generated by Step 5

## How to apply

For each ASAS event (ExonID: gene, chromosome/strand, SNP, genomic location), PAIRADISE's paired hierarchical model — binomial likelihoods on length-normalized IJC/SJC counts per allele, with logit(psi) normal distributions sharing the subject effect alpha_ik — yields a raw p-value from a likelihood-ratio test of the null delta_i = 0 against a chi-squared distribution with 1 degree of freedom, computed via nloptr optimization parallelized with doParallel/foreach. Collect the full vector of unadjusted pvals across all tested event-SNP pairs, sort them, and apply the BH step-up procedure (e.g., R's p.adjust(pval, method = 'BH')) to obtain the qval column, preserving the paired ordering so qval is monotone with rank-sorted p-values. Call events significant at the default FDR <= 10% (qval <= 0.10) and emit the table with columns ExonID, IJC_REF, SJC_REF, IJC_ALT, SJC_ALT, incLen, skpLen, pval, qval, IncLevel1/2, AvgIncLevel1/2, IncLevelDifference, AvgTotalCount1/2, SampleName, RefAltAllele, and AF. Run under the paper's conservative default (no sigma_i1 = sigma_i2 restriction); note that relaxing this constraint is a documented user option that materially increases the number of events surviving the same BH threshold.

## Related tools

- **PAIRADISE** (Paired statistical model (binomial + logit-normal with shared subject effect) whose Step 5 likelihood-ratio test produces the raw p-values that the BH procedure converts to qval; writes the significant-event table at FDR <= 10%) — github.com/Xinglab/PAIRADISE
- **rMATS** (Comparison paired model whose p-values are benchmarked against PAIRADISE's BH-corrected calls in simulation; its unreliable correlation-parameter estimation motivates the PAIRADISE LRT)
- **nloptr** (R optimizer used inside the paired model to compute the per-event likelihoods from which the raw pval is derived before BH adjustment)

## Examples

```
R> qval <- p.adjust(pval, method = "BH"); sig <- events[qval <= 0.10, ]
```

## Evaluation signals

- Every row of the output table has qval <= 0.10 and the file contains the documented PAIRADISE columns (ExonID, pval, qval, IncLevelDifference, etc.)
- qval values are monotone non-decreasing with decreasing rank of the sorted raw p-values (a BH invariant)
- GM12878 six-replicate run reproduces 116 significant ASAS event-SNP pairs at FDR <= 10% under the conservative model
- Geuvadis population runs reproduce the reported per-population significant-event counts at FDR <= 10%: CEU 91, FIN 82, GBR 75, TSI 71, YRI 143
- Cross-check in simulation: BH-corrected PAIRADISE calls at 5% FPR yield TPR 61%, the highest among paired t test (26%), paired Wilcoxon (12%), rMATS paired (23%), and Fisher's combined (4%)

## Limitations

- The paper's headline counts are intentionally conservative: sigma_i1 is not restricted to equal sigma_i2; running with sigma_i1 = sigma_i2 increases significant events from 116 to 133 in GM12878 and from 91 to 153 in Geuvadis CEU, so the BH-thresholded count depends on this model option
- Only tagging SNPs outside and near the alternative exon are tested; causal SNPs within the alternative exon or nearby intronic regions are not covered, so the BH-passing event set is incomplete with respect to true regulatory variants
- In the rMATS paired comparison method, unreliable estimation of the correlation parameter can lead to inflated p values, which would propagate misleadingly through any BH correction
