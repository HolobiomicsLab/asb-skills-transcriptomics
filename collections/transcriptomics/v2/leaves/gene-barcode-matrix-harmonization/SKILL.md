# Gene-barcode matrix harmonization

## Summary

Aligns two gene-barcode matrices (GBMs) generated by different scRNA-seq pipelines so their contents are directly comparable: only barcodes found in both matrices are kept, and genes present in only one matrix are added to the other with 0 UMIs assigned. This harmonization is the prerequisite step for computing Pearson correlations, ARI clustering similarity, and integration metrics (kBET, Silhouette) between pipeline outputs.

## When to use

Use when comparing gene-barcode matrices from two scRNA-seq processing pipelines (e.g., UniverSC vs Cell Ranger/dropSeqPipe/CogentAP/zUMIs) before correlation, clustering, or integration analysis.

## When NOT to use

- When each GBM will only be analyzed independently (e.g., standalone QC or per-pipeline clustering reports) — subsetting to shared barcodes discards cells unnecessarily
- When the two matrices use incompatible reference genomes or gene identifier schemes (e.g., one against GRCh38 hg38 and the other against a different annotation) — gene padding with 0 UMIs would create spurious zeros rather than true matches

## Inputs

- Raw gene-barcode matrix (gene x cell UMI counts) from UniverSC output (e.g., Cell Ranger-style matrix files)
- Raw gene-barcode matrix (gene x cell UMI counts) from the platform-specific counterpart pipeline (Cell Ranger, dropSeqPipe, CogentAP, or zUMIs)
- Optionally, additional GBMs for multi-way comparison (e.g., Chromium reference plus SmartSeq2 GBMs processed by UniverSC and zUMIs)

## Outputs

- Adjusted pair of gene-barcode matrices with matching sets of barcodes and genes (shared barcodes only; missing genes padded with 0 UMIs)
- Matrices formatted with identical gene sets for integration workflows (e.g., Seurat integration of SmartSeq2 with a Chromium reference)

## How to apply

Given a pair of raw gene-by-barcode count matrices (one per pipeline), first subset each matrix to only the barcodes found in both matrices, so the two matrices share an identical cell/barcode set. Next, harmonize the gene dimension: any gene found in only one matrix is added to the other matrix with 0 UMIs assigned, producing identical gene sets. For three-way comparisons (e.g., a Chromium reference plus two versions of a SmartSeq2 matrix), format all GBMs to share identical genes. Downstream, compute Pearson correlation between each gene's paired UMI counts per cell (treating each gene-by-cell pair as one data point unless both counts are zero), or feed the adjusted pair into Seurat clustering and ARI computation. In the UniverSC paper this step enabled correlations of r = 1 (Chromium/Cell Ranger 3.0.2) and r >= 0.94 (Drop-seq, ICELL8, SmartSeq3), and ARI values of 1, 0.78, 0.87, and 0.78 respectively.

## Related tools

- **UniverSC** (Generates one of the GBMs being harmonized; universal single-cell processing tool that operates as a wrapper for Cell Ranger 3.0.2) — https://github.com/minoda-lab/universc
- **Seurat** (Consumes the adjusted GBM pair for downstream clustering analysis and integration (version 4.1.1 in the paper))
- **R stats** (Computes Pearson correlation between the harmonized GBM pair (R version 4.1.2))

## Examples

```
common <- intersect(colnames(gbm_universc), colnames(gbm_pipe)); g1 <- gbm_universc[, common]; g2 <- gbm_pipe[, common]; allg <- union(rownames(g1), rownames(g2)); g1 <- g1[allg, , drop=FALSE]; g1[is.na(g1)] <- 0; g2 <- g2[allg, , drop=FALSE]; g2[is.na(g2)] <- 0
```

## Evaluation signals

- After adjustment, the two matrices have identical barcode (column) sets and identical gene (row) sets — dim checks should confirm matching dimensions
- All entries corresponding to genes padded into the other matrix must be exactly 0 UMIs
- Pearson correlation on the harmonized Chromium pair (UniverSC vs Cell Ranger 3.0.2) should reach r = 1, and the Drop-seq, ICELL8, and SmartSeq3 pairs should each reach r >= 0.94 (Fig. 2 left column)
- ARI on Seurat-clustered harmonized pairs should reproduce ~1.0 (Chromium), ~0.78 (Drop-seq), ~0.87 (ICELL8), ~0.78 (SmartSeq3)
- Correlation data points must exclude gene-by-cell pairs where both UMI counts are zero

## Limitations

- Keeping only barcodes found in both GBMs discards cells detected by one pipeline but not the other, so cell counts shrink relative to the raw matrices
- Genes found in only one GBM are added with 0 UMIs, which can only inflate the apparent agreement rather than reflect true quantification differences
- The paper's benchmark used GRCh38 (hg38) chromosome 21 as reference with filtered/downsampled inputs; results may differ on full-genome, unfiltered data
