# loss-weight-ablation-study-design

## Summary

Designs and executes a loss-weight ablation study for BIDCell on the Xenium-BreastCancer1 dataset: each biologically-informed loss weight (lambda) in the xenium .yaml configuration is zeroed one at a time, segmentation is retrained, and performance is quantified to show the synergistic contribution of each loss component.

## When to use

Use when benchmarking how individual biologically-informed loss components of BIDCell contribute to segmentation performance, e.g. reproducing the ablation trends of Supplementary Figs. 4-5 on Xenium breast cancer data.

## When NOT to use

- You want to benchmark BIDCell against external segmentation methods (Cellpose, Baysor, StereoCell) rather than dissect its own loss terms — use the full CellSPA benchmarking comparison instead.
- Your data are not from an SST platform with a xenium/cosmx/merscope/stereoseq example configuration available and you lack the single-cell reference needed for preannotate.
- You only need a single full-model segmentation result (run model.run_pipeline() directly rather than a loss-weight sweep).

## Inputs

- Xenium Output Bundle In Situ Replicate 1 (transcripts.csv.gz and morphology_mip.ome.tif) from 10x Genomics
- xenium_example_config.yaml generated by BIDCellModel.get_example_config("xenium")
- Breast cancer single-cell reference and marker files: sc_breast.csv, sc_breast_markers_pos.csv, sc_breast_markers_neg.csv

## Outputs

- Per-configuration segmented-cell mask .tif ending in _connected.tif (pixel values = cell IDs)
- Per-configuration cell-gene matrix expr_mat.csv
- Combined ablation_metrics.csv with purity F1, captured transcripts, and Chromium correlation for each loss-ablated configuration

## How to apply

Download the Xenium Output Bundle In Situ Replicate 1 breast cancer dataset from 10x Genomics and copy xenium_example_config.yaml via BIDCellModel.get_example_config("xenium"), correcting paths for transcripts.csv.gz and morphology_mip.ome.tif. Run model.preprocess() once (segment_nuclei, generate_expression_maps, generate_patches, make_cell_gene_mat, preannotate) so all ablation runs share identical inputs, using the sc_breast.csv reference and sc_breast_markers_pos.csv / sc_breast_markers_neg.csv marker files. For each ablation configuration, zero one loss weight lambda in the .yaml (and disable shape-specific expansions), then train with model.train() and predict with model.predict(), targeting ~4,000 training steps per run as in the reference configuration. Collect each run's segmented-cell mask ending in _connected.tif and the cell-gene matrix expr_mat.csv, then evaluate with purity F1, captured transcripts, and Chromium correlation following the CellSPA-style metric categories. Assemble all per-configuration metrics into a single tabular file ablation_metrics.csv and check that the relative ordering reproduces the Supplementary Figs. 4-5 degradation patterns when key biologically-informed loss components are removed.

## Related tools

## Examples

```
from bidcell import BIDCellModel; model = BIDCellModel('xenium_example_config.yaml'); model.preprocess(); model.train(); model.predict()
```

## Evaluation signals

- Each ablated run trains for approximately 4,000 steps, matching the reference configuration's step count.
- Preprocessing outputs (patches, expression maps, cell-gene matrix) are generated once and reused identically across all ablation runs.
- Removing individual losses degrades performance: purity F1 increases relative to the amount of captured transcripts compared to the full combined-loss model.
- The relative ordering of configurations in ablation_metrics.csv reproduces the degradation patterns shown in Supplementary Figs. 4-5.
- Each run produces a valid _connected.tif mask with integer cell IDs and a cell-gene matrix expr_mat.csv of matching cell count.

## Limitations

- A GPU with at least 12GB VRAM and 32GB RAM is strongly recommended; higher-resolution segmentation requires larger patch sizes and more GPU memory.
- The pickle.UnpicklingError 'pickle data was truncated' can occur; reduce the cpus parameter to fix it.
- Higher cpus values speed runs but may freeze the system; adjust to the machine.
- Results depend on the quality/appropriateness of the single-cell reference; removing positive markers common to at least a third of cell types was found appropriate, and more positive markers tend to enlarge predicted cells.
