# simulated-rnaseq-labelled-data-preparation

## Summary

Generates synthetic RNA-seq datasets carrying DEG/non-DEG ground-truth labels, calibrated to the characteristics of a real dataset (the Lafora disease dataset), so that a Naïve Bayes classifier can be trained to combine p-value vectors from multiple DEG detection methods within the ExpHunter Suite.

## When to use

Use when a supervised combination of DEG detection methods is needed and no labelled RNA-seq data exist, requiring simulated spike-in/training data with known DEG truth labels.

## When NOT to use

- Real labelled datasets with ground-truth DEG calls are already available, so simulation calibration adds no value
- The target dataset's characteristics differ fundamentally from the reference dataset used for calibration — the paper cautions results 'may differ for other organisms, tissues and experimental designs'
- The goal is unsupervised consensus combination of DEG methods (e.g. minimum vote threshold cut-off), which needs no trained labels

## Inputs

- Real RNA-seq dataset whose characteristics calibrate the simulation (Lafora disease dataset)
- ExpHunterSuite R/Bioconductor environment with auxiliary scripts for simulating RNA-seq data
- Configured launch.sh with environment load and experiment results folder path
- Configured get_results.sh with environment load and results folder path
- Autoflow installation (https://github.com/seoanezonjic/autoflow)

## Outputs

- Labelled simulation results with per-gene vectors of p-values from multiple DEG detection methods and DEG/non-DEG ground-truth labels
- HTML file with the synthetic-experiment results report generated by get_results.sh

## How to apply

Set up the R/Bioconductor environment with ExpHunterSuite installed from GitHub, then use the suite's auxiliary simulation scripts (orchestrated by launch.sh with Autoflow) to generate synthetic experiments whose properties mimic the target real dataset, in this case the Lafora disease dataset. For each simulated gene, run the multiple DEG detection methods and record the per-gene vector of p-values as classifier features, with the simulation ground truth as the DEG/non-DEG response class. Collect these labelled per-method p-value vectors via get_results.sh, which also produces an HTML results report, and save them for downstream Naïve Bayes training. The rationale is that machine-learning based combination of DEG results had not previously been applied, and simulation grounding in the real dataset's characteristics makes the trained classifier transferable to real data.

## Examples

```
Rscript -e 'devtools::install_github("seoanezonjic/ExpHunterSuite", dependencies=TRUE)'; bash launch.sh; bash get_results.sh
```

## Evaluation signals

- Each simulated gene must carry both a p-value from every DEG detection method combined and a correct DEG/non-DEG ground-truth label from the simulation parameters
- Simulated data characteristics must match those of the calibration dataset (the Lafora disease dataset)
- A Naïve Bayes classifier trained on the resulting labelled vectors must reach an F-measure of ~0.88 on the spike-in dataset with known truth labels, comparable to the best single and combination methods in Table 1 and to the vote threshold of 2
- get_results.sh produces an HTML results report after launch.sh completes

## Limitations

- Simulated data are calibrated on a single real dataset (Lafora disease), so behaviour may differ for other organisms, tissues and experimental designs; the authors 'are hesitant to extrapolate these findings to a more general rule'
- Naïve Bayes is a simple model; the article leaves 'more elaborate classifiers' to future work
- The replication scripts depend on Autoflow being installed and on configured environment paths in launch.sh and get_results.sh
