# spark-distributed-gene-filtering

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Executes distributed, MAD-based gene filtering within scSPARKL's Stage-2 on Apache Spark, removing unwanted cells and genes from tall-format scRNA-seq data using per-gene and per-cell quality summaries with a default MAD threshold k > 3.

## When to use

Use when scRNA-seq count data has been melted to tall format in Spark and low-quality cells/genes must be filtered in parallel before normalization and HVG selection.

## When NOT to use

- Input is wide-format matrix data not yet melted to tall format (.csv/.parquet tall input is required)
- Analysis is small enough to fit in memory and a tool like Seurat or Scanpy would suffice without Spark setup overhead
- The goal is Top-n gene selection by Coefficient of Variance Squared rather than MAD-threshold filtering

## Inputs

- Tall-format scRNA-seq count data (.csv or .parquet) loaded as a Spark DataFrame
- Cell and gene quality summaries generated by the scSPARKL preprocessing stage (stored in the analyses folder)

## Outputs

- Filtered gene/cell count table with unwanted cells and genes removed
- hvg_mad_selected_genes.csv containing retained highly variable genes with MAD scores
- Updated quality summary files in the analyses folder

## How to apply

Load the melted count data into a Spark DataFrame and compute per-cell quality summaries (e.g., percent_ercc > 10%, percent_mito > 5%, cells expressing < 10 genes) and per-gene summaries (genes expressed in < 3 cells, dropout rate > 70%) in parallel across Spark partitions; these summaries are saved to an automatically generated analyses folder. Pass the summaries as arguments to data_filter() to drop unwanted cells and genes, with default parameters adjustable directly in the filter package. For the MAD-based HVG variant, score each gene by the Median Absolute Deviation of normalized counts and retain genes passing the default threshold k > 3. The rationale is that filtering on robust MAD statistics in a distributed setting scales to hundreds of thousands of cells where in-memory tools like Seurat and Scanpy exhaust RAM.

## Related tools

- **scSPARKL** (Framework providing the parallel data_filter() routine and MAD-based gene selection executed on Spark) — https://www.github.com/asif7adil/scSPARKL
- **Apache Spark** (Distributed in-memory engine on which the parallel filtering of genes and cells is executed)

## Evaluation signals

- hvg_mad_selected_genes.csv exists, is valid CSV, and contains gene identifier and MAD-score fields
- Every retained gene satisfies the MAD threshold k > 3 criterion
- Genes expressed in < 3 cells, dropout rate > 70% genes, and cells with percent_ercc > 10%, percent_mito > 5%, or < 10 expressed genes are absent from the filtered output
- data_filter() was called with quality summary columns sourced from the auto-generated analyses folder
- Filtering runs across multiple Spark partitions without driver memory errors (memory allocation tuned per README guidance)

## Limitations

- Repository is not actively maintained; a new version is under development
- Default filter parameters must be changed by directly manipulating the filter package; no CLI/API for custom thresholds
- Cluster-mode operations are not yet optimized since each node has separate memory allocation; data melting workaround for RAM limitation needs further optimization
- Only .csv and .parquet inputs are currently supported
