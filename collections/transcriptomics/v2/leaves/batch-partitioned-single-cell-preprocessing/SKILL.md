# batch-partitioned-single-cell-preprocessing

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Memory-aware preprocessing of large scRNA-seq datasets using scaLR's subset-wise normalization (SampleNorm, StandardScaler), backed-mode loading, and group-based train/val/test splitting so that datasets with over 1 million cells can be processed on standard machines without a GPU.

## When to use

Use when preprocessing large scRNA-seq datasets (e.g. PBMCs-SLE >1.25M cells, PBMCs-HED >2M cells) in .h5ad/anndata format where full in-memory loading would exceed available RAM and low-resource execution is required.

## When NOT to use

- Input is already fully preprocessed and small enough to fit in memory — batch partitioning and backed-mode reads add overhead with no benefit.
- Data are not in .h5ad/anndata format or adata.X lacks log1p normalization in the expected 0–10 range, since scaLR's performance varies with input data format and requires user preprocessing for optimal results.
- The goal is downstream DGE analysis rather than classifier-driven preprocessing — the clinical pipeline targets 'disease' and uses DgePseudoBulk/DgeLMEM stages instead.

## Inputs

- scRNA-seq dataset in anndata .h5ad format (adata.X normalized gene counts, adata.obs metadata with target column and cell barcodes as index, adata.var gene names)
- scaLR configuration YAML (data section: full_datapath, sample_chunksize, splitter_config, preprocess list, target)

## Outputs

- Subset-wise normalized and (optionally) standard-scaled expression matrix processed in backed mode
- Training, testing, and validation splits generated by GroupSplitter / StratifiedGroupSplitter
- Configured data stage ready for scaLR's feature_selection and final_training pipeline stages

## How to apply

Load the dataset as an anndata object (.h5ad only) with cells in obs, genes in var, and expression in adata.X as log1p-normalized values in the 0–10 range. Configure the data stage in config.yaml with a sample_chunksize (e.g. 20000) so data are read in backed mode and processed subset-wise rather than loaded whole, and optionally apply SampleNorm (scalr.data.preprocess.sample_norm) followed by StandardScaler (scalr.data.preprocess.standard_scale) per subset. Split the data with GroupSplitter or StratifiedGroupSplitter (e.g. split_ratio [7, 1, 2.5] stratified by donor_id) to produce training, testing, and validation sets. Set the target column (e.g. cell_type or disease) in obs for downstream classification. The rationale is that subset-wise preprocessing and backed-mode disk reads keep memory consumption low, which is what lets scaLR run without specialized GPU resources.

## Related tools

- **scaLR** (End-to-end platform providing the data processing stage: subset-wise normalization (SampleNorm, StandardScaler), backed-mode loading, and train/val/test splitting) — github.com/infocusp/scaLR

```
python pipeline.py --config /path/to/config.yaml -l -m
```

## Evaluation signals

- adata.X values are log1p-normalized and fall within the expected 0–10 range before entering the pipeline.
- Sample chunks (e.g. sample_chunksize: 20000) are read from disk in backed mode — peak memory stays low and does not scale with total cell count.
- Split outputs contain training, testing, and validation sets matching the configured split_ratio (e.g. [7, 1, 2.5]) with stratification by donor_id preserved.
- The chosen target column (cell_type or disease) is present in adata.obs and usable for classification.
- Running with -m (--memoryprofiler) confirms memory consumption remains low, consistent with scaLR's low-resource design goal.

## Limitations

- scaLR's performance may vary based on the input data format, requiring users to ensure proper data preprocessing for optimal results.
- Memory usage is inversely proportional to execution time: reducing memory consumption (e.g. smaller chunks, backed mode) may increase processing time.
- The pipeline currently expects all datasets in anndata .h5ad format only; other formats require prior conversion.
