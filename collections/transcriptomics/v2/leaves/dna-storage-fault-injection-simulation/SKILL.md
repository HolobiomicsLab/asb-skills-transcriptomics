# dna-storage-fault-injection-simulation

## Summary

Run FrameD's fault-injection-based test bed to evaluate DNA storage pipeline designs: encode data into oligos, inject sampled errors (i.i.d. or DNArSim nanopore channel model), reconstruct and decode, and aggregate error statistics across parameter sweeps. FrameD's transparent MPI parallelism makes large sweeps (hundreds of fault-injection iterations, many sequencing reads) tractable.

## When to use

Use when you need to evaluate a DNA-based data storage pipeline design (encoder/decoder choice) under controlled error injection — e.g. varying fault rates, error distributions, or pipeline stages like multiple sequence alignment — and collect decode-failure and error-location statistics.

## When NOT to use

- You only need a single serial encode/decode of a small file with no error injection or parameter sweep — the fault-injection harness and MPI/job-generation machinery add unnecessary overhead
- You plan to run the full paper-scale sweep (e.g. the 6 .json paper configurations, 240 simulations) on commodity hardware — the README states these are only tractable on HPC systems and, as shipped, require an LSF scheduler
- You are simulating a nanopore channel yourself from raw sequencer data rather than evaluating a DNA storage pipeline design under injected errors

## Inputs

- JSON configuration file defining encoder parameters, decoder parameters, fault distribution parameters, copy distribution parameters, and an optional parameter sweep
- Input data file to be encoded into DNA oligos
- Repository example configurations (examples/iid for i.i.d. error model; examples/DNArSim for nanopore channel simulation), each with a C-shell driver script
- HPC or multi-core machine with an MPI implementation (Intel MPI 2017.1 or Open MPI 4.1.5 tested); DNArSim requires Julia (tested through 1.6.2)

## Outputs

- Per-parameter-combination output directory containing parameter record files (experiment parameters, decode failures, byte-error and base-error locations)
- A human-readable 'fi.stats' statistics file per parameter combination aggregating simulation counters
- A Pandas dataframe (e.g. fault_injection_dataframe) generated by db_gen.py for cross-configuration analysis
- Figures/analysis from notebooks/framed.ipynb (framed_iid.pickle and framed_DNArSim.pickle raw data)

## How to apply

Write a JSON configuration specifying encoder parameters, decoder parameters, fault distribution parameters, copy distribution parameters, and any optional parameter sweep, then launch the job generation tools (C-shell scripts under examples/ that expand the sweep and launch all simulations). For each parameter combination, FrameD encodes the input data file into DNA oligos, generates the specified number of copies per oligo, samples errors from the configured fault distribution (i.i.d. model, or the DNArSim nanopore channel simulator in Julia with channel memory k=6), reconstructs the storage pipeline, and decodes the error-carrying oligos. Record decode failures and byte-error and base-error locations in per-parameter record files, and aggregate counters into a statistics file ('fi.stats') written to each parameter-combination output directory. Leverage FrameD's transparent MPI parallelism over the many fault-injection iterations and batch-level parallelism (LSF job submission, or sub-shell background jobs for small non-HPC runs) to keep the sweep tractable. Compile results with tools/data_analysis/db_gen.py into a Pandas dataframe for cross-configuration comparison, e.g. judging whether adding multiple sequence alignment helps at a given error rate and error type.

## Evaluation signals

- A statistics file exists for every parameter combination and contains aggregated counters including decode failures and byte-error and base-error locations
- db_gen.py completes and produces a loadable Pandas dataframe at the top result path, with one row per run configuration
- The notebook framed.ipynb runs to completion on the compiled dataframes and reproduces the paper's figures from the raw data (framed_iid.pickle / framed_DNArSim.pickle)
- For the RS(9,47) configuration (25x read depth, 10% fault rate, 368 simulations), recorded speedups match the published values: 25.3x at 32 MPI ranks and 65.99x at 92 ranks against a serial wall-clock time of ~20325 s
- Choice-of-MSA conclusions track the paper's finding: whether multiple sequence alignment helps depends on error rate and injected error type, so MSA-included runs should not uniformly outperform MSA-excluded runs

## Limitations

- The job-generation infrastructure assumes an IBM LSF-managed platform; other schedulers (Slurm, Cobalt) require extending the TcshJob/LSFJob classes in tools/lsf/submit.py
- The complete paper data-generation configurations (examples/iid, examples/DNArSim, 240 simulations) will only run tractably on HPC systems; commodity hardware is supported only via the small sub-shell examples (run_small.csh, 12 cores)
- Including multiple sequence alignment in the pipeline is not always beneficial — its value depends on the error rate and the type of errors injected, so results do not generalize across configurations
- Docker image (kvolkel/framed:revision) uses openmpi, a slight environment difference from the fault-injection simulation environment
