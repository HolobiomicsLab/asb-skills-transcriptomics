# Cross-language runtime comparison (R vs Python)

## Summary

Benchmarks the execution-speed scalability of dual-language implementations of the same method suite — decoupleR in R (Bioconductor) vs decoupler-py — by timing each method on simulated omics matrices and reporting median ms per sample and regulator per language.

## When to use

Use when the same analysis toolkit exists in both an R/Bioconductor and a Python implementation and you need to quantify how execution time scales with dataset size, expressed per sample and regulator.

## When NOT to use

- You are benchmarking predictive performance (AUROC/AUPRC on perturbation experiments) rather than execution time — that is decoupleRBench's job, not this runtime skill.
- You only need to profile a single implementation's internals; this skill is specifically a cross-language comparison on matched simulated matrices.
- You need to infer biological activities from real omics data — use decoupleR/decoupler directly, not the manuscript's scalability scripts.

## Inputs

- Simulated omics count matrices generated by R/process/get_simmulated_data.R
- Analysis data from Zenodo record https://zenodo.org/record/5645208
- decoupleR R (Bioconductor) and Python (decoupler-py) installations covering the 11 methods

## Outputs

- Per-method timing measurements for both language implementations
- runtime_table.csv: comparison table of median ms per sample and regulator, reproducing Supplementary Fig. S7

## How to apply

Download the analysis data from the Zenodo record referenced by the manuscript (zenodo.org/record/5645208), then generate the simulated omics matrices for the scalability test with 'Rscript R/process/get_simmulated_data.R' from the decoupleR_manuscript repository. Run the benchmark with 'bash run_scale_bench.R', timing each of decoupleR's 11 methods in both the R (Bioconductor) and Python (decoupler-py) implementations on the same simulated matrices. Compute the median runtime per sample and regulator across methods for each language, matching the paper's reporting convention (ms/sample/regulator). Record the hardware (the paper used an Intel Core i7-8550U CPU @ 1.80 GHz) since timings are machine-dependent, and assemble the measurements into a comparison table reproducing Supplementary Fig. S7. The rationale is that runtime differences of orders of magnitude between implementations of the identical statistical methods are reproducible only when input matrices and method set are matched across languages.

## Related tools

- **decoupleR** (R/Bioconductor implementation whose methods are timed in the scalability benchmark) — https://www.bioconductor.org/packages/release/bioc/html/decoupleR.html
- **decoupler-py** (Python implementation timed alongside the R version for the cross-language runtime comparison) — https://github.com/saezlab/decoupler-py
- **decoupleRBench** (companion benchmarking package from the same manuscript; used for performance benchmarking of inference methods, distinct from this runtime scalability analysis) — https://github.com/saezlab/decoupleRBench

## Examples

```
Rscript R/process/get_simmulated_data.R; bash run_scale_bench.R
```

## Evaluation signals

- Median runtime per sample and regulator across the 11 methods should be on the order of the reported values: 1.44 ms in R and 0.44 ms in Python (i.e. Python faster by orders of magnitude).
- The assembled table should reproduce the structure of Supplementary Fig. S7.
- Timing must be reported in ms/sample/regulator with the CPU model documented (paper: Intel(R) Core(TM) i7-8550U CPU @ 1.80 GHz).
- The same simulated matrices and the same set of 11 methods must be run in both language implementations.

## Limitations

- The scalability scripts are slow: the README warns 'Run scalablity analysis (This might take a while)'.
- Absolute runtimes are hardware-dependent (reported on an Intel Core i7-8550U @ 1.80 GHz), so only order-of-magnitude agreement with the published medians should be expected on other machines.
- The R implementation is deprecated — the scverse/decoupler README notes 'a deprecated version in R can be found here' — so R timings reflect the legacy package.
