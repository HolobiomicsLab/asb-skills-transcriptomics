# assembly-accuracy-comparison-across-assemblers

## Summary

Benchmark genome-guided transcriptome assemblers (Tiglon, StringTie2, Scallop) on identical BAM alignments by evaluating each assembler's GTF output with Cuffcompare against RefSeq annotations and counting correct transcripts per dataset, to test whether one assembler consistently outperforms the others.

## When to use

Use when you need to verify that a transcriptome assembler's performance advantage over baselines (e.g., StringTie2, Scallop) holds across multiple real RNA-seq datasets, or when re-testing a trend under a different alignment setting (e.g., Hisat2 without --dta).

## When NOT to use

- The input data are long-read RNA-seq datasets (e.g., Pacific Biosciences PacBio or Oxford Nanopore Technologies ONT) — Tiglon's current version is not compatible with them
- You need annotation-guided assembly guided by known transcript annotations — Tiglon does not currently offer this option
- You only have alignments from aligners other than Hisat(2) or Star — Tiglon's current version only accepts BAM files generated by Hisat(2) and Star

## Inputs

- RNA-seq reads for 8 Homo sapiens (H1–H8) and 4 Mus musculus (M1–M4) real datasets (SRA accessions such as SRR307911, SRR387662, SRR10517380, ERR2403203, SRR307903)
- BAM alignments generated by Hisat2 (default mode, no --dta) and Star for each sample
- bamFile_list text file listing Hisat2-default and Star BAM alignments (one per line) for Tiglon
- RefSeq reference annotations for human (GRCh38) and mouse for Cuffcompare

## Outputs

- Assembled transcript GTF files per assembler per dataset (Tiglon.gtf, StringTie2 GTFs, Scallop GTFs)
- Per-dataset correct-transcript counts from Cuffcompare against RefSeq
- Aggregated consistency table, e.g., hisat2_default_consistency.csv, with assembler vs. correct-transcript counts for the 12 datasets

## How to apply

Align the RNA-seq reads of the eight Homo sapiens (H1–H8) and four Mus musculus (M1–M4) datasets with Hisat2 in the chosen mode (e.g., default mode without --dta) and with Star, producing BAM alignments per sample. Run Tiglon on the merged Hisat2&Star BAMs listed in a bamFile_list using default assembly parameters (min_trans_length 500, min_average_frac 0.03, min_unbalance_frac 0.03, min_gap_length 200), and run StringTie2 and Scallop on the same alignments as single-assembler baselines, yielding one assembled GTF per assembler per dataset. Evaluate every GTF with Cuffcompare against the respective RefSeq annotations for human and mouse, counting correct transcripts per assembler per dataset. Aggregate the counts into a CSV (e.g., hisat2_default_consistency.csv) and validate that the target assembler's correct-transcript count exceeds both baselines in every dataset (difference > 0), confirming the reported trend is retained.

## Examples

```
Tiglon -B bamFile_list -s <strandedness> -o Tiglon_outdir -p 2
```

## Evaluation signals

- In hisat2_default_consistency.csv, for each of the 12 datasets Tiglon's correct-transcript count exceeds both StringTie2's and Scallop's counts (difference > 0)
- Every assembler produced an assembled GTF for all 12 datasets (8 human + 4 mouse) before Cuffcompare evaluation
- Cuffcompare comparisons are made against the correct RefSeq annotation per species (human GRCh38 RefSeq for H1–H8, mouse RefSeq for M1–M4)
- Tiglon was run with default assembly parameters (min_trans_length 500, min_average_frac 0.03, min_unbalance_frac 0.03, min_gap_length 200) and strandedness set per sample
- Expected trend direction: Tiglon consistently superior under Hisat2 default alignments, matching the trend reported under --dta mode and Star alignments

## Limitations

- The current version of Tiglon does not have an option for annotation-guided assemblies
- The current version of Tiglon is not compatible with long-read RNA-seq datasets (e.g., PacBio or Oxford Nanopore Technologies)
- The current version of Tiglon can only accept BAM files generated by Hisat(2) and Star
