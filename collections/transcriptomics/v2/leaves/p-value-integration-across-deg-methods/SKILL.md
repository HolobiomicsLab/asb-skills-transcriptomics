# p-value-integration-across-deg-methods

## Summary

Trains a Naive Bayes classifier in the ExpHunter Suite that integrates per-gene p-value vectors from multiple DEG detection methods (e.g. DESeq2, NOISeq, limma) into robust DEG calls. The model is trained on simulated RNA-seq data with DEG/non-DEG ground-truth labels and validated on a spike-in dataset by F-measure.

## When to use

Use when multiple DEG detection method outputs (per-gene p-value vectors) are available and a machine-learning integration of DEG calls is needed, rather than a simple vote threshold cut-off.

## When NOT to use

- A minimum vote threshold cut-off is sufficient 'where possible' — the article recommends the simple threshold as the default suggestion when it works
- Only a single DEG method's p-values are available, so no multi-method p-value vector can be assembled as classifier features
- No labelled simulation or ground-truth data exist to train the classifier for the organism/tissue in question

## Inputs

- Labelled simulation results from task_001: per-gene vectors of p-values from multiple DEG detection methods with DEG/non-DEG ground-truth labels
- Simulated datasets generated based on the characteristics of the Lafora disease dataset
- Spike-in dataset count tables (FASTQ -> clean&map -> count tables, DEgenes Hunter input)

## Outputs

- Serialized Naive Bayes classifier model (naive_bayes_model.rds)
- Spike-in F-measure (~0.88 expected, comparable to vote threshold 2 and DESeq2)
- HTML results report generated by get_results.sh

## How to apply

Load labelled simulation results (per-gene vectors of p-values from multiple DEG detection methods with DEG/non-DEG ground-truth labels) generated by simulating RNA-seq data based on the characteristics of the Lafora disease dataset. Assemble the per-method p-value vectors as classifier features and the DEG/non-DEG labels as response classes. Train the Naive Bayes classifier within the ExpHunter Suite in R/Bioconductor and serialize the fitted model to naive_bayes_model.rds. Apply the trained classifier to the spike-in dataset with known truth labels and compute its F-measure, which should reach ~0.88 and be comparable to the best single method (DESeq2) and the vote threshold of 2 reported in Table 1. Run the experiments through the repository's launch.sh/get_results.sh Autoflow scripts, which produce an HTML results report.

## Evaluation signals

- Spike-in F-measure of the trained classifier is ~0.88 and comparable to the vote threshold of 2 and DESeq2 (Table 1, Naive Bayes row)
- Classifier performance is as good as the best performing single and combination methods on the spike-in dataset
- Fitted model serializes successfully to naive_bayes_model.rds
- Running launch.sh followed by get_results.sh generates an HTML results report via Autoflow

## Limitations

- The optimum vote threshold observed on the spike-in data (2) 'may differ for other organisms, tissues and experimental designs', and the authors are 'hesitant to extrapolate these findings to a more general rule'
- More elaborate classifiers than Naive Bayes are left for future work ('further work could look at more elaborate classifiers')
- Stable implementations of the proposed methodologies and workflows were still emphasized as a need by the authors
