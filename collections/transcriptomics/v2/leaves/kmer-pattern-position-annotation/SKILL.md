# kmer-pattern-position-annotation

## Summary

Annotates RF-selected position-specific gapped k-mer features with their nucleotide pattern and sequence position relative to a 41-nt RNA window, and tallies how many descriptors come from each gapped mode (B/C/D), following the iRNA5hmC-PS feature-selection experiment.

## When to use

Use when you have mode-wise random-forest-selected position-specific k-mer features from multiple cross-validation partitions and must find the intersection and annotate surviving patterns by position and descriptor mode.

## When NOT to use

- You only need classifier performance (accuracy/MCC) rather than the identity of consistently selected discriminative features — run the cross-validation evaluation skill instead.
- Your input is an arbitrary k-mer frequency (non-position-specific) feature table; the position/mode annotation logic applies to PSG k-mer descriptors from a 41-nt sequence window.
- You have a single feature-selection run rather than multiple cross-validation partitions — intersection-based stability analysis requires multiple selection sets.

## Inputs

- Dataset.csv benchmark RNA 5hmC dataset (41-nt sequences)
- All_Features_Dataset.csv generated by Feature Generation.ipynb
- 25 training partitions from 5-times 5-fold cross-validation

## Outputs

- Intersection of the 25 mode-wise RF-selected feature sets (expected: exactly 34 features)
- selected_features.csv — table of the 34 k-mer patterns with sequence positions and descriptor-mode labels
- Mode tally showing 27 of 34 features from gapped modes B/C/D

## How to apply

First compute the position-specific gapped k-mer feature table by running 'Feature Generation.ipynb' on Dataset.csv to obtain All_Features_Dataset.csv (as per the iRNA5hmC-PS README). For each of the 25 training partitions from the 5-times 5-fold cross-validation experiment, train a mode-wise scikit-learn RandomForestClassifier selector per descriptor mode and retain the top 400 features, yielding 25 sets of 400 features. Intersect the 25 sets with numpy/pandas set operations and confirm exactly 34 features survive in every set. Annotate each surviving feature with its k-mer pattern and position span relative to the 41-nt sequence (e.g., A-A-A at positions 22-26, G-G-G at positions 36-40), then tally mode membership and verify 27 of the 34 originate from the proposed gapped modes B, C, or D. Save the annotated pattern/position table as selected_features.csv.

## Evaluation signals

- Each of the 25 partition-wise selector sets must contain exactly 400 features (top 400 per mode-wise RF selector).
- The intersection across all 25 sets must contain exactly 34 features — no more, no fewer.
- The descriptor-mode tally of the 34 surviving features must show 27 drawn from the gapped modes B, C, and D.
- Each annotated feature must map to a valid position span within the 41-nt sequence window (e.g., A-A-A at positions 22-26, G-G-G at positions 36-40).
- The output table selected_features.csv must contain one row per surviving feature with pattern, position, and mode columns.

## Limitations

- Position-specific features were not effectively combined with frequency-based features in single models; the authors deferred combining both frequency and position-specific features using a feature subspace ensemble approach to future work.
- The intersection-in-stability analysis is specific to the 5-times 5-fold cross-validation design (25 partitions) and the 400-feature-per-selector retention threshold; different designs will yield different surviving feature counts.
- Feature Generation.ipynb requires Dataset.csv, Feature Generation.ipynb, and Model.ipynb in the same Jupyter folder; missing files prevent producing All_Features_Dataset.csv.
