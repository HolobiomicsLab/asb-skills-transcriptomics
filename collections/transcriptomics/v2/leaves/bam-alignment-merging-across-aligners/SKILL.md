# bam-alignment-merging-across-aligners

## Summary

Merge spliced RNA-seq BAM alignments produced by two different aligners (Hisat2 --dta and STAR) with samtools merge so that integrative assemblers like Tiglon can build a labeled splice graph covering junctions that no single aligner captures in full.

## When to use

Use when RNA-seq reads have been aligned independently by Hisat2 and STAR and a downstream integrative assembler (e.g., Tiglon) needs a combined BAM or a bamFile_list of the per-aligner BAMs as input.

## When NOT to use

- The alignments come from aligners other than Hisat(2) or STAR — the current Tiglon version only accepts BAM files generated by Hisat(2) and Star.
- The input is long-read RNA-seq data (PacBio or ONT), which Tiglon is not compatible with.
- A single-aligner assembler (StringTie2, Scallop) is the target consumer — these take one BAM directly and should not receive a merged multi-aligner BAM.

## Inputs

- Coordinate-sorted BAM alignment from Hisat2 run with --dta (e.g., Hisat.bam)
- Coordinate-sorted BAM alignment from STAR (e.g., Star.bam)
- Original RNA-seq FASTQ reads (e.g., SRA accession SRR307911)
- Reference genome index (e.g., human GRCh38) for both aligners

## Outputs

- Merged BAM combining Hisat2 and STAR alignments (via samtools merge)
- bamFile_list text file listing one BAM path per line for Tiglon input
- Tiglon assembly output GTF (e.g., Tiglon_outdir/Tiglon.gtf)

## How to apply

Align the same FASTQ reads to the reference genome twice — once with Hisat2 using the --dta option to produce Hisat.bam, once with STAR to produce Star.bam — yielding two coordinate-sorted spliced alignments. Combine them either by running 'samtools merge' into a single BAM, or by writing a bamFile_list text file listing each BAM one per line, which is the input format Tiglon expects. The rationale is that Hisat2 and STAR each cover all exons of some RefSeq transcripts (e.g., XR_929880.3 in SRR307911) but neither covers all splice junctions, so integration via Tiglon's labeled splice graph (edge labels 1/2 denoting which aligners captured each junction) recovers transcripts that StringTie2 and Scallop on single-aligner BAMs miss. Tiglon's current version only accepts BAMs generated by Hisat(2) and STAR, so merging alignments from other aligners is out of scope.

## Related tools

- **Hisat2** (Splice-aware aligner run with --dta to produce one of the two input BAMs) — https://github.com/DaehwanKimLab/hisat2
- **Star** (Splice-aware aligner producing the second input BAM from the same reads) — https://github.com/alexdobin/STAR
- **Tiglon** (Integrative assembler that consumes the bamFile_list (or merged BAM) and builds a labeled splice graph with label-based dynamic path extension) — https://github.com/yutingsdu/Tiglon
- **bamtools** (BAM manipulation toolkit used as a prerequisite for Tiglon installation) — https://github.com/pezmaster31/bamtools

## Examples

```
samtools merge Hisat.bam Star.bam merged.bam; echo -e "Hisat.bam\nStar.bam" > bamFile_list; Tiglon -B bamFile_list -o Tiglon_outdir
```

## Evaluation signals

- Both source BAMs (Hisat.bam and Star.bam) exist and are coordinate-sorted and valid before merging.
- The bamFile_list contains exactly one BAM path per line, and Tiglon runs to completion producing Tiglon_outdir/Tiglon.gtf.
- Cuffcompare of Tiglon's GTF against the RefSeq annotation shows the substring 'XR_929880' present in Tiglon's comparison output but absent from StringTie2 and Scallop single-aligner comparison outputs.
- Neither single-aligner BAM covers all splice junctions of the target transcript while both cover all its exons, consistent with the paper's motivating observation.
- On the H1–H8 and M1–M4 datasets, Tiglon's correct-transcript count (per Cuffcompare) exceeds both StringTie2's and Scallop's counts on the same alignments.

## Limitations

- Tiglon's current version only accepts BAM files generated by Hisat(2) and Star; other aligners' BAMs cannot be integrated.
- Tiglon has no annotation-guided assembly option, so merged alignments cannot be guided by known transcript annotations.
- Tiglon is not compatible with long-read RNA-seq datasets (PacBio or Oxford Nanopore Technologies).
