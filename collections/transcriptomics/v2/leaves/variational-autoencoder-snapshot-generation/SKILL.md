# variational-autoencoder-snapshot-generation

## Summary

Generates cell embeddings from multimodal single-cell omics data (RNA, ADT, ATAC) by creating snapshots of variational-autoencoder embeddings with SnapCCESS, an unsupervised ensemble deep learning approach for consensus cell clustering.

## When to use

Use when multimodal single-cell omics data (e.g. CITE-seq RNA+ADT or SHARE-seq/SNARE-seq RNA+ATAC) needs embeddings for unsupervised cell clustering or benchmarking against totalVI, MultiVI, MOFA+, or Jvis-learn.

## When NOT to use

- When the tutorial's default parameters would be copied blindly — the tutorial explicitly does not recommend best parameters; dataset-specific parameters must come from the paper
- When the task requires supervised cell-type annotation rather than unsupervised consensus clustering of embeddings
- When a single unimodality is sufficient and multimodal integration is not the goal — the paper's finding is that multimodal embeddings generally outperform any unimodality alone, so unimodal-only use forfeits the main benefit

## Inputs

- Multimodal single-cell omics dataset (e.g. CITE-seq RNA + ADT, SHARE-seq/SNARE-seq RNA + ATAC, TEA-seq GSE158013), each modality arranged as features by cells
- Reference cell-type labels for clustering validation (e.g. tutorial data in tutorials/in/: CITE-seq RNA, ADT, and cell type files)
- Dataset-specific hyperparameters (e.g. epoch=1, initial learning rate 0.02) taken from the published paper, not tutorial defaults

## Outputs

- SnapCCESS ensemble embedding of multimodality generated by variational-autoencoder snapshots
- Consensus cell cluster assignments from k-means, SIMLR, or spectral clustering coupled to the embedding
- Clustering performance scores (ARI and NMI) against reference cell-type labels (e.g. ari_comparison_s2a.csv, ari_nmi_modality_comparison.csv, figure5_ari_nmi_benchmark.csv)

## How to apply

Install the snapccess Python package via pip ('pip install snapccess --index-url https://pypi.org/simple') and load the tutorial notebook 'an_example_of_generate_embedding_using_SnapCCESS_python_version.ipynb' as the reference workflow. Arrange each modality (RNA, ADT, ATAC) as features-by-cells; the Python API expects the combined PyTorch data loader used by the training routine. Train SnapCCESS's variational-autoencoder backbone to create snapshots of multimodality embeddings (paper parameters apply, e.g. epoch=1 — the tutorial does not recommend best parameters, so take dataset-specific parameters from the paper, doi:10.1093/bioinformatics/btad382). Couple the resulting ensemble embedding with clustering algorithms such as k-means, SIMLR, or spectral clustering to generate consensus clustering of cells, then score against reference cell-type labels with ARI and NMI. Note that performance is sensitive to the initial learning rate: on the Swanson TEA-seq data, the default 0.02 gave high clustering performance while 0.2 significantly reduced it.

## Evaluation signals

- Multimodal SnapCCESS embedding attains higher ARI/NMI than every single-modality (RNA-only, ADT-only, ATAC-only) embedding, consistent with Figure 4a / Supplementary Fig. S4
- Learning-rate sensitivity trend reproduces Supplementary Fig. S2a on TEA-seq: initial learning rate 0.02 gives high ARI while 0.2 significantly reduces it
- Benchmark ARI/NMI across method-by-algorithm combinations (k-means, SIMLR, spectral clustering × totalVI, MultiVI, MOFA+, Jvis-learn, SnapCCESS) matches Figure 5, including the characteristically poor SIMLR-on-Jvis-learn result
- SnapCCESS clustering is competitive with or significantly better than totalVI on CITE-seq and MultiVI on SHARE-seq/SNARE-seq datasets

## Limitations

- The tutorial only explains how to use the package; it does not recommend best parameters — parameters for publication datasets are listed in the paper itself
- Clustering performance is sensitive to the initial learning rate (0.02 vs 0.2 on TEA-seq); suboptimal hyperparameters significantly reduce performance
- The Python API expects the combined PyTorch data loader used by the training routine, so modalities must be preprocessed into that format; the R wrapper expects features-by-cells matrices before preprocessing
- GPU acceleration is optional and depends on the local PyTorch/CUDA or PyTorch/ROCm installation
