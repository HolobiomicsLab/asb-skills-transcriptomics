# binary-classifier-power-accuracy-evaluation

## Summary

Evaluates a trained binary classifier (here, the CLOUDe neural network distinguishing 'redundant' vs 'unique' gene deletion targets) by computing power (redundant recall) and overall accuracy on a balanced test set, including under highly unbalanced training data.

## When to use

Use when a binary classifier trained on simulated OU-process expression data (or any two-class problem) must be scored for power and accuracy on a balanced test set, especially after training on skewed/unbalanced training data.

## When NOT to use

- The goal is to predict continuous evolutionary parameters (theta1, theta2, log10(sigmaSq/(2*alpha))) rather than binary class labels — use the Predictor functions instead
- Training data is already balanced and the question is only about standard classification rather than robustness to class imbalance/skew
- Input expression data is not in the required 3m-column deletion-event format (derived/survived/lost gene columns)

## Inputs

- Balanced test set of expression features (space-delimited file with N+1 rows and 3m columns: derived, survived, and lost gene expression per condition, e.g., EmpiricalData.data format with m=6)
- Highly unbalanced 'redundant-skewed' or 'unique-skewed' training set generated by GenerateTrainingData from an OU process
- Empirical reference expression file (e.g., ExampleFiles/EmpiricalData.data)

## Outputs

- Predicted classes per deletion event (test_prefix.nn.num_layers.classifications)
- Predicted class probabilities per deletion event (test_prefix.nn.num_layers.probabilities)
- Power (redundant recall) and overall accuracy metrics on the balanced test set, compared against the reported 96.65% power and 96.35% accuracy
- Fitted classifier model in TensorFlow HDF5 format (training_prefix.nn.num_layers.classifier.hdf5)

## How to apply

Generate 'redundant-skewed' or 'unique-skewed' (highly unbalanced) training sets with GenerateTrainingData, which simulates expression evolution under an Ornstein-Uhlenbeck process using the empirical file (e.g., EmpiricalData.data, N=100 deletion events at m=6 tissues) as reference. Tune hyperparameters with ClassifierCVnn using num_layers in {0,...,5}, five-fold cross-validation, log10(lambda) at 7 evenly spaced points in [-3, 3], gamma at 3 evenly spaced points in [0, 1], batch size 50, and 50 epochs; the optimal number of hidden layers is the one with the smallest validation loss. Fit the classifier conditional on the optimal lambda, gamma, and num_layers, saving the model in TensorFlow HDF5 format, then apply CLOUDeClassifyNN to the balanced test set to output predicted classes and class probabilities per deletion event. Compute power (redundant recall) and overall accuracy on the balanced test set and compare against the reported benchmarks of 96.65% power and 96.35% accuracy; the NN architecture is expected to outperform the xgboost, random forest, and SVM alternatives.

## Examples

```
source("CLOUDe.R"); ClassifierCVnn(num_layers, batchsize=50, num_epochs=50, log_lambda_min=-3, log_lambda_max=3, num_lambda=7, gamma_min=0, gamma_max=1, num_gamma=3, training_prefix); CLOUDeClassifyNN(training_prefix, testing_prefix, num_layers)
```

## Evaluation signals

- Retrained unbalanced-data NN classifier achieves power and accuracy within a few percentage points of the reported 96.65% power and 96.35% accuracy on the balanced test set
- Output files test_prefix.nn.num_layers.classifications and test_prefix.nn.num_layers.probabilities exist and contain one class label and one probability pair per deletion event
- Classifier and cross-validation output files training_prefix.nn.num_layers.classifier_cv and training_prefix.nn.num_layers.classifier.hdf5 are produced by ClassifierCVnn
- Hyperparameters fall within the specified grids: num_layers in {0,...,5}, log10(lambda) in [-3, 3], gamma in [0, 1], batch size 50, 50 epochs
- NN power/accuracy exceeds the xgboost, random forest, and SVM alternatives as reported in the paper

## Limitations

- Estimating neural-network hyperparameters via cross-validation is time-consuming, so hyperparameter tuning is done separately from final model training
- Support vector machine and random forest training occur on-the-fly at test time and do not require the separate training step; this evaluation workflow is specific to the neural network (and xgboost)
- Performance under highly unbalanced training data is reported for the NN architecture; other architectures were outperformed and may degrade more under skew
- Only two classes ('Redundant' or 'Unique') are supported; this is not a multiclass evaluation workflow
